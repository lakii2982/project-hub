# PH-249 · PH-232 覆盖公式口径同步（PH-240 实现对齐）

基线 main=26d0408（PH-248 规划槽、PH-250 手续费批准已合入）。纯文档口径同步，不改代码/迁移/测试。

## 改动（仅 project/specs/PH-232.md）

- **余额口径**：现金未核销余额/可用 = `posted gross_cents − Σ(active cleared_cents) − Σ(active 退款 gross) − Σ(active 银行退回 gross)`；OpenItem 剩余不变（`gross − Σ(active cleared)`）；**Offset 扩展位 0，明确不宣称已实现**。
- **真实接口**（按合并代码实读）：
  - `pmo_plugins/cash/refund_services.refund_coverage_for_cash(...)` → `cash_transaction_ref / refunded_cents / returned_cents / total_cents(=refunded+returned) / offset_cents=0 / offset_implemented=false`；
  - settlement `clearance_coverage_for_cash(...)` → `cash_transaction_ref / posted_gross_cents / cleared_cents / offset_cents=0 / total_cents(=cleared) / offset_implemented=false`（**无 refunded 字段**）；
  - `create_clearance` 上限 = `gross_cents − _cash_cleared − refund_coverage_for_cash(...)['total_cents']`。
- **待同步项（PH-241 契约，ready 未实现）**：核销候选 `posted_cash_candidates` 与 `create_clearance` 须经 PH-239 分类只读**排除 advance 现金**、同一现金不得同时有 active clearance 与 active offset；PH-232 已交付实现尚未包含，spec 不宣称已实现，待 PH-241 落地同步代码与本文。
- 金样例/反例补退款退回扣减示例（53000−退款10000→可用43000）；反例补“已退款/已退回金额再核销”和“advance 现金被核销（PH-241 待同步后启用）”；verify_integrity 补退款退回后可用额非负，PH-241 互斥断言标注为落地后启用。
