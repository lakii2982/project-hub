# PH222 服务期客户确认与归属月份管理收入

日期：2026-10-30。基线：PH-221 PR116 规划合入 2e91362（PH-222 在其可信 BASE 上 ready 后实现）。不重做 219/220/221。

## 本轮结论

完成 1.0 固定服务期收入首片：客户走完批准 `fixed_service_period` 合同 → 登记真实客户依据 → 独立确认已完成服务 → 按服务月确认管理收入 → 原额反收入 → 反服务确认/替代纠错 → 追溯。收入仍由 management_revenue 唯一拥有，不生成成本、现金、应收或开票。

冻结边界（与 project/specs/PH-222.md、docs/adr/0008 一致）：

- `no_partial` 只支持单自然月完整原段；跨月 no_partial 草稿可存，submit/approve/recognize 一律拒绝并提示需后续正式合同变更独立批准月度分配；不按天或等月猜分价，不伪造新合同。
- 已批准 `calendar_days` 允许原段内连续子区间；跨月仍是一个真实父确认，批准时在公司锁内先冻结各自然月交集为私有 `ServiceConfirmationMonth`（真实 PK/父 FK/月份/首尾/净额），再把父置 confirmed；父与月行受 DB 触发器保护。
- 每月金额按原整个 schedule 累计 HALF_UP 差额：`HALF_UP(M*((R-S).days+1)/D) - HALF_UP(M*(L-S).days/D)`；101 分三天 34/33/34；2026-01-31..02-02 得 1 月 34、2 月 67；合计守恒、零额月占用、不在月初重置。
- 收入 occurred_on=月覆盖末日、posting_period=服务月；客户确认日 `confirmed_on` 单列，可晚于服务月（次月确认仍入原月，原月已锁则拒绝）。
- RevenueRecognition 与 Acceptance 做 DB XOR；服务来源新增真实父/月子 FK，月行一生一笔 Recognition，反冲不释放；DB 触发器校验月行父/org/project/金额/覆盖日/期间一致，且来源三列不可变。
- 正式确认同 atomic 发一次已登记 canonical `delivery.service_confirmation_changed.v1`（不新建 topic）；草稿/依据/提交/撤回/反确认走 generic audit；已登记的 `delivery.service_confirmation.draft.save/v1` 与 PH-149 `core.document.decide` handler 属命令/PAT 接线，本片不实现也不伪造。
- 反父确认前必须逐月显式反全部已入收入（含零额），反收入复制原日期/期间并执行原月双锁；关期预检按真实覆盖（非客户确认日）识别待审确认、已确认未收入月、已反未反确认。
- 原 PH-148/149/150/154/166/167 状态与依赖不变；本片不冒称完成原任务或完整 1.0。
