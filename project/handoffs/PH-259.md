# PH-259 · 发票插件归属与契约决策（ADR 0010）

基线 main=e8183ff（PH-241 合入）。纯决策/ADR 片，无产品代码/迁移/scaffold。

## 决定

**方案 A：新建 `pmo_plugins.invoicing` 插件 app**，作为发票域写 owner；契约 schema 不变，contracts/settlement（必要时 delivery）仅以具名只读接口被消费。见 `docs/adr/0010-invoicing-plugin-ownership.md`。

判据（ADR 内逐项比较）：域所有权/owner-read-model 边界、迁移隔离与回滚、manifest 8 字段/requires 适配、路由与 canonical 命令暴露、SDK/插件演进兼容（不假设未交付的 WO-14 能力）、测试/部署/回滚成本、core 膨胀。

放弃：B1 并入 management_revenue（混收入/发票双域）、B2 并入 settlement（发票非未清事实）、B3 并入 contracts/delivery（扩大冻结契约写 owner）、C 暂缓（阻塞 WP-INVOICE/收入配对；PH-150/PH-155 本就是 PH-252 依赖）。

## 实现约束（由 PH-252 实现 PR 落地，本 ADR 不建 scaffold）

- manifest 恰好 8 字段：id=invoicing、name、version=0.1.0、kernel_api >=1.0,<2、requires={contracts>=0.1.0, settlement>=0.1.0}（若分配消费履约来源再加 delivery）、default_enabled=True、capabilities=[]、description。
- 注册：`pmo/settings.py`（INSTALLED_APPS + PMO_PLUGIN_MODULES）与 `pmo_plugins/delivery/urls.py`，均 root 单写。
- 迁移：invoicing 自有链，首号 `0001_initial`；不改已应用迁移；停用插件保留历史数据/事件队列。
- 命令：`invoicing.invoice.record/v1`、`invoicing.lines.allocate/v1`、`invoicing.invoice.reverse/v1` 首片仅私有服务/浏览器承载，不新增公开 PAT/MCP/支付/关期工具；未来暴露另立规划。
- PH-252 保持 proposed，须 PH-150/PH-155 done 且规划 PR 复核后才可开工。
