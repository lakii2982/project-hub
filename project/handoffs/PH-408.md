# PH-408 · 发票导入预检保存与原子提交浏览器衔接

## 当前实现与入口

财务从 `/modules/invoicing/invoice-import/` 上传销售发票 CSV：
- “上传并预检”保持临时只读，不新增 `ImportPreview`。
- “预检并保存，前往提交”仅用于 invoicing 写路径，服务端从原 CSV 重算 `preview_import`，复用 `persist_preview` 后进入现有 `/modules/onboarding/import-submit/`；保存不写业务事实，提交仍须期间预检与原子事务。超过 200 行的截断显示投影会 400 拒绝并提示拆分，避免 201–500 行被静默少存；只读预检上限不变。

实现只改 onboarding 浏览器接线、发票导入按钮及 HTTP 测试；不改业务服务、模型/迁移、金额/审批/核对口径。Issue：https://github.com/lakii2982/project-hub/issues/298 。

## 实际验证

- 新增 HTTP 测试先红后绿；相关 74 项回归通过。金样例从 HTTP 上传保存到提交，不再内部调用 `persist_preview` 补步；普通预检、越权、停用、无效 CSV、其它 kind 和伪造字段均有反例。
- 隔离 SQLite 演练库中，1440px 与 390px 均由 finance 完成上传保存 → 期间预检 → 原子提交 → committed 收据 → 发票对账 → 运营核对工作台。两票均 active、含税/不含税/税额 10000/9000/1000、已分配 10000/未分配 0；对账仍显示来源夹具的 `revenue_invoice_mismatch`，工作台保留既有 missing，不声称业务全绿。
- 390px 真实 Tab 到新按钮，`:focus-visible=true`、3px solid 焦点环、44px 高；无效 CSV 返回 400 且预览数不增；两视口无页面横向溢出。
- 配置与迁移漂移检查通过。默认本地 `runtime` 缺少既有 `core_timesheet.organization_id` 列，完整性命令失败，未擅自迁移用户库；新迁移隔离演练库完整性 `ok=true/errors=[]`、47 条账本记录。
- 首次全量回归的 6 项 DRF 兼容失败来自本机 3.16.1 与锁定 3.18.2 不一致；按锁文件校正后该 13 项套件通过，最终全量 1503 项在 163.946 秒完成、`OK (skipped=73)`。独立 S 复核先打回截断与前缀问题，修复后 PASS；复核者独立验证 201 行 400 零写入、200 行完整保存、`/pmo/` 前缀及 74 项相关回归，详见 `project/reports/PH-408.json`。
