# PH-250 · 手续费提交/批准与成本过账首片：core.document.decide bank_charge handler 与一次性费用成本

## 开工资格、价值与范围

PH-247 规划槽消费；PH-244 明确延后的手续费后续薄片第 1 片。依赖 PH-210（单一冲销/原现金消费契约，done）与 PH-244（BankCharge 草稿事实与 saved 事件，done），故 ready。承接 WP-FEE-TRANSFER 手续费剩余：把 PH-244 的 draft-only BankCharge 推进到可批准并形成**一次性公司费用成本**，使“手续费事实→独立批准→成本过账”闭环。**不做**：ReceiptFeeSettlement 未清核销/关联、`existing_cost_ref` 复用既有成本、counterparty/unconfirmed 承担方（留 PH-251）；不做退款/更正/内部转账/现金分类桥接/账本现金账 posting（手续费只走 cost 账）；不改 cash 事实。

## 行为

- **状态机**：BankCharge draft → pending（submit，提交人记录）→ approved 或 rejected（decide）；approved/rejected 终态不可再改；自审拒绝（批准者≠创建/提交者）；驳回必须填 reason；并发 decide 只一胜。
- **审批通道**：实现已登记的 `core.document.decide` 的 **bank_charge handler**（`core/services.py` 具名 `decide_document` 服务，kind=bank_charge；浏览器工作流经 costing 视图调用，命令通道不新增公开 PAT/MCP/支付/关期工具，报告披露）。审批前重读草稿/公司/期间/角色，校验 draft/pending、公司承担、金额/期间未变（若变须重新保存）。
- **成本过账（恰一次）**：approved 时同事务写 core `AccountingEvent`（event_type=`costing.bank_charge.cost`，occurred_on/posting_period 取 BankCharge 冻结值，algorithm_version 常量；claim 为 consumer=`cost`、coverage_key=`bank_charge:<BankCharge stable id>` 的 SourceConsumption）+ 恰一条 `LedgerPosting`（book=cost、origin=current、scope.kind=project、scope_id=BankCharge 项目、amount_cents=+gross_cents）。本片按费用总额 gross_cents 全额计成本；`tax_cents` 仅记录，不做可抵扣税拆分/TaxQualification 处理（明确披露，留 PH-251 与既有税额政策片）。
- **事件/审计**：审批与成本过账契约目录无独立 canonical topic，本片只写 generic audit `costing.bank_charge.submitted/approved/rejected/cost_posted` 与 core AccountingEvent，不新增/伪造 topic；`costing.bank_charge_saved.v1` 仍只由 PH-244 保存路径产生。
- **幂等**：submit/decide 各自 request_token 收据（复用 costing 收据模式），同 token 重放原结果、改输入冲突；approved 后重复 decide/重复成本过账拒绝，DB/服务双重保证恰一条成本事件。
- **期间/锁期**：submit/decide 与成本过账期间必须与 BankCharge.posting_period 一致、active 未关闭、非未来、> org.locked_through；关期拒绝。
- **权限**：owner/finance submit；另一 owner/finance 批准/驳回；auditor 只读；pm/member 拒绝；模块停用写拒绝、历史只读。
- **只读**：bank_charge 详情显示审批链与成本事件引用；`bank_charge_cost_snapshot` 只读投影（service/auditor）。
- 明确不做：ReceiptFeeSettlement、existing_cost_ref、counterparty/unconfirmed、退款/更正、现金账/分类桥接、批量/导入/期初/预测。

## 模型与字段

- 复用 PH-244 `BankCharge`（canonical 五状态枚举；本片新增 pending/approved/rejected 写入路径）与 `BankChargeReceipt`（action=submit/decide）。
- 无新业务表；PH-244 的 BankCharge 当前只有 status/version/created_by，本片须在 costing 迁移（按实际叶节点下一号，白名单已含 `pmo_plugins/costing/migrations/*.py`）新增审批链字段 submitted_by/approved_by/approved_at/submitted_at/reject_reason（或等价字段，报告说明命名），不抢号、不改已应用迁移。
- 成本事实复用 core `AccountingEvent`/`LedgerPosting`/`SourceConsumption`（PH-210 契约）；不改 core 模型结构（若确需 DB 约束调整，必须在报告披露并走 root_only 单写，不扩本片范围）。
