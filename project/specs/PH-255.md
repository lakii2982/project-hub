# PH-255 · 共享费用分摊首片：单笔已确认共享费用按显式份额跨项目分摊（无重分摊/无驱动因子）

## 开工资格、价值与范围

PH-248 规划槽消费；来源：1.0 需求 WP-SHARED（共享费用分配与重分配，S4）与 WP-EXPENSE/WP-TIME-REVIEW 上游。拟依赖 PH-162（报销费用、发生确认与待定税额，proposed）与 PH-153（投入审批与缺项处理，proposed）；依赖未 done，故 proposed。承接共享费用最小闭环：把**一笔已确认的公司/共享费用**按显式份额（整数分或权重+最大余数）分摊到 2..n 个项目，形成 append-only 分摊事实并可整体撤销；**不做**重分摊链、跨期调整、按工时/面积等自动驱动因子、跨公司、金额部分分摊后再改、预算/预测联动、收入/成本确认规则变更。不解除 PH-165/PH-157/PH-170 等 proposed。

## 行为

- **来源**：仅对同一公司、已确认（PH-162 的 expense claim 已生效）的共享费用发起；金额=该费用可分摊净额（整数分）；同一费用在任一时点至多一条有效分摊（撤销后允许重新分摊一次，历史保留）。
- **份额**：调用方提供 2..n 个项目与显式整数分份额，份额合计必须恰等于可分摊金额；或提供整数权重，服务端按最大余数法（ROUND_HALF_UP 不适用，份额为整数分）拆分且合计守恒；禁止负份额/跨公司/停用项目/重复项目。
- **事实**：`AllocationRun`（append-only，kind=shared_expense，source_ref=费用 ref，total_cents，status=posted/reversed）+ `AllocationTarget`（每项目一条，target_ref、amount_cents）；撤销以 `costing.allocation.reverse/v1` 追加负值 run（不删原 run），恰好一条反向事实；一次撤销必须整体撤销该 run 的全部 targets。
- **事件/审计**：撰写本 spec 时 canonical 事件目录**没有** allocation 专用 topic；实现前若仍无，本片以 generic audit `costing.shared_allocation.posted/reversed` 记录、不新增/不伪造 canonical topic，并在报告披露该缺口；若执行时目录已登记 allocation topic，则按契约真实 topic/版本写恰一条，posting_event_refs 按契约（本片不写会计事件/账本）。
- **幂等/期间/权限**：request_token 唯一收据；公司锁；期间 active 未关闭、非未来、> locked_through；owner/finance 写、auditor 读、pm/member 拒绝；模块停用写拒绝、历史只读。
- **只读**：分摊 run 列表/详情、按项目分摊覆盖（已分摊/可分摊，服务端派生，拒绝调用方余额/证明）。
- 明确不做：重分摊/再分配链、跨期调整、自动驱动因子、工资池分摊（既有 labor allocation 不重叠）、收入/成本确认、现金/账本/未清写入、批量/导入。

## 模型与字段

- 复用 costing 既有 `AllocationRun`/`AllocationTarget`（若当前仅支持 labor pool，需在不破坏既有语义前提下扩展 kind=shared_expense 与来源引用；报告披露扩展点）；金额整数分>0 ≤1e12；append-only + 触发器禁改删；撤销以负值新 run 表达。
- 迁移：costing 按实际叶节点下一号；不抢号、不改已应用迁移；SQLite/PostgreSQL 双实现触发器。
- 不建可编辑余额列/第二套桥表。
