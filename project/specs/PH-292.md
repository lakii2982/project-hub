# PH-292 · onboarding 导入提交首片：预览持久化后逐域提交编排实现（先前置后写）

## 开工资格、价值与范围

PH-290 规划槽消费；来源：ADR 0012（PH-267 done）、PH-274（onboarding bootstrap + 只读预览，done）、PH-289（导入提交/冲突持久化前置契约，proposed）。承接导入闭环：在 PH-289 的 ImportPreview/ImportConflict 落库与提交契约冻结完成后，实现逐域提交编排——单事务按固定域顺序调用既有 owner 命令（合同/结算/现金/成本），任一失败整批回滚，已过账走既有更正；**不做**期初正式覆盖、不直接改已过账事实、不新增 canonical `import.*` 命令、不写账本/现金/收入/未清绕过 owner 服务。依赖 PH-289 与 PH-181/PH-185（均 proposed），故 proposed。

## 行为（冻结 DoR）

- **提交服务**：`commit_import(member, *, preview_id, request_token, dry_run=True)`：校验 preview 未过期、冲突已解决、调用方不得传派生字段；dry_run 返回将执行的 owner 命令计划（域/顺序/行数/预计影响），不写；真实提交单事务按域顺序调用既有 owner 命令，任一失败整体回滚、零半笔；成功后 preview status applied（若契约无 applied 则报告披露）。
- **命令暴露**：仅具名服务/浏览器工作流；不新增 PAT/MCP/支付/关期工具；不新增 canonical `import.*` topic/command（复用 owner 既有命令语义）。
- **权限/门控**：owner/finance 提交；auditor 只读；pm/member 拒绝；onboarding 模块停用写拒绝、历史只读；跨公司/批量并发拒绝。
- **幂等/并发**：request_token 收据（org+token 唯一、输入 digest）；同 token 重放原结果、改输入冲突；公司锁；同 preview 并发提交只一胜。
- **明确不做**：期初批次/覆盖、模板市场、批量/外部 API、直接改已过账事实、跨公司、导出。
