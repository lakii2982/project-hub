# PH-316 · 运营核对工作台导出联动首片：分区下钻与底稿导出衔接

## 开工资格、价值与范围

PH-315 规划槽消费；来源：PH-309（运营核对工作台聚合，ready）、PH-304（运营核对底稿 CSV 导出，done）。本片在工作台聚合与导出首片之上做衔接：从工作台分区/issue 下钻到导出底稿（带 dataset/as_of/period 过滤），保持只读、授权、零写；**不做**新核对口径、不做新导出格式（PH-310 后续）。依赖 PH-309 与 PH-304 均已 done（工作台聚合/底稿导出已交付），故本片晋级 ready。

## 行为（冻结 DoR）

- **下钻/导出联动**：工作台每个分区/issue 提供导出链接（dataset + as_of/period），导出仍调用 PH-304 具名导出服务；工作台与导出使用同一 as_of 口径，行数/合计一致。
- **权限**：owner/finance/auditor 全量；pm 仅管理项目行；member 拒绝；导出不新增通道（复用 PH-304 路由/服务）。
- **只读/审计**：工作台只读；导出按 PH-304 语义（本波默认零 audit；如 PH-310 引入导出审计则在后续片接通）。
- **路由**：复用 canonical `ops-workbench/` 与 `ops-export/`；不新增元数据副本。
- **明确不做**：新核对口径、Zip/外发、定时导出、业务写、迁移、客户门户。

## 模型与字段 / 迁移

- 不新增业务表/迁移；复用既有服务与路由。
