# PH-276 · time 可计费确认后续片：confirmed 撤销与收入/结算只读配对

## 开工资格、价值与范围

PH-273 规划槽消费；来源 PH-269（time 可计费确认实现首片）的明确不做项与 ADR 0011 残留：confirmed 之后的撤销、与收入/结算的只读配对。依赖 PH-269（ready 未 done；实现合入并 done 后本片可晋级）、PH-266（ADR 0011，done）、PH-219/PH-222（管理收入/结算配对，done）。PH-269 未 done，故本片保持 proposed，blocker 写明待 PH-269 done 后由后续规划槽复核 DoR 再晋级。

承接 `BillableConfirmation` confirmed 之后的**append-only 撤销**与**只读配对**：confirmed→reversed（不物理删除、不改历史分钟）、撤销写 generic audit 与既有 status 迁移（不新增 canonical topic——契约仅有 time.billable_confirmed.v1），并只读展示与 RevenueRecognition/Settlement 的配对状态（已配对/未配对/金额差）；**不做**收入确认写、账本/现金/成本/未清写、重新确认、批量/导入、费率、timesheet 提交/审批。不解除 PH-154/PH-269 后续之外 proposed。

## 行为（冻结 DoR）

- **撤销**：owner/finance 对 confirmed 的 BillableConfirmation 执行 `reverse_billable_confirmation(member, confirmation_id, *, reason, request_token, expected_version, dry_run=True)`：公司锁、fresh 重读、仅 confirmed 可撤销、创建人不能撤销自己（换一位 owner/finance）、reason 1..500、expected_version 匹配、期间/锁期不适用（无金额/日期写）、同 token 重放、并发只一胜；同事务 status→reversed、version+1、generic audit `time.billable_confirmation.reversed`（含 reason/refs，不含敏感值）、复用既有 receipt（action=reverse）；**不新增 canonical 事件 topic**（契约无 reversed 事件），report 披露。
- **只读配对**：`billable_confirmation_pairing(member, confirmation_id)` 返回：confirmation ref/status/confirmed_minutes、timesheet/contract_line refs、是否存在引用该确认的 RevenueRecognition/Settlement（只读查询 PH-219/PH-222 owner 接口）、配对状态（paired/unpaired/partial）与差额（仅展示，不写）；列表 `billable_confirmation_pairing_list(member, *, project_id=None)`。
- **权限/门控**：写 owner/finance；读 owner/finance/auditor；pm 仅管理项目只读；member 拒绝；time 模块停用写拒绝、历史只读。
- **幂等/审计**：receipt（org+token 唯一，action=reverse）；重复撤销拒绝；dry_run 零副作用；拒绝零半笔（BillableConfirmation 状态/version、事件、审计计数不变，generic audit 除外）。
- **迁移/触发器**：新增 time `0002_time_billable_reversal_guards`（不改已应用 0001）——扩 receipt action 允许 `reverse`、双 vendor 触发器允许 confirmed→reversed 单字段更新；本片不新增表，撤销状态迁移由该迁移放行，`makemigrations --check` 必须无未生成变更。
- 明确不做：收入确认/账本/现金/成本/未清写、重新确认、批量/导入、费率、跨公司、canonical topic 新增。

## 模型与字段

- 复用 PH-269 `BillableConfirmation`（status draft/confirmed/reversed、version）与 `BillableConfirmationReceipt`；**新增 time 迁移 `0002_time_billable_reversal_guards`**（不改已应用 0001）：扩 `BillableConfirmationReceipt.action` CheckConstraint 允许 `draft.save/confirm`/**`reverse`**；以 SQLite/PostgreSQL 双实现触发器允许 **confirmed→reversed** 单字段状态更新（OLD.status=confirmed、NEW.status=reversed、其余字段不变），保留既有 draft→confirmed 路径与 receipt 不可改删；不新增表、不改 core/contracts 迁移。
- 不新增 canonical topic/command/schema；reversed 仅状态+generic audit。
- 配对只读聚合 RevenueRecognition/Settlement 既有字段，不新建桥表/可编辑余额。

## 服务

- `reverse_billable_confirmation(...)`（写，append-only 状态迁移 + receipt + generic audit）。
- `billable_confirmation_pairing`/`billable_confirmation_pairing_list`（只读）。
- UI：列表/详情增加撤销入口与只读配对区；不新增写事实。

## 权限与拒绝

- 写 owner/finance；读 owner/finance/auditor、pm 管理项目；member 拒绝；模块停用写拒绝。
- 拒绝：非 confirmed 撤销、重复撤销、创建人自撤、跨公司、expected_version 不符、token 改输入、reason 非法、客户端传状态/收入/账本覆盖；逐条断言零半笔。
