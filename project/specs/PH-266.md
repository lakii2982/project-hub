# PH-266 · time 插件归属与可计费确认契约决策前置

## 开工资格、价值与范围

PH-263 规划槽消费；来源：1.0 需求 WP-TIME-INPUT/WP-BILLABLE（legacy PH-152/PH-153/PH-154）与 PH-259（发票插件归属决策）同类的**归属决策前置**。当前工时事实在 core（`core.Timesheet`、`core.services` 审批、`core.labor_projection` 月池，PH-025/PH-217 done），客户确认可计费事实的 canonical 实体 `BillableConfirmation`（`x-owner=time`）与命令 `time.billable.confirm/v1`、事件 `time.billable_confirmed.v1` 已在契约中冻结，但**没有 time 插件 App/迁移 owner**，不能直接新建 scaffold。本片只产出决策与后续契约，不实施可计费确认本身。

依赖：PH-025（项目级工时核算，done）、PH-214（三模板合同批准/收费模板含 confirmed_time，done）、PH-217（月度人工确认/分配，done）、PH-224（客户结算/未清，done）——决策所需事实均已 done，故 PH-263 晋级 ready。

## 精确交付（docs-only）

1. 新建 ADR `docs/adr/0010-time-plugin-ownership.md`，冻结：
   - `BillableConfirmation`（canonical `x-owner=time`、`x-record-kind=owned_fact`、状态 draft/confirmed/reversed）由**新建 `pmo_plugins/time` 插件**承载，还是由 core/contracts 既有 owner 承载；给出唯一选择与理由（插件 SDK/迁移 owner/入口门控/历史约束）。
   - time 插件（若新建）的 `plugin.py`/`domain_metadata.py` 路由与 access 元数据、迁移序号 owner（避免与 contracts 0003/settlement 0005 抢号）、与 core.Timesheet 只读关系（不复制工时事实）。
   - `time.billable.confirm/v1` 的暴露口径：仅具名服务/浏览器工作流，或接入 PAT/MCP（若接入须列命令胶囊与权限）；本决策默认不新增个人 AI 审批/支付能力。
   - 与合同 `confirmed_time` 收费模板、PH-224 结算/OpenItem、PH-219/PH-222 管理收入的分工：可计费确认只记录客户确认事实，不写收入/账本/现金/未清。
