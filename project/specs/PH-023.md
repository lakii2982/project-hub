# PH-023 · Kimi 视觉系统与前端规范

来源：2026-10-25 用户六项需求、父 Issue #41；前端相关全部交给本机 Kimi Code。先完成本任务并冻结规范，再施工产品前端。后端 PH-024/025 可同时进行。

交付 docs/engineering/visual-system.md、frontend-standards.md、ui-tokens.css、可直接打开的 ui-specimen.html，及 AGENTS.md 的必读入口。视觉方向对标 Linear 的信息层级、侧栏/页头/页签一致性与 Atlassian 的语义令牌/密度/可访问性，不复制品牌资产。中文经营SaaS，清晰浅色工作台、克制强调色、稳定间距与字体、表格优先，避免大段英文眉题、装饰渐变和堆叠数字卡片。

设计需覆盖侧栏/移动导航、页头与操作层级、项目/基础资料页签、筛选、表格、表单、审批、状态、空态、错误、反馈、登录、趋势图与可展开数据表；样张至少包含经营总览、项目页签、基础资料、表单，桌面1440与390px可用。令牌包含语义色、字体、字号/行高、间距、圆角、边框、阴影、断点、焦点、图表颜色。标准正文不小于14px、表格/辅助文字不小于12px；金额等宽数字，中文长标题正常折行。无远程字体/脚本、无构建链、无新依赖，使用系统中文字体和原生CSS/JS/SVG。

规范明确后续前端必须先读规范/视觉系统、使用令牌和共享组件，新增模式先更新规范与样张；审查桌面/390px、焦点/键盘、溢出、空态、错误、加载或不可用状态，拒绝只换色不统一布局。不强制新审批阶段，整合者作技术验收。AGENTS只追加此入口，不改已有治理。

参考：https://linear.app/now/behind-the-latest-design-refresh 、https://linear.app/changelog/2024-03-20-new-linear-ui 、https://atlassian.design/foundations/typography 、https://atlassian.design/foundations/spacing 、https://atlassian.design/tokens/design-tokens/ 。引用作为设计借鉴，不称官方组件或认证。

本任务不涉及数据库、状态机、权限、幂等或金额计算。反例：390px不可横向溢出；焦点不可丢；组件颜色不能仅靠色觉区分。Kimi只写规范/样张及AGENTS，整合者写状态/报告；运行契约两条验收并做浏览器视觉检查。依赖完成只允许把已冻结后续任务置ready，报告区分设计、浏览器、自动化和生产未验证。

治理风险校正：本任务会追加AGENTS入口并更新任务状态，两者均为projectctl CRITICAL_PATHS；风险必须S，最终独立执行器只读复核及两条验收通过后才能经PR合入。文件范围与产品设计均不扩大，旧A标注不得用于绕过门禁。
