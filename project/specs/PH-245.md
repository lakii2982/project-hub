# PH-245 · 内部账户互转首片：成对现金关联、公司范围抵销与撤转（无跨币种、无手续费）

## 开工资格、价值与范围

PH-242 规划槽消费；来源：1.0 需求 V1-CSH-08（WP-FEE-TRANSFER）与 PH-233/PH-238 遗留候选。依赖 PH-239（现金分类与账本桥接首片，done（c1cd18d，PR #142））与 PH-244（手续费与净额对账草稿首片，done（37b5fdf，PR #137））；依赖全部 done，PH-248 规划槽据此晋级 ready，实现仍须规划 PR 正常合入可信 BASE 且任务 ready 后才可开工。承接“内部账户成对关联、可检查缺失一侧、公司范围抵销、不增加公司净流入”的首片：把同企业两条已过账、方向相反、金额相等的现金流水成对关联为内部互转，支持撤转；**不做**跨币种、手续费、多账户批量、部分金额、跨日期/跨期间、自动对账、导入、退款、更正、收入/成本/应收/应付/未清写。本片不解除 PH-170/171/PH-169 proposed。

## 行为

- **成对创建**：owner/finance 选择同企业、均已 posted 的两条现金流水 out_cash（direction=out）与 in_cash（direction=in）；要求 funding_account 不同、gross_cents 相等、transaction_date 相等；transfer_date 取该日期，不未来、不 ≤ org.locked_through、所在 AccountingPeriod active 未关闭；同 token 重放原结果、改输入冲突；每条现金流水全生命周期至多参与一条有效互转（重复/并发只一胜）。
- **分类事实与账本桥接**：互转创建时经 PH-239 的分类桥接具名接口为两条流水各写一条内部 `CashClassification(classification='transfer')` 及其规范 `cash.classification_recorded.v1`（恰 1 个 core/accounting_event），现金账 posting 为 cash_out(−gross)/cash_in(+gross)、scope=funding_account；公司净现金恒为零（抵销）。**契约选择（推荐 A，已冻结，PH-239 已实现）**：PH-239 的模型/DB `classification` 枚举已含 receipt/payment/advance/tax/**transfer**，其中 transfer 仅供内部互转编排使用；客户端 `cash.classification.record/v1` 仍只接受四值，PH-239 客户端服务对 transfer 请求拒绝。本片必须复用 PH-239 已合入的**非路由内部服务** `pmo_plugins/cash/classification_services.record_internal_classification(member, *, cash_transaction_id, evidence, occurred_on=None, posting_period=None, request_token, dry_run=True)`（`PH-245-only`，不暴露 HTTP/PAT/canonical transfer 入口）为两条流水写 transfer 分类与桥接；不得自建第二套分类/桥接/事件，也不改变其语义；`pmo_plugins/cash/classification_services.py` 只允许调用（不在本片写白名单内），PH-239 的服务/语义原样保留。与 PH-244 手续费/净额无耦合：互转不写 BankCharge/费用，不调用手续费服务，手续费片也不消费互转事实。
- **规范事件**：成对创建恰一条 `cash.internal_transfer_linked.v1`（source=internal_transfer ref、payload changed_refs=[internal_transfer ref, out 分类 ref, in 分类 ref]、posting_event_refs=[]——posting 归属两条分类事件，不重复记在公司互转事件上）。**不做**手写第二套桥表：`advance-openitem-offset`/关系投影只读派生；不新增事件 topic。
- **撤转（append-only）**：仅对 active 互转；新增两条 `CashClassificationReversal`（各自撤原分类，恰一条 `cash.classification_reversed.v1` 并携带冲销 accounting event），把 InternalTransfer 状态 active→reversed（仅该字段更新，由触发器放行，金额/引用/日期不变），恰一条 `cash.internal_transfer_reversed.v1`（source=internal_transfer_reversal ref、payload changed_refs 恰 3=[internal_transfer ref, 2 分类撤转 refs]、original_internal_transfer_ref、classification_reversal_refs=2、posting_event_refs=[]）；同一互转只能撤一次，重复/并发只一胜；撤后公司净现金仍为零。
- **余额/核对口径**：不建可编辑余额；`internal_transfer_snapshot/list` 返回成对双方现金 ref/账户/金额/transfer_date/out_transaction_date/in_transaction_date/状态（canonical InternalTransfer 的 out_transaction_date/in_transaction_date 必填字段须映射）；`internal_transfer_integrity` 只读检查：每 active 互转恰一对（缺失一侧即报错）、方向/金额/日期一致、公司范围现金账净额不受影响（Σcash_in−Σcash_out 不变）。
- **期间/权限**：写 owner/finance；读 owner/finance/auditor；pm/member 拒绝；cash 模块停用写拒绝、撤权写拒绝；写入口不新增公开 canonical 通道（`cash.internal_transfer.link/v1`、`cash.internal_transfer.reverse/v1` 由私有服务承载，报告披露）。
- 明确不做：跨账户多跳、手续费与净额拆分（PH-244）、非公司账户/员工账户、跨币种、部分金额互转、跨日跨期、自动匹配、导入、期初、退款/更正、收入/成本/应收/应付/未清、账龄/预测。

## 模型与字段

- `InternalTransfer`（cash 新增，append-only owned_fact）：org、out_cash_transaction FK(related_name='out_transfers')、in_cash_transaction FK(related_name='in_transfers')、out_cash_ref JSON、in_cash_ref JSON、transfer_date、gross_cents(>0 ≤1e12)、**out_transaction_date（=out 现金 transaction_date，服务端派生写入）**、**in_transaction_date（=in 现金 transaction_date，服务端派生写入）**、status（canonical 枚举 draft/active/posted/reversed/superseded 保留；本片只产生 active/reversed，其余不产生）、version、created_by、created_at。约束：**无条件 Unique(out_cash_transaction)、Unique(in_cash_transaction)（每条流水终身至多一次互转，不因撤转释放）**；gross>0；仅 active→reversed 单字段状态更新由触发器放行，其余字段不可改、不可删。
- `InternalTransferReversal`（cash 新增，append-only，canonical 已定义）：org、internal_transfer_ref（SourceRef）、out_classification_reversal_ref、in_classification_reversal_ref、occurred_on、posting_period、status（canonical `posted`）、version、created_by、created_at；`cash.internal_transfer_reversed.v1` 的 source 必须为该 reversal ref。约束：append-only、不可改删；同一 internal_transfer 至多一条 reversal（Unique(internal_transfer_ref)）。
- `InternalTransferReceipt`：org、request_token 唯一、action(link/reverse)、input_digest、result、created_by、created_at。
- 复用 PH-239 的 `CashClassification`/`CashClassificationReversal` 与 core `AccountingEvent`/`LedgerPosting`（经具名桥接接口），不新建桥表、不新增可编辑余额列。
- 迁移：cash 当前叶为 `0005_cash_classification_guards`（PH-239），本片新建下一号 `0006`（InternalTransfer、InternalTransferReversal 新表与触发器；不抢号、不改已应用迁移）；SQLite/PostgreSQL 双实现触发器。不新增 core 迁移（core 叶 0009 由 PH-239 已落）。
- **实现注意**：两腿分类必须使用不同 request_token（各自独立收据）；`record_internal_classification` 为内部函数、不含角色校验，服务层必须先做 owner/finance、模块/撤权校验再调用；分类与撤分类各自会写 CashReceipt（PH-239 语义），本片 report 须披露该收据数量与 action。
- 所需前置已合入：PH-243 的 canonical 修正（分类事件 posting_event_refs 恰 1）与 core LedgerPosting 约束放宽（cash_in/out + funding_account/legacy_project）随 PH-239 done（c1cd18d）；本片不再改契约。

## 服务

- `link_internal_transfer(member, *, out_cash_transaction_id, in_cash_transaction_id, evidence, occurred_on=None, posting_period=None, request_token, dry_run=True)`：公司锁；fresh 重读角色/企业/两条流水/账户/期间/既有互转；校验 posted、方向、账户不同、金额/日期相等、金额/期间/锁期/未来、流水未参与其它互转；dry_run 零副作用；事务内写两条内部 classification + 两条 classification 事件/posting（经 PH-239 桥接）+ InternalTransfer + generic audit `cash.internal_transfer.linked` + linked 事件 + receipt。
- `reverse_internal_transfer(member, transfer_id, *, reason, evidence, occurred_on=None, posting_period=None, request_token, expected_version, dry_run=True)`：仅 active；公司锁内 fresh 复核；写两条撤分类记录 + 两条 classification_reversed 事件/冲销 posting + InternalTransfer status→reversed + audit `cash.internal_transfer.reversed` + reversed 事件 + receipt；重复/并发只一胜。
- 只读：internal_transfer_snapshot/list、internal_transfer_integrity。

## 权限与拒绝

- 写 owner/finance；读 owner/finance/auditor；pm/member 拒绝；模块停用/撤权写拒绝。
- 拒绝：草稿/未 posted/跨 org/同账户、方向不符、金额不等/≤0/bool/float/超1e12、日期不等/未来/locked_through/关期、流水已参与互转、重复 token 改输入、撤转非 active/重复撤/并发、客户端传状态/余额/账本/事件覆盖、分类命令传 transfer。
- 所有拒绝零半笔：InternalTransfer/两分类/事件/审计/posting/receipt/现金/未清计数不变（generic audit 与其非 canonical 事件除外）。
