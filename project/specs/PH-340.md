# PH-340 · 通知中心实现首片：当前成员收件箱、去重与已读/忽略

## 开工资格、用户成果与范围

PH-410 有界规划重基线：PH-355 的 reminder refs/扫描骨架已 done。本片实现站内通知收件箱最小闭环：当前成员同步可见提醒、来源去重、已读/忽略和历史快照；不做邮件/短信/Webhook、自动审批/支付/锁账、客户门户或新 canonical 实体。PH-301/314 保持 proposed 历史承接；PH-380 须等本片 done 后再复核。

## 冻结行为

- **同步**：只物化 PH-355 `scan_reminders` 对当前成员返回的提醒。客户端不能提交 reminder/source/project/recipient/digest 作为可信输入。
- **内部快照**：新增非 canonical `Notification`：organization、member、reminder_key、reminder_ref/source_ref/project_ref、issue_code/severity、title/summary/due_on/as_of/deeplink、created_at/read_at/ignored_at。`member + reminder_key` 唯一；组织必须同时匹配 member，数据库约束/服务双重保证。
- **幂等**：同步使用公司锁与 get-or-create；同一事实重试或并发不多条。已有快照不覆盖首次来源/文案，事实状态由后续读取另行判断；事实解除后不产生新待办，历史保留。
- **权限/停用**：每次读取重新检查 active membership/user。owner/finance/auditor 可见其角色/项目范围，pm 仅管理项目，member 仅本人；跨 org/成员拒绝。撤权后历史也不可读。来源模块停用不新增同步，已有本人快照保留只读历史。
- **已读/忽略**：本人可标记已读或忽略；状态不改业务事实、不构成授权。默认列表隐藏 ignored，已读可筛选；重复操作幂等。无外部发送。
- **入口**：根路由 `/notifications/`，共享导航“通知中心”；只读 GET 列表与筛选，写状态仅本人 POST。无第二套 owner 到期规则。

## 模型与迁移

整合者按当前 core 迁移叶生成下一号；不得修改已应用迁移。`Notification` 是内部通知快照，不是 canonical 业务事实，不写账本、收入、现金、审批或 Outbox。
