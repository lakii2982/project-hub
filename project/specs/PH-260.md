# PH-260 · 管理收入确认与结算配对首片：单一收入方法确认 + 与结算/成本的只读配对结果

## 开工资格、价值与范围

PH-258 规划槽消费；来源：1.0 需求 WP-REVENUE-PAIR（收入与结算配对及结果查询，S4）与 legacy PH-168 首片。拟依赖 PH-167（工时/固定服务期收入，proposed）、PH-156（客户结算/未清/账龄，proposed）、PH-162（报销费用/发生确认，proposed）、PH-161（人工分配/差额/开放期调整，proposed）；依赖未 done，故 proposed。承接收入最小闭环：按一种收入方法（首片：固定价里程碑确认，PH-166 的最小实现）确认收入，并与结算（PH-156 未清/开票前结算）及已确认成本做**只读配对结果查询**；**不做**多方法切换、调整分录、红冲、开票、税额、预算/预测、现金/账本/未清写入（收入确认按既有 core 账本契约写 AccountingEvent/LedgerPosting，不新造账本语义）。不解除 PH-166/167/168 proposed。

## 行为

- **收入确认**：owner/finance 对已批准合同/里程碑（PH-150/PH-166 上游来源，经具名只读校验同 org/项目/往来方/状态）按固定价里程碑确认收入：金额整数分>0 ≤1e12、≤里程碑/合同剩余可确认额（服务端派生）；确认期必须 active、非未来、> locked_through、未关闭；同一里程碑累计确认不得超过其金额；幂等 request_token。
- **配对结果（只读）**：按项目/期间返回 收入确认 vs 结算未清（PH-156）vs 已确认成本（PH-162/PH-161）的配对视图：recognized_cents、settled_cents、unsettled_cents、cost_cents、margin_cents（全部服务端派生，SignedCnyCents，拒绝调用方余额/证明）；差异不自动更正，只呈现。
- **事件/审计**：确认收入按既有管理收入契约写规范事件（若 `management_revenue.recognize/v1` 已定义 topic/字段则复用，不新增/伪造）；写 generic audit `management_revenue.recognized`；配对查询零写入。
- **期间/权限**：owner/finance 写确认；auditor 只读；pm 只读其项目配对视图；member 拒绝；模块停用写拒绝、历史只读。
- **幂等/版本**：重复 token 重放原确认、改输入冲突；确认后里程碑/合同变更走后续片（不在本片）。
- 明确不做：多收入方法互斥切换、调整/红冲、开票、税额、预算/预测、现金/结算/未清写、批量/导入。

## 模型与字段

- 复用 management_revenue 既有确认事实（若不存在则按契约新增 `RevenueRecognition` append-only：org、project_ref、counterparty_ref、milestone_ref、period_id、recognized_cents(SignedCnyCents)、status(posted/reversed 仅 posted 首片)、version、created_by、created_at；Unique(milestone_ref) 仅一条有效确认）；不建可编辑余额。
- 迁移：管理收入按实际叶节点下一号；不抢号、不改已应用迁移；SQLite/PostgreSQL 双实现触发器。
- 复用 core AccountingEvent/LedgerPosting（收入账 book=revenue/scope=project）与 settlement/contracts/costing 具名只读；不改 core 模型。
