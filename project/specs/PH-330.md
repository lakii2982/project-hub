# PH-330 · 分摊/预算 ETC 实现首片（costing 0005/0006）

- 里程碑：v1.0.0 / 批次 B
- 风险：S
- 依赖：PH-313（分摊/预算实现前置，ready 未 done）、PH-322（关期/结项实现，proposed）
- 状态：proposed（依赖完成后由规划槽复核 DoR 晋级）

## 目标

按 PH-313 spec 落地共享费用分摊与预算/ETC 写侧首片：costing 迁移 `0005_shared_cost_allocation`、`0006_project_budget`；append-only 批次/版本；净零重归属；只读核对与 verifier 分支；页面。

## 行为 / 契约

执行时以 PH-313 `§1–§8` 与 PH-305/PH-306 冻结契约为唯一口径（本 spec 不重复冻结正文，只登记切片边界）：

1. 模型/迁移：`SharedCostAllocationBatch/Line/Receipt`、`ProjectBudgetVersion/Line/Receipt`；append-only vendor-aware 守护；`costing/0005`、`0006` 取实际叶。
2. 服务：`create_shared_cost_allocation_batch`/`reverse_shared_cost_allocation_batch`、`create_project_budget`/`approve_budget`/`supersede_budget`/`reject_budget`；公司锁、request_token 收据、expected_version、dry_run、期间/关期。
3. 分摊驱动/权重、末项吸收 `basis_points_clamped_half_up_last_absorb_v1`、净零 AccountingEvent+claim 重归属（source 负/project 正）；预算四眼、`budget_residual_v1` ETC 只读派生。
4. 只读核对页 + verifier 分支；issue codes 按 PH-313。
5. 无 core 迁移；白名单增补需规划槽授权。

## 反例

- 重复有效正向批次/预算版本 → 拒绝；超池分配、bp≠10000、负末项 → 拒绝；关期后写 → 拒绝；无收据重放/改输入 → 拒绝；append-only 历史 UPDATE/DELETE → 拒绝。
