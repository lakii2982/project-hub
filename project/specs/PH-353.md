# PH-353 · 导入提交拆分：ImportPreview/ImportConflict 持久化与原子提交首片（PH-289 拆分）

## 开工资格、价值与范围

PH-351 规划槽消费；PH-289 拆分。范围：把 PH-274 只读预览推进为**持久化提交首片**：ImportPreview/ImportConflict canonical 持久化、字段映射/冲突清单、原子提交（全有或全无）、请求令牌幂等、错误行回滚；**不做**PH-181/185 的期间预检/四类核对实现、新账本事实、客户数据。依赖 PH-181/PH-185 未 done，故 proposed。

## 行为（冻结 DoR）

- 预检持久化：ImportPreview/ImportConflict 按 canonical 形状落库；ephemeral 预览不进业务事实；x-owner=onboarding。
- 提交：复用 PH-274 映射；同 token 重放；提交全有或全无（事务/公司锁）；失败回滚且零业务事实。
- 冲突：跨 org/项目、来源未批准、金额不守恒、越期、重复键逐条拒绝；错误行含原因/原值。
- 权限/门控：owner/finance 写；auditor 读；pm 项目摘要；member 拒绝；停用 history_read。
- 明确不做：期间预检/核对（PH-181/185）、账本/收入/现金/成本事实、客户数据、新 canonical topic（除非已冻结）。

## 模型与字段 / 迁移

- onboarding 插件内部 ImportPreview/ImportConflict 持久化模型 + 迁移 0002（新号按实际 BASE）；不改已应用迁移。
