# PH-386 · 后续交付独立规划入口（接续 PH-381）

## 开工资格、价值与范围

接续 PH-381 规划入口，保持 1.0 规划链不断：只做后续问题定位、独立规划契约/规格/依赖/精确白名单及验证方法，**不实施**产品业务/工程改造、不扩本任务范围。状态/范围/验收以可信 BASE `project/tasks.json` 为准，proposed 不是开工许可。本槽依赖 PH-381 完成；PH-381 done 后由下一规划槽复核 DoR 再置 ready，本 BASE 登记为 proposed。

## 本轮规划范围

- 依赖达成复核：按本槽 BASE 复核 PH-382/383/384/385 与批次 C/D 剩余 proposed 的依赖/DoR。
- 批次 C 收尾：PH-367/372/377/382 链、PH-366 发布资格 gate、PH-335/368 容量基线后续。
- 批次 D：发票批量/导入、insights、通知、导入提交、多币种/合同后续、验收运维；每项须有上游 done 证据，否则 proposed 并写清缺口。
- 独立工程改造规划：仅用户明确授权的新目标下登记；不改既有门禁/验收命令/报告 schema。
- 下一规划槽：完成时留下新的独立规划入口（新 PH 编号，先核号），只把依赖 done 且 DoR 完整的任务置 ready。
- 约束：规格/验收不得含未替换任务编号占位符；acceptance 只用可执行命令；不建 scaffold、不改 contract schema、不自扩白名单。

## DoR与适用性

本片只产生后续规划；业务字段/类型/默认值、状态机、授权、幂等键、金额/日期/舍入、迁移均不适用。反例：借规划入口改产品代码/工程脚本；正确例：只改规划规格/依赖清单与本任务报告交接，check 与治理测试实际通过，再经独立 S 复核/CI/PR。
