# PH-235 · projectctl 会话效率命令

来源：用户2026-10-30授权"Agent交付token降低至少40%、任务时间缩短至少50%"的工程改造，经PH-233规划槽登记（依据AGENTS.md"用户提出新问题时先定位，再补入规划任务"）。仅新增只读命令与现有命令的可选参数；不改变`check`/`next`/`brief`/`verify-change`既有输出语义，不放宽任何治理检查，不修改CRITICAL_PATHS、验收命令或报告schema，不新增依赖。

## 交付内容

1. `next --compact`：仅输出 id、title、kind、risk、status、milestone、depends_on，省略 allowed_paths、acceptance、github_issue 等大字段；省略 `--compact` 时输出与现状逐字节一致。ready 判定逻辑不变。
2. `orient`：单次 JSON 输出新会话开场所需最小事实——manifest 摘要、活动 handoff 正文（文本）、compact ready 列表（复用 --compact 口径）、AGENTS.md「验收与交付」四条命令。只读文件，不执行任何命令；任一来源缺失时返回 ok=false 与结构化错误，不猜测。
3. `draft-report <id>`：从 tasks.json 生成 `project/reports/<id>.json` 骨架写到 stdout，不写任何文件。骨架含 task_id、summary 留空、tests 按 acceptance 预填 command 且 result 一律 `"not_run"`、evidence 空串，review（S 级 required=true、status `"pending"`）、unverified、deviations 空数组。骨架只减少模板抄写；`_validate_report` 与所有门禁不变，pass 仍以实际运行为准。

## 反例（实现不得出现，测试须覆盖）

- `--compact` 输出缺 ready 判定所需字段或改变默认输出。
- `orient` 输出非 JSON、在 tasks.json/handoff 缺失时静默猜测或退化为部分成功。
- `draft-report` 预填 `result:"pass"` 或生成不满足 `_validate_report` 的骨架。
- 任何对 `verify-change`、`_validate_report`、`check` 校验逻辑的修改。
