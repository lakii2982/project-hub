# PH-224 · 客户结算、到期/质保未清与账龄（应收首片）

## 开工资格、价值和范围

PH-223 规划候选；拟依赖 PH-214、PH-219、PH-222、PH-223。须规划 PR 正常合入可信 BASE、依赖 done 且任务 ready 后才可实现，本文不是开工许可。承接正式 PH-155（应收结算条件与质保未清）第 1 片与 PH-156（账龄只读），在既有已批准合同/验收/服务期收入之上补齐"应收结算 → 到期与质保未清 → 账龄/质保只读"闭环。PH-155/156 及 PH-157/158/170/171 状态与依赖不改，不冒称完成原任务或完整 1.0。

产品边界（本片冻结）：**条款行组合结算**。一次结算覆盖 1..n 个完整、未使用过的批准 PaymentTerm/WarrantyTerm 行，金额只由条款 gross 派生，客户端不得传金额或任意分配；允许"部分结算"，因为条款本身即批准的分期/质保结构（金样例 UAT-03-S03 的 50% 与 UAT-10 的 50%+40%+10% 均成立），但**不允许一次结算只取条款金额的一部分**。可结算的前提是该合同明细已有真实已确认履约且本次净额不超过"已确认履约净额 − 已结算净额"；未达实质条件只能保存草稿，不建未清项。本片不做现金/核销/抵扣、折让/减免/坏账、应付、发票、开票、争议与延期（V1-SET-09 留后续薄片）、AgingCase 写入；不做生效结算的反冲（无核销模型时反冲会留下不可解释的负未清，留待核销/纠错薄片统一处理）。AgingCase 实体不在本片生成，账龄由 OpenItem 真实字段按基准日只读派生。

## 唯一 owner 与来源

- `settlement` 是本片唯一写 owner：Settlement、OpenItem、SettlementReceipt 与账龄读服务；不存余额列、不建第二份可编辑余额。
- 只通过其它 owner 的具名服务读取事实，不直接跨 app 查表：
  - contracts 新增只读 `approved_terms_snapshot(member, line_ref, as_of)`：复用 approved_line_snapshot 的批准/摘要校验，返回批准明细与全部 PaymentTerm/WarrantyTerm 冻结行（condition_type、gross_cents、due_date、release_condition、release_on、稳定 term ref）及合计；要求条款合计恰等于明细含税额（未覆盖全部含税额的合同不可结算）。
  - delivery 新增只读 `confirmed_line_performance(member, line_ref, as_of)`：按合同模板汇总该明细下真实已确认履约来源（固定节点 Acceptance 覆盖；服务期已确认月行），返回累计净额、来源 ref/版本/金额；只做事实汇总，不判定完整性门槛。
  - 收入/成本/现金事实只读；结算不产生管理收入、成本或现金，不写 AccountingEvent/LedgerPosting。
- 公共 schema 已冻结 Settlement/OpenItem/AgingCase 与 `settlement.settlement.draft.save/v1`、`settlement.open_item.create/v1`、`settlement.open_item.get/v1`、`settlement.aging.get/v1`、`settlement.open_item_created.v1`；本片不改 schema/fixture/extension-freeze 摘要（无字段扩充），实现只做已登记字段、事件与查询的服务端校验。

## 模型与字段（私有工作流 + 公共实体映射）

- Settlement：UUID、org/project/contract_line/contract_version/selection/counterparty 真实 FK、contract_line_ref、source_ref（公共来源：本次结算最新的真实已确认履约来源；完整列表见私有 source_performance）、policy_version、pricing_configuration、terms_snapshot（全部可用条款 + 本次所选条款的冻结副本）、source_performance（真实已确认履约 ref/版本/金额列表）、evidence、settled_on、due_date（所选条款最早到期）、gross/net/tax 整数分、version、status(draft/submitted/active/withdrawn 内部态不输出 canonical)、created_at/created_by、submitted_by、approved_by/approved_at/approved_version、approval_audit、approved_input_snapshot、review_note。DB 约束：gross=net+tax、金额≤10^12、coverage 顺序；`contract_line` 上的已用条款由消费键唯一保证，不建第二套余额列。
- OpenItem：UUID、org/project FK、settlement FK related_name='items'、direction('receivable')、partition_kind('due'|'retention')、partition_key（稳定键：term 类别+term id，全局唯一）、term_ref、counterparty FK、payee_ref、scope、source（Settlement 的 source_ref）、gross_cents、tax_cents（按累计含税额比例 HALF_UP 分摊，全部结算合计等于行税额）、due_date（warranty 用 release_on，可为空）、occurred_on、release_condition、status(active)、version、created_at；UniqueConstraint(partition_key)。
- SettlementReceipt：org、request_token 唯一、action、input_digest、result、created_by。
- 所有分区合计 gross 必须等于 Settlement.gross；OpenItem 创建后不可改；Settlement 进入 active 后除审核字段与状态外不可改；DB 触发器（SQLite/PostgreSQL 双实现）保证父/分区不可变、分区与父 org/project 一致、分区金额合计=父含税额。

## 服务、幂等、事件与期间

- 具名服务（`receivable_services.py`）：save_settlement、submit_settlement、review_settlement、withdraw_settlement、settlement_snapshot、open_items_for_settlement；条款选择 term_refs 是服务层显式输入，公共 SettlementDraft 不新增字段（命令接线时由 internal service 承载，不改 schema）；`aging_services.py`：open_item_aging/aging_export_rows（只读）。写函数统一 expected_version（create 不传）、request_token、dry_run 严格 bool 默认 True，review 额外 decision(approve/return/reject)+note，其余原因操作 reason。
- 保存：server 取 approved_terms_snapshot 与 confirmed_line_performance，校验所选 term_ref 均属该明细、未消费；同时要求该明细全部可用条款（非 warranty 的 PaymentTerm + WarrantyTerm）合计恰等于行含税额，否则整行不可结算并提示条款未覆盖；所选条款 gross 合计即本笔 gross；按累计比例计算本笔 net/tax/gross（net_cum(gross_cum)=HALF_UP(line.net*gross_cum/line.gross)，本笔=net_cum(新增累计)−net_cum(既有累计)，tax=gross−net），冻结 terms/source 快照；金额、方向、payee、scope、日期不得由调用方覆盖。草稿只登记，不建未清项、不消费条款。
- 提交/批准：批准者须为另一 owner/finance（非 creator/submitter），company lock 内 fresh 重读批准条款、已确认履约、既有结算累计与消费键后：状态置 active、版本+1、冻结 approved_input_snapshot 与 approval_audit、一次性 bulk 建全部分区 OpenItem、写 settlement receipt、每个分区同 atomic 发一次已登记 canonical `settlement.open_item_created.v1`（source=OpenItem 永久 source_ref，不改 events/registry）；结算激活本身无已登记 canonical，用 generic audit。草稿/提交/退回/撤回用 generic audit。
- 幂等：request_token 同键重放原结果、异输入冲突；条款一次性由 SourceConsumption(org, consumer='settlement', source_id=line.id, coverage_key='term:<kind>:<term_id>') 唯一 + OpenItem.partition_key 唯一双重保证，重试/重复不产生第二份未清；同一履约来源可对应多笔按条款分期结算，但不得重复使用同一条款行。
- 期间/锁期：settled_on 必须为有效日期且不晚于 Asia/Shanghai 今天；与 org.locked_through 相交或所在 AccountingPeriod 非 active/已关闭时拒绝；到期日/质保释放日可未来。写入不建 AccountingEvent。
- 生效结算不可变、无反冲：本片不提供 reversed 路径（无核销模型时反冲会产生不可解释的负未清），错误在草稿/提交阶段更正；生效后的纠错留待核销/折让薄片，spec/report 明确披露，不声称已覆盖全部纠错。

## 权限、状态与反例

- 角色：owner/finance 可保存/提交/批准/撤回；PM 只读管理项目；auditor 只读；member 拒绝；自审、跨企业/跨项目、模块停用、撤权后写入均拒绝。停用模块后历史只读，写入与新建拒绝。
- 拒绝：批准条款未覆盖全部含税额、所选条款不属于该明细/已被使用、本次净额超过已确认履约净额与已结算净额之差、金额被调用方篡改、无已确认履约或本次净额超过"已确认−已结算"、结算日未来、锁期/关期、过期版本、跨企业/项目、重复 request 改输入、bool/float、超 10^12、非 receivable 方向。每个拒绝断言业务/未清/审计/Outbox 无半笔新增。
- 账龄只读：按 as_of 返回 active OpenItem，remaining=gross（本片无核销），分未到期/逾期 1-30/31-60/61-90/90+；质保分区以 release_on 为到期日，未到 release 日不得算逾期；不改预测日、不写余额、不产生收入/成本/现金；日期按 Asia/Shanghai 业务日含端点；无 AgingCase 行。
