# PH-262 · 经营指标与项目工作台读模型首片：只读指标快照 + 项目汇总视图（无写入口）

## 开工资格、价值与范围

PH-258 规划槽消费；来源：1.0 需求 WP-INSIGHT-METRICS/WP-WORKSPACES（legacy PH-182/PH-184）与 WP-RECONCILE 上游。拟依赖 PH-182（经营指标/缺口/复盘草稿，proposed）与 PH-183（到期扫描/幂等待办/停用保留，proposed）；依赖未 done，故 proposed。承接只读读模型首片：按项目/期间刷新并查询**经营指标快照**（收入/成本/毛利/现金/未清/差异计数）与项目工作台汇总（四职责视图的首个只读投影），供 owner/finance/PM/auditor 只读消费；**不做**写入型工作台、通知/待办、导出底稿、项目结项/归档、指标口径变更、账本/收入/成本/现金/未清写入。不解除 PH-182/PH-183/PH-184/PH-186 proposed。

## 行为

- **指标快照刷新**：owner/finance 触发按项目/期间的只读刷新（mode=read_model）：复用既有 owner 具名只读派生收入（管理收入/结算）、成本（costing）、现金（cash）、未清（settlement）与差异计数（PH-181 若已落地）；快照写 `MetricSnapshot`（append-only，org、project_ref、period_id、metric_key、value_cents(SignedCnyCents)、count_value、source_version、refreshed_at、status(active/superseded)）；同 project+period+metric_key 只保留最新 active，历史保留。
- **工作台汇总（只读）**：按用户角色与项目范围返回汇总卡片（我的项目、经营结果、现金与应收概览、待核对差异计数），全部服务端派生；pm 只读其管理项目；member 拒绝；auditor 只读。
- **口径**：指标=确定性派生，不调用模型/文本；金额整数分、SignedCnyCents；未知/缺失指标不显示为 0，而是 null/缺失标签（缺项不得显示完整经营结果）；不改变既有财务口径。
- **幂等/期间/权限**：刷新 request_token 收据、同 token 重放；期间 active、非未来、> locked_through（历史期间刷新只读、不改账）；owner/finance 刷新、auditor/PM 读、member 拒绝；模块停用写拒绝。
- **事件/审计**：刷新写 generic audit `insights.metrics.refreshed`；无业务事实/账本/收入/成本/现金/未清写入；契约目录若无 metrics canonical topic 则不新增/伪造，报告披露。
- 明确不做：工作台写操作/审批、通知/待办、导出、结项归档、指标口径调整、预测/预算、批量/导入。

## 模型与字段

- `MetricSnapshot`（insights 新增，append-only）：org、project_ref、period_id、metric_key(枚举常量)、value_cents(SignedCnyCents, 可 null)、count_value(int, 可 null)、source_version、status(active/superseded)、refreshed_by/refreshed_at；同 project+period+metric_key 至多一条 active。
- `MetricDefinition`：复用契约既有定义（key/label/口径说明/角色可见性），新建表仅在 app 归属确认后按契约落地。
- 迁移：insights 按实际叶节点下一号（新 app 自有 `0001_initial` 起，不抢号）；SQLite/PostgreSQL 双实现触发器禁改删快照；**app 归属已由 PH-270 ADR 0013 决定：新建 `pmo_plugins.insights` 插件（canonical x-owner=insights）；本 spec/tasks 白名单已补 bootstrap 与 settings/urls**。
- 不建可编辑余额/指标重算历史；读模型只追加快照。
