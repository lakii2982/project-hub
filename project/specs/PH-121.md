# PH-121 · 客观覆盖率、财务反例和发布边界

依赖PH120。仅增加CI质量与发布边界，不修改产品核算/权限/表结构。使用固定coverage.py 7.11.0（Apache-2.0）作为CI依赖，产品requirements不改；先实际量测SQLite/PostgreSQL覆盖率与环境跳过，再设有证据的总量底线和新增/修改行门槛，覆盖率不替代业务反例。检查器与门槛取可信BASE，候选不能删配置放行；保留测试数量、失败与skip明细，未知skip阻断或明确按平台列白名单。

增加PostgreSQL多连接真实并发反例，覆盖财务幂等过账/公司锁的关键路径；SQLite仅可明确跳过PG专属测试。已有权限、租户、费率快照、成本现金分离、追加冲销、锁期反例继续全量运行。迁移风险新增时要求有历史演练数据的升级、触发器/完整性与恢复证据，不声称本任务证明所有未来迁移正确。

补齐PR合并结果的客观证据、CodeQL扫描结果阻断与最新重跑核对；不启用未经支持的merge queue。发布workflow改为明确的人工触发与受保护发布环境，代码合并不会触发生产发布；不创建或推送标签、不执行生产部署。兼容现有工程发布脚本，正常发布另有授权和保护。

反例：零测试、未知跳过、覆盖率降低/删除源文件、错误BASE、缺失/损坏覆盖率文件、失败被allow_failure吞掉、候选修改检查器自放行、SQLite冒充并发、重复记账、成本现金混算、已应用迁移修改、标签自动发布均需测试。实际CI对PG和容器/恢复进行证明，本机不具备时不虚构。

状态、白名单、依赖和验收命令以BASE project/tasks.json为准。

依赖激活：本任务完成并正常PR合入时，可仅将已在本规划冻结的PH-122从proposed置ready，保持其spec、allowed_paths、acceptance、risk和其他契约不变。后续实现仍以新BASE为准；不扩大本任务自身范围。
