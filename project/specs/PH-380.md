# PH-380 · 通知中心收件箱实现首片（PH-340/355 后续）

## 开工资格、价值与范围

PH-376 规划槽消费；接续 PH-340（通知中心实现首片）与 PH-355（reminder refs 契约与扫描骨架）。本片实现站内通知/待办收件箱**写侧最小闭环**：扫描/派生 reminder、按成员/角色可见、已读/忽略状态、去重/幂等、权限/停用；**不做**邮件/短信/Webhook/外部推送、自动审批/支付/锁账、客户门户、新 canonical 实体。依赖未 done，故 proposed。

## 行为（冻结 DoR）

- 派生只引用 PH-355/PH-364 的 reminder ref；同来源+kind+recipient 去重，重复扫描不同步重复待办；扫描公司锁/幂等。
- 收件箱每成员只看自己的提醒；owner/finance/auditor 全量、pm 项目摘要、member 本人；撤权/停用后不可访问，停用保留历史队列。
- 已读/忽略最小状态 append-only 或单字段，不写业务事实/不改 owner；扫描失败重试不重复待办、不自动业务动作。
- 无外部渠道/自动动作；浏览器 1440/390 与 PG 交 CI。
- 明确不做：邮件/短信/Webhook、审批/付款/关期/结项动作、客户门户、新 canonical topic/command。

## 模型与字段 / 迁移

- 复用 PH-340 的最小通知/收件箱内部表模式；如需迁移按实际叶在 core 申请，不改已应用迁移。
