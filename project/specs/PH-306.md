## 1. 冻结状态与不变量

- 状态：**FROZEN（契约冻结）**；写侧实现仍为 proposed（PH-313），本片不解除任何 proposed。
- 冻结日期：2026-10-31；BASE：`15cf20c`。
- 预算/ETC 是**项目成本口径**，不是合同收入、不是应收应付、不是现金余额、不是账本余额；不得与收入/现金混加。
- 预算版本、成本事实、ETC 派生值均**不可无迁移重算历史**：已批准预算版本只追加不改写；已过账成本只追加/负值冲销；ETC/缺口为**按请求只读派生**，不持久化为可编辑余额、不回写成本。
- 缺失数据（无批准预算、无成本事实、成本 owner 不可读、科目无法归属）一律返回 `null` + `missing` 标记，**不得显示 0、不得猜测、不得用预算倒挤成本**。

## 2. 预算基线（Budget Baseline）契约

未来实现（拟名 `ProjectBudgetVersion`/`ProjectBudgetLine`；最终表名/字段由 PH-313 在真实 BASE 复核申请；本节冻结语义）：

### 2.1 预算版本

| 语义 | 冻结要求 |
|---|---|
| 组织/项目 | 必填；项目必须属于组织且在有效期内 |
| 期间 | `period` 为 `YYYY-MM`（项目预算按月/项目期）；一个版本可含多科目行；不做隐式跨期摊派 |
| 版本号 | 项目内递增整数 `version`，从 1 开始；append-only |
| 状态机 | `draft → approved → superseded`；`draft` 可改，`approved` 后**金额/科目/期间/生效日全部不可改**；替代只能新建版本并在批准时 supersede 旧版本；`rejected` 终止草稿（保留审计） |
| 生效日 | `effective_from`（业务日期）；批准时冻结；同一项目/期间同一时点只能有一个 `approved` 有效版本（不允许重叠或双有效） |
| 金额 | 每科目行整数分，`>= 0`；科目枚举**冻结为**：`labor`（人工）、`expense`（费用）、`procurement`（采购）、`other`（其他）；未登记科目拒绝 |
| 合计 | 预算总额 = 各科目行整数分之和；不另行存储冗余总额（或存储时以行合计校验一致） |
| 审批链 | 创建人/提交人/批准人/批准时间；批准人与创建人/提交人不得同一人（沿用既有四眼原则）；角色 owner/finance 可写，auditor 只读 |
| 幂等/并发 | 写命令必须 `request_token` 收据 + `expected_version` 乐观并发 + 公司锁；重复 token 返回原结果，不产生第二版本 |
| 审计 | 批准/取代追加 AuditEvent（canonical 写侧实现时定义 topic），不得物理删除历史版本 |
| 只读回看 | `as_of` 取 `approved ∧ effective_from <= as_of` 的最近版本；未找到 = `missing`，不是 0 |

### 2.2 预算行与科目归属

- 每行：`subject`（上述四类）、`amount_cents`、可选 `contract_line_ref`/`cost_owner_ref`（用于后续科目/合同行对比；无引用时仍为项目级预算）。
- 同一版本内 `(subject, contract_line_ref)` 唯一定位一行；同一合同行不得在同类科目重复计预算。
- 预算行不得引用未批准/已终止合同条款；引用合同行时币种固定为 `CNY`（多币种不在本契约）。
- 预算总额可为 0（合法“零预算”），但必须显式记录；0 与 `missing` 语义不同，不得混用。

## 3. ETC（完工尚需成本）派生契约

ETC 是**只读派生值**，由 owner 事实计算，不自动写成本、不写预算、不生成 canonical 事件。

### 3.1 冻结输入

- `incurred_cost_cents`：项目**已发生成本**，仅取成本 owner 的已过账成本事实（`book=cost`、`status=posted`、`origin=current` 的 LedgerPosting 及其来源事件/来源消费；负值冲销行按符号计入）。**不包含**：现金付款、未批准手续费草稿、结算/应收、预算本身、未过账/草稿成本。
- `approved_budget_cents`：按 `as_of` 生效的批准预算总额（见 §2）；无批准预算 = `missing`。
- 可选 `remaining_workload`/`remaining_contract_cost_basis` 仅在实现片显式选择方法时使用；本契约**默认方法**为 `budget_residual_v1`（下述）。

### 3.2 默认口径 `budget_residual_v1`（冻结）

```
ETC = max(0, approved_budget_cents - incurred_cost_cents)
EAC = incurred_cost_cents + ETC
budget_variance = approved_budget_cents - EAC
over_budget = max(0, EAC - approved_budget_cents)
remaining_budget = approved_budget_cents - incurred_cost_cents
```
- 全部为整数分；若 `approved_budget_cents` 或 `incurred_cost_cents` 缺失/不可读 → ETC/EAC/variance 返回 `null` + `missing`（不得按 0 计算）。
- 负值冲销后 `incurred_cost_cents` 可为负；`ETC` 下限 0；`EAC` 可低于已发生成本时说明预算已超支，须以 `over_budget` 展示，不截断为 0。
- 本项目只允许一个默认方法；若实现片新增 `remaining_workload_v1`/`contract_remaining_v1`，必须显式 `etc_method` 参数并作为新契约扩展规划，不得静默切换或双口径混算。

### 3.3 缺口/未分配/超支

- `gap_cents`（缺口）= `over_budget`（EAC 超出批准预算的正数）；预算有剩余时缺口 = 0，同时展示 `remaining_budget`。
- `unallocated_budget_cents` = 批准预算总额 − 各科目行预算合计；正常情况下为 0；若行合计 > 总额则 `issue_code=budget_lines_exceed_total`（不得截断）。
- 科目级对比：仅当成本事实可归属到科目时展示 `subject_actuals`；不可归属时该科目 actual/ETC 为 `missing`，**不得把未归属成本摊入某科目**。v1 只读投影至少保证总额口径；科目级归属属实现片显式范围。
- ETC 与预算对比不得写回成本或预算；超支不自动生成调整凭证。

## 4. 跨 owner 边界（谁拥有什么）

- **costing**：拥有已过账成本事实（`LedgerPosting` book=cost、CostEvent/SourceConsumption 来源链）；提供只读成本聚合接口，不允许预算/ETC 复制成本表或直接改成本。
- **time**：拥有工时/费率与人工成本基础事实；预算/ETC 只通过 costing 已过账成本读取，不直接读工时算钱（避免第二套成本口径）。
- **contracts**：拥有合同行/条款/变更；预算行可引用合同行，但预算不改变合同金额；终止合同不得作为新预算行依据。
- **settlement/management_revenue**：结算/收入是收入侧，不参与 ETC 成本计算；不得用结算额代替成本或缺口。
- **cash**：现金付款≠成本；预算/ETC 不读现金余额，不把付款当已发生成本。
- 预算/ETC owner（未来 `budget` 插件或扩展）只拥有预算版本与只读派生投影；不得成为成本/现金的第二 owner。

## 5. 只读展示与核对口径

- 投影必须展示：批准预算总额、已发生成本、ETC、EAC、缺口/超支、剩余预算、预算版本/生效日、方法标识、`as_of`，以及 `missing`/issue。
- 缺失/不可读时不显示 0；每个派生值附带来源 refs（预算版本 ref、成本聚合 ref/查询口径、方法版本）。
- 只读接口无副作用：无 audit/收据/事件/事实写；不得导出文件（明确不做）。
- 权限：owner/finance 可写预算（未来实现片）；auditor 只读全量；pm 仅其管理项目摘要；member 拒绝；模块停用后历史只读仍可读；未登录 403。只读投影对 pm 仅返回其管理项目，不泄露跨项目成本。
- 展示层不得成为审批/记账依据；预算批准必须走独立写命令与四眼审批，不能由只读页面触发。

## 7. 反例清单（实现片必须拒绝/报 issue）

1. 未批准/缺失预算就按 0 预算计算 ETC 或缺口；
2. 已批准预算版本被原地修改/删除/覆盖，或同项目期间双有效版本；
3. 预算行科目非法、负预算、同一合同行重复预算、引用未批准/终止条款；
4. 成本缺失/owner 不可读时按 0 成本计算 ETC；
5. 把现金付款、结算、收入、未批准手续费、预算本身计入已发生成本；
6. ETC/EAC 写回成本、预算或账本，或自动生成调整/凭证；
7. 用 float/未 ROUND_HALF_UP，或先汇总后取整产生逐笔差异；
8. 未归属成本强行摊入科目以凑平；
9. 无 `request_token`/`expected_version`/公司锁的预算写，或批准人与创建人同一人；
10. 在只读核对/展示中写事实或 canonical 事件；
11. 无迁移重算历史预算/成本/ETC 口径；
12. 跨 org/跨项目引用预算或成本、pm 读越权项目。
