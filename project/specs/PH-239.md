## 行为

- **分类创建**：owner/finance 对同企业、posted 的 CashTransaction 记录唯一有效分类。首片客户端分类集合固定为 receipt（收款）、payment（付款）、advance（预收/预付）、tax（税费）；模型/DB 的 `classification` 枚举额外保留 `transfer`（仅由内部互转编排 PH-245 经内部接口使用，客户端 `cash.classification.record/v1` 仍只接受上述四值，PH-239 服务对客户端 transfer 请求拒绝）；**payroll 明确不在本片**（命令层遇到 payroll 拒绝并提示未支持），工资现金链接与成本账留后续薄片。方向约束：receipt/advance 仅 direction=in；payment/tax 仅 direction=out；advance 还要求存在有效往来方（transaction.counterparty 或最新未反向的 CashPartyMatch 识别结果）。分类只记录归属，不改金额、日期、方向、账户、往来方。
- **唯一有效与追加撤分类**：每个 CashTransaction 至多一条有效分类；有效=存在且未被完整撤销。撤分类采用 append-only `CashClassificationReversal`（status=posted），不改原分类行、不删除；同一原分类只能被撤一次；撤后允许重新分类，原分类与撤分类历史保留。仅 active→reversed 的既有状态字段更新（若模型采用 status 字段）由 DB 触发器放行，其余字段不可改、不可删。
- **账本桥接**：每条有效分类恰一个 core `AccountingEvent`（event_type=`cash.classification`，occurred_on=流水 transaction_date，posting_period=该日期所属月，algorithm_version 固定常量；claim 指向 consumer=`cash`、coverage_key=`bank_effect`、source=原 CashTransaction 稳定身份的 SourceConsumption）+ 恰一条 `LedgerPosting`（book=cash_in 当 direction=in，否则 cash_out；amount_cents=+gross_cents 整数分；scope.kind=`funding_account`、scope.id=账户 id；origin=current）。项目归属不在此片（CashAllocation 另片）；同一银行流水只在账户维度记一次现金，不重复记项目现金。
- **撤分类桥接**：新增冲销 `AccountingEvent`（status=posted、reverses_event_ref=原事件（PH-210 的 core/accounting_event 只读引用）、claim_effect_cents=-原额）与冲销 `LedgerPosting`（amount_cents=-原额、reverses_posting_id=原 posting、book/scope 与原一致）。原事件/原 posting 不改不删。现金账净额口径=Σcash_in − Σcash_out（含冲销负值），不得为银行余额或可用余额。
- **bank_effect 消费**：`SourceConsumption(consumer='cash', coverage_key='bank_effect', source=原 CashTransaction SourceRef)` 与现金流水一一对应且永久保留，撤分类不删除、不释放该 claim；撤后完全撤分类后重新分类复用同一 claim（要求该 claim 现存事件 claim_effect 合计为 0 才能新增），永不得对同一银行流水建第二个 bank_effect claim；**任一时刻同一 bank fact 至多一组有效原始 cash-book posting 组**，完全撤分类后重分类可追加新原始组（口径与 PH-243 冻结句交叉一致）。
- **期间/锁期**：occurred_on 必须等于流水 transaction_date；不得未来、不得 ≤ org.locked_through、所在 AccountingPeriod 必须 active 且未关闭；撤分类允许落在更新后的开放期，但不能改写原期间已关历史。
- **规范事件**：每次有效分类恰一条 `cash.classification_recorded.v1`（source=cash_classification ref、payload changed_refs=[分类 ref]、posting_event_refs=[该 AccountingEvent ref]）；每次撤分类恰一条 `cash.classification_reversed.v1`（source=cash_classification_reversal ref、payload changed_refs=[撤分类 ref]、original_classification_ref=原分类 ref、reversed_payroll_link_refs=[]、posting_event_refs=[冲销 AccountingEvent ref]）。事件与事实、报表、审计同事务。
- **只读**：分类列表/详情（按账户/流水/期间）、流水详情显示有效分类与是否已桥接、账户现金账覆盖 `cash_book_coverage(member, funding_account_id, *, as_of=None)`：from_ledger_cash_in_cents、from_ledger_cash_out_cents、book_net_cents、classified_count、unclassified_posted_count、last_event_at；as_of 含端点；文案必须写“现金账净额（含冲销），非银行余额/可用余额”。owner/finance/auditor 可读，pm/member 拒绝。
- 模块停用后历史只读、写路由 403；不写收入/成本/应收/应付/未清/核销/分类分配/预算预测。

## 模型与字段

- `CashClassification`（cash 新增）：org、cash_transaction FK(related_name='classifications')、classification(receipt/payment/advance/tax/transfer；transfer 仅内部互转编排使用、不开放客户端命令)、status(active/reversed)、version、evidence JSON(≥1)、created_by、created_at。约束：classification 枚举；同一 org+cash_transaction 至多一条非 reversed 分类（部分唯一索引或双实现触发器）；仅 active→reversed 单字段更新放行；不可删。
- `CashClassificationReversal`（cash 新增，append-only）：org、classification FK(related_name='reversals')、cash_transaction FK、status='posted'、reason(1..1000 字)、evidence JSON(≥1)、occurred_on、posting_period、created_by、created_at；Unique(classification) 保证同一原分类只撤一次。
- `CashClassificationReceipt`（cash 新增）：org、request_token 唯一、action(record/reverse)、input_digest、result、created_by、created_at（幂等收据；若评估复用 CashReceipt 可行须在报告说明）。
- 不新增可编辑余额列；AdvanceBalance/PayrollCashLink/CashAllocation 不在本片生成（明确留后续）。
- 迁移：cash 按实际叶节点生成下一号（当前叶 0003_cash_posting_guard，下一号 0004；若 PH-239/240/241 并行落地则以实际叶节点为准）；core 当前叶仍为 0008（PH-243 只改契约/测试，不生成迁移），本任务实现时新建 core 下一号 0009 放宽 `labor_posting_cost_scope` 为 cost↔project/nonproject、cash_in/out↔funding_account/legacy_project；均不抢号、不改已应用迁移；SQLite/PostgreSQL 双实现触发器。

## 服务

- `record_classification(member, *, cash_transaction_id, classification, evidence, occurred_on=None, posting_period=None, request_token, dry_run=True)`：公司锁；fresh 重读角色/企业/流水/期间/既有分类/往来方；校验 posted、同 org、方向与分类匹配、advance 有有效往来方、无有效分类、payroll 拒绝、期间/锁期/未来日；dry_run 零副作用；同 token 同输入重放原结果、改输入冲突；同一事务写分类、generic audit `cash.classification.recorded`、core 桥接事件/posting（经具名接口）、canonical 事件、receipt。
- `reverse_classification(member, *, classification_id, reason, evidence, occurred_on=None, posting_period=None, request_token, expected_version, dry_run=True)`：仅 active；同 org/项目权限；公司锁内 fresh 复核仍 active；条件状态更新（仅 status 字段）；写追加撤分类记录、audit `cash.classification.reversed`、冲销事件/posting、canonical 事件、receipt；重复/并发撤分类只一胜。
- 桥接代码归 core owner：`core/cash_accounting.py`（新）提供 `post_cash_classification(member, classification)` / `reverse_cash_classification(member, reversal)` 具名接口，仅 cash 分类服务调用；不新增公开 HTTP/PAT/MCP 命令通道（`cash.classification.record/v1`、`cash.classification.reverse/v1` 的 x-exposure=authenticated_application_service，首片由私有服务承载，报告须披露）。
- 只读：`classification_snapshot/list`、`cash_book_coverage`。

## 权限与拒绝

- 写：owner/finance；读：owner/finance/auditor；pm/member 拒绝；模块停用写拒绝；撤权后写拒绝。
- 拒绝：未 posted/草稿流水、跨 org/账户、direction 与 classification 不符、advance 无有效往来方、已存在有效分类、payroll 或未支持分类、金额/日期/期间/locked_through/未来日、重复 token 改输入、撤分类非 active/重复撤/并发撤、非整数或 bool/float、调用方传金额/状态/账户/往来方覆盖、调用方传 AccountingEvent/claim/posting/余额/证明。
- 所有拒绝零半笔：分类/撤分类/receipt/generic audit/canonical 事件/AccountingEvent/LedgerPosting/SourceConsumption 计数不变（generic audit 与其非 canonical DomainEvent 除外）。余额/可用证明仅服务端派生（等价 server-only FundingAvailabilityProof），调用方提供的余额或证明一律拒绝。
