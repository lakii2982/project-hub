# PH-252 · 发票登记与逐行分配首片：sales/purchase 发票、行项目与业务来源分配（无红冲/税额抵扣全量）

## 开工资格、价值与范围

PH-247 规划槽消费；来源：1.0 需求（WP-INVOICE）与 PH-233 遗留候选之外的下一业务缺口；invoicing 插件归属为本片前置决策点之一（见“模型与字段”）。拟依赖 PH-150（合同、收费明细与生效方法，proposed）、PH-155（客户结算/未清，proposed）、PH-224（OpenItem，done）与 PH-232（Clearance，done）；依赖未全部 done，故保持 proposed。**契约冻结：`docs/adr/0015-invoice-tax-contract.md`（PH-293）** 已冻结发票实体/状态（私有 draft 不输出 canonical，登记成功即 canonical `active`）、价税分离/税额资格、红冲负值冲销与跨 owner 边界；本片按该 ADR 落地，不产生 `posted`/`reversed` 全量（红冲留后续）。承接 WP-INVOICE 首片：登记 sales/purchase 发票主档与行项目，并把发票行金额分配/核对到已批准业务来源（合同收费明细、结算未清项等），使“业务来源→发票→逐行分配”可核对，**不做**：发票红冲/撤销（`invoicing.invoice.reverse/v1` 留后续）、税额抵扣/进项认证全量、与现金核销直接绑定、批量开票、电子发票、导入、期初、AP/AR 全量、多币种。不解除 PH-157/PH-158/PH-170/171 proposed。

## 行为

- **发票登记**：owner/finance 登记 sales 或 purchase 发票：counterparty（同 org）、invoice_number（org+direction 内唯一，1..80）、invoice_date（非未来、不得 ≤ org.locked_through、期间 active 未关闭）、gross/net/tax 整数分且 gross=net+tax、金额>0 ≤1e12、tax 可 0 但不得为负；发票状态从 draft 到 active（本片只登记，不做红冲）。source/owner/状态由服务端派生，客户端不得传派生字段。
- **行项目**：每张发票 1..n 行，line_no 在发票内唯一且 ≥1；每行 gross/net/tax 整数分且 gross=net+tax；所有行合计必须等于发票头金额（服务端校验）；行不可跨发票复用。
- **逐行分配**：每行可分配 1..n 个业务来源（发票行→业务来源关系，`business_source_ref` 指向已批准合同收费明细/结算/履约来源；owner 只读校验同公司/项目/往来方）；分配金额按行金额拆分，累计不得超过该行 gross/net/tax；同一业务来源在同一方向下累计分配不得超过其可分配额度（只读派生，不新建第二套余额）；超额/跨企业/跨项目/方向不符/来源未批准拒绝。规范事件 `invoicing.recorded.v1`（source=invoice ref、changed_refs=[invoice ref、行 refs]）、`invoicing.lines_allocated.v1`（source=invoice ref/分配 ref、changed_refs=[分配 refs]）。
- **幂等/期间/权限**：request_token 收据；公司锁；同 token 重放原记录、改输入冲突；owner/finance 写、auditor 读、pm/member 拒绝；模块停用写拒绝、历史只读。
- **只读**：发票列表/详情（含行与分配）、按项目的发票/分配覆盖投影（发票金额、已分配、未分配，全部服务端派生）；`invoicing.invoice.get/v1` 等价只读查询通道可后续片暴露。
- 明确不做：红冲/撤销、跨期调整、税额抵扣认证、发票与收款核销绑定、批量、导入、期初、多币种、电子发票、真实税务申报。

## 模型与字段

- `Invoice`（invoicing 新增）：org、direction(sales/purchase)、counterparty FK、invoice_number、invoice_date、gross_cents/net_cents/tax_cents、status(draft/active；canonical 枚举保留 reversed/superseded 本片不产生)、version、created_by、created_at；Unique(org, direction, invoice_number)。
- `InvoiceLine`（invoicing 新增）：invoice FK(related_name='lines')、line_no、gross/net/tax_cents、status、version；Unique(invoice, line_no)；gross=net+tax。
- `InvoiceAllocation`（invoicing 新增，append-only）：invoice_line FK(related_name='allocations')、business_source_ref JSON、gross/net/tax_cents、status(active)、version、created_by、created_at；累计额度由服务派生，不建可编辑余额。
- **前置决策点（已由 PH-259 ADR 决定，见 `docs/adr/0010-invoicing-plugin-ownership.md`）**：采用方案 A——新建 `pmo_plugins.invoicing` 插件 app（manifest 8 字段、requires contracts/settlement、自有迁移链 0001 起、delivery/urls root 单写绑定、canonical 命令首片仅私有服务/浏览器承载）；本 spec/tasks 的 `pmo_plugins/invoicing/*` 精确白名单与该结论一致，不扩大范围。**PH-252 仍保持 proposed**：须 PH-150/PH-155 done 且规划 PR 复核后才可开工；实现 PR 负责创建 app scaffold 与迁移 0001，不在本 spec/ADR 提前落代码。确认后迁移按实际叶节点下一号，不抢号、不改已应用迁移。
- 复用 contracts/settlement/costing 具名只读接口；不改 core 模型。

## 验收与反例

```sh
python scripts/projectctl.py check
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test tests --verbosity 1
python manage.py verify_integrity --json
python manage.py test tests.test_v1_invoice tests.test_v1_invoice_http --verbosity 1
```

- 金样例：sales 发票 10000（net 9000/tax 1000）、两行合计 10000；分配一行 6000 到已批准合同收费明细、一行 4000 到结算来源 → 分配合计=发票合计、覆盖不超来源额度。
- 反例：发票号重复、gross≠net+tax、行合计≠头、负数/bool/float/超1e12、未来/locked/关期、跨 org/项目/往来方、来源未批准/超额/方向不符、重复 token 改输入、分配后修改行/头；每个拒绝断言发票/行/分配/事件/审计无半笔。
- `verify_integrity`：发票头行合计一致、分配引用来源存在且同 org/方向、累计分配不超行与来源额度、每发票/分配恰一条规范事件、无现金/账本/未清直接写入。
- 浏览器 1440/390：发票表单/行编辑/分配/详情/五角色/键盘/无横溢/空错载停用态。

风险 S（金额自洽、来源额度与跨域只读）。PH-323 规划槽重映射依赖为既有已交付能力：PH-214（三模板合同批准/条款）、PH-287（条款快照）、PH-224（结算/未清）、PH-232（核销）、PH-293（ADR 0015 契约冻结）均 done；legacy PH-150/PH-155 的契约边界已由上述能力覆盖。本片据此晋级 ready；不解除 PH-157/PH-158/PH-170/171 proposed。

## 依赖/停用顺序说明（PH-328 规划补充）

本插件按 ADR 0010 `default_enabled=True`、`requires = {contracts, settlement}`。默认启用后，既有测试在停用 `contracts`/`settlement` 前必须先停用本插件（依赖守卫）；这些测试文件（共 16 个，含 PG-only 并发用例 `tests/test_contract_approval.py`/`tests/test_v1_contracts.py`）已由 PH-328 规划槽加入本任务 `allowed_paths`，实现时只做「先停用 invoicing 再停用被依赖模块」的最小顺序同步，**不得改动既有业务断言**。
