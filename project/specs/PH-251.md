# PH-251 · 手续费净额结清、既有成本复用与承担方后续片（ReceiptFeeSettlement / existing_cost_ref / counterparty-borne / 税额）

## 开工资格、价值与范围

PH-247 规划槽消费；PH-244/PH-250 的费用后续薄片第 2 片。拟依赖 PH-250（手续费批准与一次性成本过账，ready 未 done）、PH-224（OpenItem，done）、PH-232（Clearance，done）与 PH-157（应付义务接口，proposed）。依赖未全部 done，故保持 proposed。承接 WP-FEE-TRANSFER 收口：在已批准手续费与净额现金事实上实现 ReceiptFeeSettlement 非现金结清（毛额应付/应收 = 净到账 + 公司承担手续费）及其撤销，支持 `existing_cost_ref` 复用既有已批准成本（禁止重复成本）与 counterparty/unconfirmed 手续费承担方，并落实可抵扣税额口径（TaxQualification）。**不做**：现金账/分类桥接、退款/更正/转账/导入/期初、发票、AP/AR 全量；不解除 PH-157/PH-171 proposed。

## 行为

- **承担方**：`fee_bearer` 扩展 company/counterparty/unconfirmed：仅 company 可成为公司成本（PH-250 成本路径）；counterparty 承担时不记公司成本、不改变应收应付本金；unconfirmed 不得自动计成本/结清，须补证后重判。
- **ReceiptFeeSettlement**：对 posted 净额 incoming CashTransaction、同往来方/项目 receivable OpenItem、已 approved BankCharge 与有效 net clearance 建立非现金结清事实；`applied_cents` 由服务端按“毛额−净额−费用”派生（SignedCnyCents），单笔恰一次；金额自洽校验：gross payer payment evidence、withheld fee、净到账三者一致；不合成毛额现金、不重复净收款、不再扣同一手续费。恰一条 `cash.receipt_fee_settled.v1`（source=receipt_fee_settlement ref）；`settlement.receipt_fee_settlement.reverse/v1` 追加负 applied_cents 的冲销记录并恰一条 `settlement.receipt_fee_settlement_reversed.v1`，只恢复费用结清 AR 范围，不回滚净额现金/成本/银行资金；v1 每原费用来源最多一次完整冲销。
- **existing_cost_ref**：允许把已生效、同公司/项目、已批准费用成本（CostEvent kind=expense 或 legacy 成本 posting，且非工资/分摊/预付/现金账行）绑定到该银行手续费；派生 gross/tax，禁止客户端传毛额；同一原成本与原银行费用身份只允许一个有效绑定，禁止循环/自引用；无充分毛额/税证据（仅净额）拒绝。
- **税额**：tax_cents 为票面税（可 null，未知不推断为 0）；可抵扣税额按既有 TaxQualification 决定成本净额与可抵扣额，不得由手续费金额推断；未知政策阻断成本/结清并提示补证，不静默按 0。
- **依赖前置**：existing_cost_ref 需要 PH-157 形成的已批准费用义务/成本来源；PH-157 未 done 时该分支要么在本片内以具名只读接口占位并明确拒绝（报告披露），要么等 PH-157 done 后再实现——执行时以 BASE 事实为准，不得伪造来源。
- **幂等/期间/权限**：request_token 收据；公司锁、period/lock/future 校验；owner/finance 写、auditor 读、pm/member 拒绝；模块停用写拒绝、历史只读。
- **只读**：ReceiptFeeSettlement 列表/详情、费用结清覆盖投影（毛额/净额/费用/已结清/可结清，全部服务端派生，拒绝调用方余额/证明）、既有成本绑定视图。

## 模型与字段

- `ReceiptFeeSettlement`（settlement 新增）：org、cash_transaction_ref、open_item_ref、bank_charge_ref、net_clearance_ref、applied_cents(SignedCnyCents)、status(active/reversed)、reverses_ref(null/ref)、evidence(≥1)、version、created_by、created_at；Unique 每原 bank charge 至多一条有效结清；append-only，撤销以负 applied_cents 新记录表达。
- `BankCharge` 扩展：existing_cost_ref（cost_event/ledger_posting SourceRef|null）、fee_bearer 写入路径；tax/成本口径按 TaxQualification。
- 复用 `Clearance`/`OpenItem`/`BankCharge`/core AccountingEvent；迁移：settlement/costing 各自按实际叶节点下一号，不抢号、不改已应用迁移。
- 不建可编辑余额或第二份桥表；`receipt-fee-settlement` 关系只读投影。
