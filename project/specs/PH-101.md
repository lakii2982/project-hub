# PH-101 - GitHub需求缺陷桥：对话记录、幂等与追溯

Status, scope and dependencies: project/tasks.json. Source: user request dated 2026-10-23.

## Scope

实现GPT整理的需求/缺陷结构、GitHub客户端抽象及Issue幂等创建/更新；不启动模型/worker，不改ready或自动合并。

## Contract

严格字段schema_version=1,request_id(UUID),repository(owner/name),kind(requirement|bug),revision(正整数),title(1..200),summary,acceptance(字符串列表),source(conversation_ref非私密标识),business_decisions(列表),links(task_id/pr/release)。bug另需observed_version,reproduction,expected,actual,severity(S0..S3)。默认dry_run不联网；execute需本机repo允许列表、可信actor和授权记录，凭据不传worker。客户端固定argv，不用shell。幂等键repo/request_id/action/revision，唯一隐藏标记与payload摘要定位；同revision改内容冲突，旧revision拒绝，多条同标记拒绝；结果不明先查远端，鉴权失败不重试，网络最多一次。只上传白名单摘要，Issue不形成开工许可。

See docs/engineering/ai-native-delivery.md for state, authorization, idempotency and trust boundaries. Product accounting, data schema and personal MCP are outside scope. Shared wiring is integrator-owned.

授权及并发幂等以主协议第6节“PH-101冻结”两小节为精确契约：只接受grant_id引用，由独立Authorizer核对专有授权库、当前GitHub principal、repo/request/action/revision/digest/expiry/revocation；请求不可伪造Grant。私有SQLite两表复合唯一键、每请求跨进程排他锁和dispatching前持久化；响应丢失/重启转unknown，未找到远端结果仍不重发创建，阻塞后续revision。对账分页列举而非依赖搜索索引。主协议的明确unknown规则优先于上文“网络最多一次”的笼统描述。

## Counterexamples

重复投递不重复建Issue；同revision改负载冲突；外部文本/label不触发本机命令；错误repo/actor/未授权写拒绝；超时按unknown规则对账且不盲重发；dry_run不联网；鉴权失败不盲重试。

追加必测：请求伪造合法principal/授权字段仍拒绝；过期/撤销/摘要不符grant拒绝；两个进程并发投递只发送一次create；远端已成功但响应丢失时对账确认；分页暂未找到时保持unknown不重发；dispatching后崩溃/重启不重复创建；更新revision不可并行越序。
