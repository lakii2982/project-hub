# PH-305 · 共享费用分摊（WP-SHARED-COST）首片：跨项目分摊规则与只读摊回核对冻结

## 开工资格、价值与范围

## 行为（冻结 DoR）

- **分摊规则**：共享费用池 → 按明确基准（项目收入/工时/直接成本/固定比例）分摊到项目/成本对象；权重为整数 basis points（合计 10000），末项吸收舍入差（ROUND_HALF_UP）；同一费用池同一期间至多一次有效分摊批次；服务端派生，不接受客户端覆盖金额。
- **只读摊回核对**：核对分摊合计=费用池金额、项目摊回与直接成本不重复、跨期/跨 org/项目范围正确；缺失 null+missing 不显示 0。
- **权限/门控**：owner/finance 写分摊；auditor 只读；pm 仅其项目摘要；member 拒绝；模块停用历史只读。
- **幂等/并发**：request_token 收据；公司锁；同费用池并发分摊一胜；重复分摊拒绝。
- **不写事实**：实现时经既有 costing/账本 owner 命令，不直接改数据；不新增 canonical topic/command 除非另立规划；不改 contract schema。
- **明确不做**：实现/迁移、预算/ETC、多币种、工资/报销、导出。

## 契约冻结（PH-305 冻结正文，写入本 spec、不新增 ADR 文件）

按 Lead 更正的 BASE 口径：PH-305 白名单不含 `docs/adr/`，分摊契约冻结正文落本 spec；不新增 ADR 文件、不改 contract schema。

### A. 共享费用池（pool）定义与边界

- pool 只含**公司级共享成本**：以 `LedgerPosting.scope.kind ∈ {nonproject, unallocated}` 记录的、无法直接归属单一项目的已过账成本事实；当前已交付来源仅非项目/未分配人工成本（PH-217 AllocationRun 的 nonproject/unallocated 部分）；后续公司级费用须由对应 owner 以 nonproject/unallocated scope 记成本（未交付前 null + missing，不显示 0）。
- **明确排除 PH-250 手续费成本**：PH-250 的 `costing.bank_charge.cost` 过账为 `scope.kind='project'`（cost posting 200，scope=project），已计入项目成本与公司总成本；它属**直接项目成本**，不得入池或再分摊（否则重复计成本，违反 T09）。本契约不把已 posted 的 project 成本改挂到 pool；若未来确有公司级手续费，必须由 cash/costing owner 以 nonproject 记账（另立规划/迁移），不得回写历史。
- pool 唯一键冻结：`pool_key = sha256(org_id + "|" + period + "|" + pool_kind + "|" + 规范化有序 source_ref digest)`；同一成本事实在一个 org+period 内**至多属于一个有效 pool 批次**（source membership 互斥，重叠来源由只读核对报 `source_in_multiple_pools`）；`source_refs` 变化只能“冲销旧批次 + 开放期新批次”，不得编辑批次。
- 金额=该 pool 合格来源事实金额合计（posted、未被冲销、同 org、同期间、scope 为 nonproject/unallocated）的派生剩余（扣除已分摊部分）；不得含任何直接项目成本。
- 排除：直接项目成本（含 PH-250 项目手续费）、未批准/草稿成本、现金流水（付款不是成本）、收入、税额、跨 org、已冲销事实（派生 0）；T09 口径：共享池 + 项目成本合计等于公司总成本。

### B. 分摊批次与驱动（append-only）

- costing owner 新增私有批次事实 `SharedCostAllocationBatch`（append-only）：`id/org/period/pool_key/pool_kind/driver/basis_points/input_digest/amount_cents/kind/status/algorithm_version/source_refs/reverses_batch_ref?/reversed_by_ref?`。`kind ∈ {allocation, reversal}`；状态正向批次 `draft → posted`，冲销批次 `draft → posted`；原批次在冲销批次 posted 时 `posted → reversed`（**只变状态位，金额/明细/权重永久不变**）。
- 唯一性（条件唯一约束）：同 org+period+pool_key 至多一条**有效正向**批次，谓词 `kind='allocation' AND status='posted' AND reversed_by_ref IS NULL`；冲销批次（kind=reversal）不受该谓词约束。公司锁串行化；新正向批次只能在旧批次 `reversed` 后提交。
- 纠错：追加 `kind=reversal` 批次，`reverses_batch_ref=原批次`，`amount_cents = −原批次.amount_cents`，明细**逐项精确镜像**原批次（同一目标、同一顺序、取负），**不重新计算**；原批次置 `reversed`；冲销批次本身为终态 posted，不可再次冲销（如需再更正，只能追加新的正向批次，且只能在其后开放期）。
- 驱动 `driver` 枚举冻结：`revenue_cents`（经 management_revenue 只读已确认收入）、`approved_minutes`（经 time/costing 只读已批分钟）、`direct_cost_cents`（经 costing 只读直接成本）、`fixed_weights`（owner/finance 固定权重）。
- 权重：整数 basis points，合计恰 10000；目标=同 org 下 active 项目集合（或显式项目列表）；服务端派生；客户端不得传项目金额/权重结果，只传 driver 与权重输入（fixed_weights 时）。
- 金额与符号（正/负批次分规则）：
  - **正向批次**：`amount_cents = pool_amount_cents ≥ 0`；逐项目 `alloc_i = round_half_up(amount * bp_i / 10000)`，按项目 id 稳定序末项吸收舍入差，保证 `sum(alloc_i) == amount` 且每项 `≥ 0`；零分摊项目保留明细（0 合法），不产生成本事实。
  - **冲销批次**：`amount_cents = −原批次.amount_cents`；明细逐项 `alloc_i = −原批次.alloc_i`，因此每项 `≤ 0` 且 `sum(alloc_i) == amount`；禁止对负批次套用“末项吸收”或重新分摊，符号/目标/顺序必须与原批次一一对应。
- **不重复计成本**：分摊不新增公司总成本；实现须经 costing/账本 owner 的追加冲减+重归属命令（未分配部分 −amount、项目部分 +alloc_i），保留原始来源引用；不得直接改 LedgerPosting/余额，不得用第二套账。

### C. 只读摊回核对

- `shared_cost_reconciliation(member, *, period, pool_kind=None, as_of=None)`：返回 pool_amount、allocated、unallocated、per-project allocations（project_refs/amount/basis_points）、直接成本 base、issues[]、missing[]、truncated；全部服务端派生整数分，缺失 null+missing（不显示 0）。
- issues 冻结：`pool_amount_mismatch`、`over_allocated`、`under_allocated`、`direct_and_shared_overlap`、`source_in_multiple_pools`、`cross_org_reference`、`cross_period_reference`、`unapproved_source`、`reversed_source_used`、`duplicate_active_batch`、`invalid_reversal_mirror`、`basis_points_not_10000`、`rounding_residual`；每条含 code/refs/expected/actual/severity。
- 只读不写；as_of 仅过滤；不执行分摊、不建可编辑余额。

### D. 幂等、并发与期间

- request_token 收据（org+token 唯一、输入 digest）；同 token 重放原结果、改输入冲突；公司锁串行化；重复分摊拒绝；`dry_run=true` 零副作用并返回计划（pool/驱动/权重/明细/校验）。
- 日期/期间：分摊日期与 posting_period 必须同 pool 期间、非未来、> org.locked_through、期间 active 未关闭；关期拒绝。
- **不可无迁移重算历史**：已 posted 批次金额/权重/明细永久保留；纠错=在开放期追加冲销批次（负值、原引用、一对一）再追加新批次；算法/舍入规则以 algorithm_version 记录，不得换标签重算历史（T09/PH-217 口径）。

### E. 权限、门控与 owner 边界

| 操作 | owner | finance | auditor | pm | member |
| --- | --- | --- | --- | --- | --- |
| 建/冲销分摊批次 | ✓ | ✓ | 只读 | 只读其项目摘要 | 拒绝 |
| 摊回核对/批次/明细只读 | ✓ | ✓ | ✓ | 其管理项目摘要 | 拒绝 |

- 模块停用：历史只读（history_read）；写入口守卫。
- **owner 边界**：costing 拥有 pool/批次/成本事实；contracts/management_revenue/time 只读提供驱动（收入/条款/分钟）；cash 不参与、不被写；core 账本/审计只经既有具名 owner 命令；insights/invoicing 只读消费，不复制表、不建第二套账。
