# PH-305 · 共享费用分摊（WP-SHARED-COST）首片：跨项目分摊规则与只读摊回核对冻结

## 开工资格、价值与范围

PH-302 规划槽消费；来源：1.0 WP-SHARED-COST 与 legacy PH-255（共享费用分摊，proposed），并依赖 PH-162（成本归集/项目成本，proposed）。本片冻结共享费用分摊规则（分摊基准/权重/舍入/幂等）与只读摊回核对，供后续实现；**不做**实现、不写成本/账本/现金、不做预算/多币种。依赖已重映射为既有已交付能力：PH-217（月度人工确认/归集分配）、PH-244（手续费草稿事实）、PH-250（手续费批准与一次性成本过账）均 done；共享费用池/分摊写侧实现保持 proposed，契约冻结只需既有 costing 事实与 owner 边界。本片据此晋级 ready。

## 行为（冻结 DoR）

- **分摊规则**：共享费用池 → 按明确基准（项目收入/工时/直接成本/固定比例）分摊到项目/成本对象；权重为整数 basis points（合计 10000），末项吸收舍入差（ROUND_HALF_UP）；同一费用池同一期间至多一次有效分摊批次；服务端派生，不接受客户端覆盖金额。
- **只读摊回核对**：核对分摊合计=费用池金额、项目摊回与直接成本不重复、跨期/跨 org/项目范围正确；缺失 null+missing 不显示 0。
- **权限/门控**：owner/finance 写分摊；auditor 只读；pm 仅其项目摘要；member 拒绝；模块停用历史只读。
- **幂等/并发**：request_token 收据；公司锁；同费用池并发分摊一胜；重复分摊拒绝。
- **不写事实**：实现时经既有 costing/账本 owner 命令，不直接改数据；不新增 canonical topic/command 除非另立规划；不改 contract schema。
- **明确不做**：实现/迁移、预算/ETC、多币种、工资/报销、导出。

## 契约冻结（PH-305 冻结正文，写入本 spec、不新增 ADR 文件）

按 Lead 更正的 BASE 口径：PH-305 白名单不含 `docs/adr/`，分摊契约冻结正文落本 spec；不新增 ADR 文件、不改 contract schema。

### A. 共享费用池（pool）定义与边界

- pool 只含**公司级共享成本**：无法直接归属单一项目的已过账成本事实，来源限既有 owner 只读/事实：非项目或未分配人工成本（PH-217 AllocationRun 的 nonproject/unallocated 部分）、公司级手续费成本（PH-250 过账的一次性费用成本）、后续经规划登记的公司级费用成本（未交付前 null + missing，不显示 0）。
- pool 身份：`org + period + pool_kind + source_refs[]`；金额=合格成本事实之和（已 posted、非冲销、同 org、同期间），减去已直接归属项目/已分摊部分，保证**不重复计入直接成本**。
- 排除：直接项目成本、未批准/草稿成本、现金流水（付款不是成本）、收入、税额、跨 org、已冲销事实（派生 0）；T09 口径：共享池 + 项目成本合计等于公司总成本。

### B. 分摊批次与驱动（append-only）

- costing owner 新增私有批次事实 `SharedCostAllocationBatch`（append-only：id/org/period/pool_key/driver/basis_points/input_digest/amount_cents/status/algorithm_version/source_refs/reversed_by_ref?）；状态 `draft → posted`，纠错只能追加负值冲销批次，禁止编辑/删除已 posted 批次。
- 唯一性：同 org+period+pool_key 至多一条有效（posted 未冲销）批次；新批次必须先冲销旧批次或使用新 pool_key（公司锁 + 条件唯一约束）。
- 驱动 `driver` 枚举冻结：`revenue_cents`（经 management_revenue 只读已确认收入）、`approved_minutes`（经 time/costing 只读已批分钟）、`direct_cost_cents`（经 costing 只读直接成本）、`fixed_weights`（owner/finance 固定权重）。
- 权重：整数 basis points，合计恰 10000；目标=同 org 下 active 项目集合（或显式项目列表）；服务端派生；客户端不得传项目金额/权重结果，只传 driver 与权重输入（fixed_weights 时）。
- 金额：`amount_cents = pool_amount_cents`；逐项目 `alloc_i = round_half_up(amount * bp_i / 10000)`，末项（按项目 id 稳定序最后一项）吸收舍入差，保证 `sum(alloc_i) == amount` 且每项 ≥0、非负；零分摊项目不产生成本事实但保留在批次明细（0 合法）。
- **不重复计成本**：分摊不新增公司总成本；实现须经 costing/账本 owner 的追加冲减+重归属命令（未分配部分 −amount、项目部分 +alloc_i），保留原始来源引用；不得直接改 LedgerPosting/余额，不得用第二套账。

### C. 只读摊回核对

- `shared_cost_reconciliation(member, *, period, pool_kind=None, as_of=None)`：返回 pool_amount、allocated、unallocated、per-project allocations（project_refs/amount/basis_points）、直接成本 base、issues[]、missing[]、truncated；全部服务端派生整数分，缺失 null+missing（不显示 0）。
- issues 冻结：`pool_amount_mismatch`、`over_allocated`、`under_allocated`、`direct_and_shared_overlap`、`cross_org_reference`、`cross_period_reference`、`unapproved_source`、`reversed_source_used`、`duplicate_active_batch`、`basis_points_not_10000`、`rounding_residual`；每条含 code/refs/expected/actual/severity。
- 只读不写；as_of 仅过滤；不执行分摊、不建可编辑余额。

### D. 幂等、并发与期间

- request_token 收据（org+token 唯一、输入 digest）；同 token 重放原结果、改输入冲突；公司锁串行化；重复分摊拒绝；`dry_run=true` 零副作用并返回计划（pool/驱动/权重/明细/校验）。
- 日期/期间：分摊日期与 posting_period 必须同 pool 期间、非未来、> org.locked_through、期间 active 未关闭；关期拒绝。
- **不可无迁移重算历史**：已 posted 批次金额/权重/明细永久保留；纠错=在开放期追加冲销批次（负值、原引用、一对一）再追加新批次；算法/舍入规则以 algorithm_version 记录，不得换标签重算历史（T09/PH-217 口径）。

### E. 权限、门控与 owner 边界

| 操作 | owner | finance | auditor | pm | member |
| --- | --- | --- | --- | --- | --- |
| 建/冲销分摊批次 | ✓ | ✓ | 只读 | 只读其项目摘要 | 拒绝 |
| 摊回核对/批次/明细只读 | ✓ | ✓ | ✓ | 其管理项目摘要 | 拒绝 |

- 模块停用：历史只读（history_read）；写入口守卫。
- **owner 边界**：costing 拥有 pool/批次/成本事实；contracts/management_revenue/time 只读提供驱动（收入/条款/分钟）；cash 不参与、不被写；core 账本/审计只经既有具名 owner 命令；insights/invoicing 只读消费，不复制表、不建第二套账。
