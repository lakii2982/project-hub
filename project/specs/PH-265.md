# PH-265 · 合同变更与终止首片：变更草稿、独立决策、生效版本与终止

## 开工资格、价值与范围

PH-263 规划槽消费；来源：1.0 需求 WP-CHANGE（legacy PH-151 合同变化/终止）与 WP-CONTRACT 后续。依赖 PH-212（客户/供应商/合同草稿）、PH-214（三模板合同首次独立批准与生效）、PH-215（合同 schema 冻结摘要）、PH-224（客户结算/未清/账龄）均 done；结算读取已批准合同条款的具名只读接口 `pmo_plugins/contracts/approval_services.approved_terms_snapshot` 已存在，本片在其内部加终止守卫，不改 settlement 文件。依赖全部 done，PH-263 规划槽据此晋级 ready。

承接合同变更最小闭环：按 canonical `contracts.contract_change.draft.save/v1` 与 `contracts.change.decide/v1` 实现变更草稿（新增范围/缩减范围/价格变更/延期/终止）、独立审批（批准/驳回/撤回），批准时生效为新的合同版本（上一批准版本 superseded）或终止合同；写 `contracts.version_approved.v1` 与 `contracts.change_effective.v1` canonical 事件；终止后结算创建被拒。**不做**：客户门户/待客户确认状态流转（`pending_customer` 本片不产生）、多币种、税额重算、自动重开旧版本、变更对已过账结算的追溯调整、删除历史、账本/现金/收入/未清写、发票。不解除 PH-150/PH-151/PH-155 legacy proposed（能力由本片与既有 done 片逐步覆盖，后续槽评估关闭）。

## 行为（冻结 DoR）

- **变更草稿**：owner/finance 对已生效合同创建 `ContractChange`（contract FK、change_type∈add_scope/reduce_scope/price_change/extension/termination、requested_on、status=draft、deltas 由服务端派生）；`draft_content` 与合同批准草稿同 schema（按 PH-214 三模板冻结结构），必须包含替换后的完整 version 内容；服务端派生 `net_delta_cents/tax_delta_cents/gross_delta_cents`（有符号整数分；线路含税合计差；终止时差额为 0 且不得携带新版本内容）；客户端传 deltas 必须与派生一致，否则拒绝。同合同同一时刻至多一个 draft 变更；同 token 重放原结果、改输入冲突；版本+1。
- **独立决策**：`contracts.change.decide/v1`——owner/finance 对 draft 做 approved/rejected/withdrawn；**创建人不能决策自己的变更**（换一位 owner/finance）；驳回必须填 note；决策后状态不可再改；同 token 重放、并发只一胜。
- **批准生效**：非 termination 变更——同事务创建新 `ContractVersion`（version_no = 现有最大+1、status=approved、approval 记录=决策人、effective_on=requested_on、header_snapshot/draft_content 取变更内容）并把原 approved 版本改 superseded（恰一条 approved）；写 `contracts.version_approved.v1`（source=新 contract_version ref、changed_refs=[新版本, 变更 ref]、posting_event_refs=[]）与恰一条 `contracts.change_effective.v1`（source=contract_change ref、changed_refs=[contract_change ref, 新 contract_version ref]、posting_event_refs=[]）。**termination**：不创建新版本，`Contract.status=terminated`、`terminated_on=requested_on`（新增字段），恰一条 `contracts.change_effective.v1`（source=contract_change、changed_refs=[contract_change, contract]）。
- **变更内容校验**：变更草稿必须通过 PH-214 同源的合同内容校验（三模板字段/线路/付款条款/质保条款/税合计）；线路净/税/含税合计必须等于替换内容派生值；终止不得携带线路变更。
- **终止守卫**：`approved_terms_snapshot(member, line_ref, as_of)` 在合同已终止且 `as_of >= terminated_on` 时拒绝结算读取；既有已过账结算/OpenItem 不改；termination 之后不得再创建变更（除已存在 draft 决策撤回/驳回）。
- **幂等/并发**：`ContractChangeReceipt`（org、request_token 唯一、action∈draft.save/decide、input_digest、result_ref、created_by、created_at）；同 token 重放原结果、输入不一致冲突；并发批准只一胜。
- **明确不做**：客户确认流转（pending_customer）、自动重算历史结算/发票、变更对未清追溯、跨公司、删除/改写历史版本、账本/现金/收入/成本写。

## 模型与字段

- `ContractChange`（contracts 新增 owned_fact，canonical 实体字段对齐）：id、organization FK、contract FK(related_name='changes')、version、status∈draft/pending_customer/approved/rejected/withdrawn（本片只产生 draft/approved/rejected/withdrawn）、created_at、change_type、requested_on、deltas（Signed）、evidence JSON、draft_content JSON、decided_by_member FK null、decided_on null、decision_note（≤500）、create_token/create_digest。约束：append-only（不可删；仅决策状态字段由触发器放行）、同合同最多一个 draft、同 token 唯一。
- `Contract` 新增 `terminated_on`（DateField null）与状态机：active→terminated 单字段更新由触发器放行，其余字段不可改。
- `ContractChangeReceipt`：org、request_token 唯一、action、input_digest、result_ref/result_snapshot、created_by、created_at。
- 迁移：contracts 当前叶 `0002_contractversion_contractline_methodpolicyselection_and_more`，本片新建 `0003_contract_change`（ContractChange/Receipt 表、Contract.terminated_on、SQLite/PostgreSQL 双实现触发器）；不改已应用迁移、不改 core 模型。
- 不新增 canonical topic/command（使用既有 contracts.change_effective.v1 / contracts.version_approved.v1 / contracts.contract_change.draft.save/v1 / contracts.change.decide/v1）。

## 服务

- `save_contract_change_draft(member, *, contract_id, change_type, requested_on, draft_content, evidence, request_token, expected_version=None, dry_run=True)`：公司锁、fresh 重读合同/批准版本/既有 draft；校验 active 合同、change_type、草稿 schema（复用 PH-214 校验器）、deltas 派生一致、终止约束；写 ContractChange + generic audit `contracts.change.draft_saved` + receipt；不写 canonical 事件。
- `decide_contract_change(member, change_id, *, decision, note, request_token, expected_version, dry_run=True)`：仅 draft；创建人≠决策人；owner/finance；approved 走生效事务（新版本/supersede/终止 + 两个 canonical 事件 + audit `contracts.change.effective`）；rejected/withdrawn 只改状态+audit；receipt。
- 只读：`contract_change_list/snapshot`（status/deltas/evidence/decider/生效版本 ref）、合同详情页变更历史。
- 复用：`approved_terms_snapshot` 加终止守卫；不新写结算逻辑。

## 权限与拒绝

- 写：owner/finance；读：owner/finance/auditor、pm 只读其项目合同；member 拒绝；contracts 模块停用写拒绝、读历史保留。
- 拒绝：非 owner/finance、创建人自审、跨 org 合同、非 active 合同、终止后再变更、并发第二个 draft、deltas 与派生不符、终止带线路变更、草稿 schema 非法、expected_version 不符、token 改输入、决策后重决、终止合同再结算（`approved_terms_snapshot`）。
- 拒绝零半笔：Contract/ContractVersion/ContractChange/Receipt/事件/审计无半笔。

## 验收与反例

```sh
python scripts/projectctl.py check
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test tests --verbosity 1
python manage.py verify_integrity --json
python manage.py test tests.test_v1_contract_change tests.test_v1_contract_change_http tests.test_v1_contract_termination --verbosity 1
```

- 金样例：已生效合同起草 price_change（线路含税合计 +10000 分）→ 另一位 owner 批准 → 新 ContractVersion approved、旧版 superseded、恰两条 canonical 事件（changed_refs 口径如上）、合同详情显示新版本；起草 termination → 批准 → Contract.terminated_on 生效，之后 `approved_terms_snapshot` 在 as_of >= terminated_on 拒绝结算。
- 反例：创建人自审、跨 org、非 active、并发第二 draft、deltas 不符、终止带线路、终止后再变更/再结算、重复批准、token 改输入、非法模板/金额（负数越界/float/bool）、决策后重决；逐条断言事实/事件/审计/收据无半笔。
- `verify_integrity` 新增：每 ContractChange 状态合法；approved 变更恰一条 change_effective 事件且 envelope/changed_refs 正确；每合同至多一个 approved 版本、superseded 历史完整；terminated 合同无新版本/新变更；无账本/现金/收入/未清写入。
- 浏览器 1440/390：变更表单/列表/合同详情/决策与驳回表单、空错停用态、键盘焦点。
- PG 并发（CI 双连接）：同一合同并发 draft 只一胜；重复批准只一胜。
