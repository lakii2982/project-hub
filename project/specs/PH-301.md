# PH-301 · 到期扫描与通知中心（WP-NOTIFY）首片：待办/到期提醒只读收件箱与去重

## 开工资格、价值与范围

PH-298 规划槽消费；来源：1.0 WP-NOTIFY 与 legacy PH-179（到期扫描/待办）、PH-183（到期扫描/待办/通知）（均 proposed）。本片实现通知中心最小闭环：按既有 owner 事实派生「待办/到期/异常」提醒（合同到期、结算逾期、未清超期、可计费待确认、导入冲突、权限/令牌到期），写入 append-only 通知收件箱（或只读派生 + 已读状态最小表），支持按用户/角色去重与已读；**不做**邮件/短信/外部推送、不做自动业务动作、不新增 canonical topic/command。依赖未 done，故 proposed。

## 行为（冻结 DoR）

- **提醒派生**：只读扫描既有 owner 事实（合同 terminated/变更 pending、结算 due_date 超期、OpenItem 超期、time pending、onboarding 冲突、AgentToken 到期），生成提醒条目（kind/severity/ref/deeplink/角色范围）；同一事实+kind 去重，不重复轰炸。
- **收件箱**：每成员只读自己的提醒；已读/忽略为最小状态（append-only 或单字段），不写业务事实；owner/finance/auditor/pm 的提醒范围按既有可见性；member 仅自己的待办。
- **权限/门控**：登录成员可读自己的收件箱；跨成员/org 拒绝；模块停用历史只读；无外部推送。
- **幂等/并发**：扫描任务幂等（同事实同 kind 至多一条未读/每日聚合）；公司锁；重复扫描不重复写。
- **明确不做**：邮件/短信/Webhook、自动审批/支付/关期、canonical 新 topic、导出、客户门户、预测。

## 模型与字段 / 迁移

- 如需 `Notification` 最小内部表（org/member/kind/severity/ref/dedupe_key/read_at/created_at），由实现片按实际 BASE 复核并申请；首片优先只读派生 + 已读状态最小表；不改已应用迁移；无 canonical 实体。
