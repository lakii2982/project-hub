# PH-283 · 结算未清/核销/退款覆盖只读核对首片（无写入口、无迁移）

## 开工资格、价值与范围

PH-282 规划槽消费；来源：PH-224（客户结算/未清/账龄）、PH-232（核销首片）、PH-240（退款/银行退回）、PH-230（posted 现金）均 done；PH-241 Offset 仍 in_review，不作为依赖。承接应收覆盖核对缺口：把「OpenItem 剩余 ↔ active Clearance ↔ 退款/退回覆盖 ↔ posted 现金 gross」做成**只读核对清单**，检查超额核销、覆盖为负、重复 active clearance、退款后退回再核销、未清余额与覆盖不一致等问题；**不做**任何写入口、不改核销/未清/现金事实、不新增 canonical 事件/命令、不做迁移、不实现 Offset。

## 行为（冻结 DoR）

- **只读接口**：
  - `open_item_coverage_snapshot(member, *, as_of=None, project_id=None)`：按 OpenItem 返回 gross_cents、Σactive cleared、Σactive offset（未实现显示 0/offset_implemented=false）、refunded/returned coverage、remaining_cents（服务端派生）；分页上限 200。
  - `open_item_coverage_issues(member, *, as_of=None)`：异常清单（remaining<0、cleared>gross、重复 active clearance、clearance 引用现金/未清跨 org、退款/退回后仍可核销超额、账龄 remaining 与派生不一致、cash 覆盖为负），每条含 issue_code/refs/期望与实际。
  - 全部只读派生（复用 settlement/cash 既定具名接口与模型只读），不复制业务表为可编辑余额。
- **口径**：金额整数分；核销/退款/退回/覆盖公式以 PH-232/PH-240 交付与 PH-249 校准后口径为准；`as_of` 仅只读过滤。
- **权限/门控**：owner/finance/auditor 可读全量；pm 仅其管理项目摘要；member 拒绝；settlement/cash 模块停用后只读历史可读；未登录 403。
- **幂等/审计**：只读无副作用、无收据；可选 generic audit `settlement.coverage_snapshot.viewed`（actor/org/as_of）。
- **明确不做**：核销/撤核/退款/退回写、Offset 实现、账本/收入/成本/现金/未清写、迁移、canonical 新 topic、导出文件。

## 模型与字段 / 迁移

- 首片不新增业务表/迁移：按请求只读派生；复用 `OpenItem`/`Clearance`/`Refund`/`BankReturn`/`CashTransaction` 只读；不改已应用迁移（settlement 叶 0005）。
