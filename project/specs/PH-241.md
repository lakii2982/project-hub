# PH-241 · 预收/预付抵扣 Offset 首片：客户预收对未清项的部分抵扣（无撤销、无退款、无账本）

## 开工资格、价值与范围

PH-231/PH-233/PH-238 规划候选；依赖 PH-210（冲销引用/现金消费契约，done）、PH-224（结算未清，done）、PH-230（已过账现金，done）、PH-232（核销首片：Clearance 事实与覆盖只读，ready 未合入）、PH-239（advance 分类与现金事实，ready 未实现）。依赖未全部 done，故本任务保持 proposed；须规划 PR 正常合入可信 BASE、依赖 done 且任务 ready 后才可实现，本文不是开工许可。承接 PH-170 第 2 片的预收部分与 PH-171 的“转用”语义：把客户预收（direction=in 且有效分类 advance 的 posted 现金）按同企业/同往来方抵扣 active 应收 OpenItem，支持部分抵扣、上限=双方余额，余额由服务端派生。**不做**：核销写（复用 PH-232，不重复实现）、退款/银行退回（PH-240）、供应商预付对 AP 的抵扣（应付 OpenItem 未实现，留 PH-157 后续）、现金分类/账本/会计事件/收入/成本/应收应付写、Offset 撤销（契约目录无 offset.reverse，撤销路径留后续契约规划，不自行新增命令/表）、批量、导入、期初、AdvanceBalance canonical 投影。本片不解除 PH-170/171 proposed。

## 行为

- **advance 事实只读**：客户预收事实由 cash 提供具名只读 `posted_advance_for_offset(member, advance_ref)`：返回 posted、同 org、direction=in、有效往来方（transaction.counterparty 或最新未反向 CashPartyMatch 识别结果）、gross_cents、transaction_date、source ref/version；有效分类必须为 advance（PH-239 事实）；未 posted/非 advance/无有效往来方/跨 org 拒绝。settlement 不直接读 cash 表，不写 cash 数据。
- **抵扣创建**：owner/finance 选择同企业、同往来方的 advance 与 active、direction=receivable 的 OpenItem；offset_cents 为正整数分，≤ min(advance 可用额, OpenItem 剩余)；occurred_on 必须等于 advance 现金 transaction_date（与 PH-232 同口径），且不得未来、不得 ≤ org.locked_through、所在 AccountingPeriod 必须 active 未关闭；同一 (advance, open item) 允许多次部分抵扣，累计不得超双方余额；不得抵扣跨项目/跨往来方/非应收未清项。
- **余额口径（服务端派生，不可编辑）**：advance 可用 = advance gross_cents − Σ(该 advance 的 active Offset.offset_cents)；OpenItem 剩余 = gross_cents − Σ(active Cleared 合计) − Σ(active Offset.offset_cents)；两者均不得为负；UI/账龄/详情显示 cleared/offset/remaining。调用方传入的余额/可用证明（等价 server-only FundingAvailabilityProof）一律拒绝。
- **幂等**：复用 settlement 既有 `SettlementReceipt`（org、request_token 唯一、action=`offset.create`、input_digest、result、created_by）；同 token 同输入重放原结果、改输入冲突；累计上限由公司锁 + 新鲜重算余额 + 唯一收据共同保证，重试/重复不产生第二笔超额抵扣。
- **无规范事件披露**：契约目录未登记 offset 事件（无 settlement.offset_created 等），本片不新增、不伪造 canonical topic；只写 generic audit `settlement.offset.created`，并把 `advance-openitem-offset` 关系作为只读投影从 Offset 事实派生（不建第二套桥表）。报告须披露“无 canonical 事件”的契约缺口。
- **无撤销披露**：本片不提供 Offset 撤销；错误抵扣只能通过后续契约规划的撤销/纠错片处理，报告须披露，不得声称已覆盖全部纠错，也不得把 PH-232 的撤核当成 Offset 撤销。
- **只读**：Offset 列表/详情（按项目/未清项/advance）、OpenItem 详情显示 cleared/offset/remaining 与抵扣历史、`open_item_offset_snapshot(member, open_item_id)`、`advance_offset_snapshot(member, advance_ref)`；owner/finance/auditor 可读，PM 只读其管理项目，member 拒绝。
- 模块停用后历史只读、写路由 403；不写收入/成本/现金/会计事件/账本/消费（除既有核销覆盖只读）。

## 模型与字段

- `Offset`（settlement 新增，append-only owned_fact）：org、project FK、open_item FK(related_name='offsets')、advance_cash_transaction_id UUID（跨 owner 无 FK，经 cash 具名只读校验）、advance_ref JSON、offset_cents(>0，≤1e12)、occurred_on、status(active)、version、created_by、created_at。约束/触发器：offset_cents>0；occurred_on 非空；status 固定 active（本片无撤销）；所有字段不可改、记录不可删；org/project 与 OpenItem 一致。
- 不新增可编辑余额列；OpenItem/Clearance 既有字段不改；不新增 OffsetReceipt（复用 SettlementReceipt）。
- 迁移：settlement 下一号（PH-232 为 0003，若其先落则为 0004；按实际叶节点生成，root 单写，不抢号、不改已应用迁移）；SQLite/PostgreSQL 双实现触发器。
- 不新增 AdvanceBalance 投影/表（留后续读片）；余额只由 Offset/Clearance 聚合派生。

## 服务

- `create_offset(member, *, open_item_id, advance_ref, offset_cents, occurred_on=None, request_token, dry_run=True)`：公司锁；fresh 重读角色/企业/项目/OpenItem/advance（经 cash 具名只读）/期间/既有 Offset；校验同 org、同往来方、OpenItem active 且 receivable、advance posted 且 advance 分类有效、金额/上限、期间/锁期/未来日；条件插入（唯一收据 + 余额复核）；写 Offset、generic audit `settlement.offset.created`、SettlementReceipt；dry_run 零副作用。
- `offset_snapshot/list`、`open_item_offset_snapshot`、`advance_offset_snapshot`：只读投影（owner/finance/auditor；PM 项目范围）。
- cash 侧新增具名只读 `posted_advance_for_offset(member, advance_ref)`（整合者 root 单写于 `pmo_plugins/cash/transaction_services.py`），返回必要事实与有效往来方；未 posted/非 advance/跨 org 拒绝。
- 不写 SourceConsumption（Offset 不消费银行流水；bank_effect 消费属 PH-239 分类桥接）；不新增公开 canonical 通道（`settlement.offset.create/v1` 的 x-exposure=internal_cash_orchestration_only，仅私有服务承载，报告披露）。

## 权限与拒绝

- 写：owner/finance（项目可见）；读：owner/finance/auditor、PM 仅管理项目；member 拒绝；cash/settlement 模块停用写拒绝；撤权后写拒绝。
- 拒绝：advance 未 posted/非 advance 分类/跨 org/无有效往来方、OpenItem 非 active/非 receivable/跨项目/往来方不一致、金额≤0/bool/float/超双方余额/超 1e12、未来日/locked_through/关期、重复 token 改输入、Offset 撤销请求（本片不支持）、客户端传余额/证明/状态/方向覆盖。
- 所有拒绝零半笔：Offset/SettlementReceipt/AuditEvent/规范事件（无）/Clearance/OpenItem/SourceConsumption 计数不变（generic audit 与其非 canonical DomainEvent 除外）。
