# PH-249 · PH-232 覆盖公式口径同步：未核销现金余额纳入退款/银行退回

## 开工资格、价值与范围

PH-247 规划槽消费；来源：PH-232 已合入的核销实现与 PH-240 规划披露——核销的“现金未核销余额”在退款/退回实现后应为 `posted gross − Σ(active cleared) − Σ(active refund) − Σ(active bank return)`（Offset 未实现，按扩展位留 0），但 PH-232 冻结 spec 的余额口径仍写 `posted gross − Σ(active cleared)`，两处口径将不一致。本片只同步 spec 文字与验证口径，**不改 PH-232 已实现代码/迁移/测试、不实现退款/退回**。依赖 PH-232（done）与 PH-240（done（a760cf7，PR #139）），PH-248 规划槽复核 DoR 后晋级 ready。

## 精确交付（仅文档）

1. `project/specs/PH-232.md`：
   - 余额口径条目改为：现金未核销余额 = posted gross_cents − Σ(active cleared_cents) − Σ(active refund gross) − Σ(active bank return gross)（退款/退回按 PH-240 定义；Offset 未实现，扩展位为 0，不伪造已有抵扣）；OpenItem 剩余口径不变（gross − Σ(active cleared) − Σ(active offset，未实现为 0)）。**PH-240 实现口径已复核**：`pmo_plugins/settlement/clearance_services` 的核销上限/覆盖 = gross_cents − `_cash_cleared` − `refund_coverage_for_cash(...)['total_cents']`，其中 total_cents 聚合 active 退款+active 银行退回；`clearance_coverage_for_cash` 实际返回 cash_transaction_ref/posted_gross_cents/cleared_cents/offset_cents/total_cents/offset_implemented（不含 refunded 字段）；refunded_cents/returned_cents/total_cents 来自 `refund_coverage_for_cash`。编辑 PH-232 spec 时按这些真实字段写，不另创公式/字段名。
   - 金样例/反例与 verify_integrity 条目补一句：退款/退回发生后的剩余/可退覆盖须由 service 只读接口派生且非负；核销上限仍取双方剩余，不得把已退款/已退回金额再核销。
   - 不改核销创建/撤核/事件/模型/白名单/验收命令的既有语义。
2. `docs/verification.md` 追加本片真实执行条目（projectctl check + 23 项治理测试；纯文字片无运行时）。
3. 若 PH-240 实现时发现覆盖公式另有口径（例如 offset 扩展位命名不同），以 PH-240 report/spec 的实际口径为准并同步差异，不另创第三套公式。
