# PH-280 · 手续费批准/成本与净额只读配对首片（无写入口、无迁移）

## 开工资格、价值与范围

PH-278 规划槽消费；来源：PH-244（BankCharge 草稿事实，done）、PH-250（手续费提交/批准与一次性成本过账，done）、PH-224/PH-232（结算未清/核销，done）、PH-230（posted 现金，done）。承接手续费链路核对缺口：把「BankCharge 草稿/批准状态 ↔ 一次性成本 AccountingEvent/LedgerPosting/claim ↔ 原净额现金 ↔ 退款/退回覆盖」做成**只读配对视图**，供 owner/finance/auditor 检查未批准、批准未过账、成本重复/缺失、净额+费用与毛额不一致等问题；**不做**任何写入口、不改手续费/成本/现金事实、不实现 PH-251（ReceiptFeeSettlement/existing_cost_ref/counterparty）范围、不新增 canonical 事件/命令、不做迁移。

## 行为（冻结 DoR）

- **只读配对接口**：
  - `bank_charge_pairing(member, *, status=None, cash_transaction_id=None, as_of=None)`：返回 BankCharge ref/状态/版本、原始 posted 净额现金 ref/gross、费用 gross/tax、批准人/时间（若有）、关联成本 AccountingEvent ref/金额、cost posting ref/金额、claim coverage_key、退款/退回覆盖合计、配对状态（draft/approved_unposted/posted/paired/partial/异常）。
  - `bank_charge_pairing_issues(member, *, as_of=None)`：异常清单（approved 无成本事件、成本 event 重复、posting 金额≠费用 gross、claim 非唯一/净额不符、费用金额>原现金 gross、同一现金重复 BankCharge、跨 org/项目错位）。
  - 全部只读派生（复用 costing/cash/settlement 既有具名只读接口），不建可编辑余额/第二套账，不持久化快照（首片按请求派生）。
- **口径**：金额整数分；费用成本口径以 PH-250 交付为准（首片按 gross 全额计成本，tax 拆分留 PH-251）；净额+费用 vs 毛额只读展示差额，不自动更正；`as_of` 仅只读过滤。
- **权限/门控**：owner/finance/auditor 可读全量；pm 仅其管理项目摘要；member 拒绝；costing 模块停用后只读历史可读；未登录 403。
- **幂等/审计**：只读接口无副作用、无收据；可选 generic audit `costing.bank_charge_pairing.viewed`（actor/org/as_of），不写业务事实。
- **明确不做**：ReceiptFeeSettlement 净额结清/冲销、existing_cost_ref 复用、counterparty-borne、税额抵扣拆分、任何写/迁移/canonical 新 topic（这些属 PH-251 或后续片）。

## 模型与字段 / 迁移

- 首片**不新增业务表/迁移**：read-only 查询即时派生；不改 costing 已应用迁移（叶 0004）。
