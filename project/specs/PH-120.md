# PH-120 · 可信PR交付契约、独立审查与自动仲裁

来源：用户2026-10-27在当前治理会话中明确要求“准备好改造的前置工作，然后一次性完成所有改造”，授权当前PH120至122的提交、PR和满足现有保护后的合并，不授权生产发布、关闭保护或真实数据操作。前置规划必须先经PR合入，不能用实现PR扩大范围。

复用现有tasks/spec/reports/handoff/DeliveryGate；不建第二套任务、常驻服务或新模型API。新增版本化delivery-policy与交付报告契约；报告保留需求、验收场景、范围、兼容、迁移/回滚、演示环境、实际测试与未验证边界。旧历史报告不批量重写。任务状态/交接元数据的正常收口不一概变成S；修改别人的任务/契约仍为S，不能自行降级。

独立审查复用现有只读review和GitHub Codex Connector：校验官方App及bot数字身份、当前HEAD、最新完整结果；旧结果/伪造身份/无结果/未解决发现阻断。保留复核limitations。所有PR另由可信默认分支上的元数据仲裁器读取PR/CI/审查证据，持写令牌的工作流不执行候选代码。既有8项检查和新增仲裁来源、workflow、event、HEAD/test-merge SHA均核对；不能接受自报pass、过期、skipped/neutral/未知或伪造来源。治理workflow变更只允许BASE契约和此次明确授权的有限任务，独立审查不得省略。

S级额外授权按BASE策略中明确的task/spec契约摘要和来源检查；本轮仅登记PH120/121/122当前指令授权，其他S任务没有授权时阻断，后续用户已明确授权的范围通过独立规划PR登记，不能从Issue/label/候选报告推断。不得伪造人类GitHub批准；个人仓库仍只有一个真实维护者，服务器不能识别人类聊天本身，信任边界如实记录。自动化合入低风险已冻结任务无需逐PR请示；高风险需范围授权及额外独立风险复核。重大业务口径变化才向用户升级。

扩展现有controller/CLI报告和仲裁入口，合并前检查strict、管理员保护、PR要求、完整必需检查、最新BASE/HEAD、mergeable、审查及讨论；合并后记录提交。代码合并、测试部署、生产发布独立。新会话从AGENTS最小入口读长期协议，不纳入另一会话要求仅本地保留的AGENTS重构。

反例：同开发者自评、伪造App评论、旧HEAD审查、最新失败重跑、测试合并SHA变化、远端断网、未解决review、权限/迁移风险缺额外授权、候选改policy自授权、任务元数据降级绕过、workflow伪造相同检查名必须阻断。现有BASE门禁引入前仅作受限bootstrap，不宣称新远端检查已强制，实际启用由PH122验证。

状态、白名单、依赖和验收命令以BASE project/tasks.json为准。

依赖激活：本任务完成并正常PR合入时，可仅将已在本规划冻结的PH-121从proposed置ready，保持其spec、allowed_paths、acceptance、risk和其他契约不变。后续实现仍以新BASE为准；不扩大本任务自身范围。
