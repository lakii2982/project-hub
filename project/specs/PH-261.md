# PH-261 · 预算版本与 ETC 首片：预算版本/行草稿与批准、剩余预计（ETC）发布（不做预测覆盖）

## 开工资格、价值与范围

PH-258 规划槽消费；来源：1.0 需求 WP-BUDGET/WP-ETC（legacy PH-177/PH-178）与 WP-FORECAST 上游。拟依赖 PH-177（预算版本与批准，proposed）、PH-164（暂估转正式/退货折让/支出更正，proposed）、PH-161（人工分配/差额/开放期调整，proposed）；依赖未 done，故 proposed。承接预算与 ETC 最小闭环：创建预算版本与预算行草稿（项目/成本类别/期间）、批准版本；发布剩余预计（ETC：estimate to complete）快照供后续预测/指标消费；**不做**预算重分配/版本切换、预测来源升级、13 周现金预测、覆盖率、调整分录、账本写入、成本/收入确认。不解除 PH-177/PH-178/PH-179 proposed。

## 行为

- **预算版本/行（草稿）**：owner/finance 创建 `BudgetVersion`（org、year/period_range、label、status=draft）与 `BudgetLine`（version、project_ref、cost_category、period_id、amount_cents≥0 ≤1e12）；草稿可增删改（append-only 行版本或 draft 行语义按 report 说明）；金额整数分、禁止 float/bool；期间必须存在且未关闭（草稿允许 open 期间）；同 org+year+label 唯一。
- **批准**：`planning.budget.approve/v1` 语义——owner/finance 批准后版本 approved 且行不可改（append-only 新版本替代）；批准前须行合计与分类汇总一致（服务端校验）；同 token 幂等、并发批准只一胜；批准后不删除历史。
- **ETC 发布**：`planning.etc.publish/v1` 语义——owner/finance 按项目/期间发布 ETC 快照（project_ref、period_id、etc_cents≥0、basis(manual)、version、published_at）；同 project+period 只保留最新 published 快照、历史 append-only；ETC 仅为估计，不写账本/收入/成本/现金。
- **只读**：预算版本/行列表、ETC 快照按项目/期间、版本对比（draft vs approved）；全部服务端派生；auditor 只读、pm 只读其项目 ETC。
- **事件/审计**：预算批准/ETC 发布写 generic audit（`planning.budget.approved`、`planning.etc.published`）；契约目录若无对应 canonical topic 则不新增/伪造，报告披露。
- **权限/期间/幂等**：owner/finance 写；auditor 只读；pm 只读项目；member 拒绝；模块停用写拒绝；request_token 收据；未来/锁期按既有规则拒绝。
- 明确不做：预算重分配/结转、版本回滚、预测来源升级/13 周、覆盖率/资金缺口、调整/红冲、账本/收入/成本/现金/未清写入、批量/导入。

## 模型与字段

- `BudgetVersion`（planning 新增/复用契约实体）：org、year、period_start/end、label、status(draft/approved/superseded)、approved_by/approved_at、version、created_by/created_at；Unique(org, year, label)。
- `BudgetLine`（append-only）：version FK、project_ref、cost_category、period_id、amount_cents(≥0 ≤1e12)、version、created_by/created_at；approved 后禁改。
- `EtcSnapshot`（append-only）：org、project_ref、period_id、etc_cents(≥0 ≤1e12)、basis、status(published/superseded)、version、published_by/published_at；同 project+period 至多一条 published。
- 迁移：planning 按实际叶节点下一号；SQLite/PostgreSQL 双实现触发器；不改 core 模型；**app 归属（新建 planning 插件 vs 复用 management_revenue/既有 app）沿用 PH-150 规划边界，若需新建须先经规划确认 SDK/插件契约，本片不预设 scaffold**。
