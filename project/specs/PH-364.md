## 目标与范围

为 PH-179/PH-183/PH-151/PH-301 的遗留「到期扫描/待办/通知」冻结**只读派生契约**：扫描来源、reminder ref 形状、去重键/幂等、时效、收件人、权限/停用历史、缺失语义、与通知中心边界、证据与验收命令。**不做**通知写侧/队列/推送/外部渠道/已读状态/实现/迁移/表；不新增 canonical topic/command/schema。所有实现由 PH-355 及通知中心后续片按实际 BASE 复核。

## 2. reminder_ref 与待办 item（冻结）

### 2.1 来源 ref

所有来源引用使用既有 `SourceRef` 形状：

```json
{"namespace": "contracts|settlement|cash|time|invoicing|costing|delivery|onboarding|core",
 "kind": "具体 owner 实体 kind", "id": "<uuid>", "version": 1}
```

- `version` 为来源实体不可变版本；来源无 version 字段时固定 `1`；禁止把 `request_id`/调用渠道/展示名当 ref。
- 来源必须同 org；project 来源必须属于调用者可见项目；refs 只读、不可由客户端提交。

### 2.2 待办 item

```json
{
  "reminder_key": "<64位小写sha256>",
  "reminder_ref": {"namespace": "core", "kind": "reminder_ref", "id": "<uuid>", "version": 1},
  "issue_code": "<注册表 §2.3>",
  "severity": "blocker|warning|info",
  "source_ref": {"namespace": "...", "kind": "...", "id": "...", "version": 1},
  "source_owner": "contracts|settlement|cash|time|invoicing|costing|delivery|onboarding|core",
  "project_ref": {"namespace": "core", "kind": "project", "id": "<uuid>", "version": 1},
  "recipient_scope": {"kind": "member|role|project", "id": "<membership uuid|owner|finance|auditor|project uuid>"},
  "refs": [{"namespace": "...", "kind": "...", "id": "...", "version": 1}],
  "title": "脱敏短文案",
  "summary": "脱敏说明；不得含客户敏感原文/金额以外的秘密",
  "due_on": "YYYY-MM-DD",
  "as_of": "YYYY-MM-DD",
  "missing": ["code"],
  "deeplink": "/modules/<owner>/<page>/"
}
```

- `project_ref` 无项目级归属时必须是 `null`，不得伪项目；`due_on` 无到期日必须 `null`，不得猜日期；`missing` 为空数组表示来源完整，缺失必须列 code。
- `reminder_ref.id` = `uuid5(NAMESPACE_URL, "pmo:reminder:" + reminder_key)`；同一 `reminder_key` 在所有扫描/成员解析中稳定。`reminder_ref` 是只读派生引用，不是持久化实体/命令。
- `title/summary` 只做脱敏展示，不构成合同/关期/结项状态声明；只要对应 run/current 状态未提交并读回，文案不得写「已关期/已结项/已重开」。
- 金额/日期如需展示，一律整数分/ISO 日期；null+missing 优先，禁止显示 0 冒充缺失。

### 2.3 issue_code 注册表（冻结）

| issue_code | severity | source owner/kind | 触发（只读） | 收件人 |
| --- | --- | --- | --- | --- |
| `settlement_open_item_overdue` | warning | settlement/open_item | status='active' 且 due_date < as_of 且未清余额 > 0 | role owner/finance；project→pm |
| `settlement_clearance_pending` | info | settlement/clearance | active clearance 尚未覆盖来源要求（只读差额） | role finance/auditor |
| `cash_plan_overdue` | warning | core/cash_plan（现金预测 owner 读接口） | approved/active 且 due_date < as_of，未清/未执行 | role owner/finance；project→pm |
| `contract_change_pending` | warning | contracts/contract_change | status in draft/pending_customer | role owner/finance；project→pm |
| `contract_terminated` | blocker | contracts/contract | status='terminated' 且 terminated_on <= as_of | role owner/finance/auditor；project→pm |
| `billable_confirmation_pending` | warning | time/billable_confirmation | status='draft' 且 confirmed_on <= as_of（仅已批准可计费范围） | role finance；project→pm |
| `tax_qualification_pending` | warning | invoicing/tax_qualification | status='pending' 且来源发票同 org | role finance；project→pm |
| `budget_missing` | warning | costing/project_budget_version | 项目无 approved budget（budget_residual_v1 的 missing，不猜 0） | project→pm；role finance |
| `budget_overrun` | blocker | costing/budget_etc_snapshot | over_budget_cents > 0（只读） | project→pm；role finance |
| `close_precheck_blocker` | blocker | delivery/close precheck | 预检 blocker（只读 issue_code/refs；不执行关期/结项） | role owner/finance/auditor；project→pm |
| `import_conflict_pending` | warning | onboarding/import_conflict | 未解决冲突（PH-274 只读预览） | role finance；project→pm |
| `agent_token_expiring` | info | core/agent_token | 未撤销且 expires_at <= as_of+30d | member self |
| `read_model_missing` | info | core（任意来源） | 来源接口缺失/未交付/不可读，附 missing ref | 按该来源收件人；不得猜 0 |
| `module_disabled_history` | info | core/plugin_state | 模块停用且无历史快照可读 | 按原收件人；只读历史，不派发新提醒 |

- 新增 issue_code 只能由后续规划槽冻结，不得实现片自由扩展；已有 owner issue_code（如 overview 的 `pending_change_approval`）优先复用，本表为其通知化别名时须在实现片映射并保留原 ref。
- severity 固定 blocker > warning > info；`blocker` 只表示需人工处理，不表示系统拒绝/自动阻断。

### 2.4 收件人解析矩阵

| 角色 | 可见范围 | 禁止 |
| --- | --- | --- |
| owner/finance/auditor | 同 org 全部 role/project 提醒（auditor 只读） | 跨 org；member 私有 item |
| pm | 仅 `Project.manager=member` 的 project 提醒 | 公司级 role 提醒、非管理项目、跨 org |
| member | 仅 `recipient_scope.kind='member' and id=self` 的提醒 | role/project 提醒、他人、跨 org |
| 已停用/撤销 membership | 拒绝（403） | 缓存 pending refs、历史越权读取 |
| 模块停用 | 仅有历史快照时只读；无快照返回 `missing=['module_disabled_history']`，不派发新提醒 | 写队列/伪造历史 |

- 收件人按读取时角色重新解析，不缓存授权；撤权后 pending_refs 不可读（PH-183）。
- 通知/提醒不改变任何业务状态；已读/忽略不能代替审批/付款/关期/结项。

## 3. 来源扫描契约

实现片（PH-355）须为每个来源提供只读 adapter：

```
scan_<owner>(member, *, as_of: date, period: str|None, projects: QuerySet|list)
  -> {"reminders": [item], "missing": [str], "issues": [{"issue_code","refs"}]}
```

- adapter 只调用既有 owner 只读服务/模型查询；不得写、不得锁业务、不得调用通知/审批服务。
- adapter 必须显式处理 `None`（无数据/无权限/未实现）：返回 `missing` + `read_model_missing`，不得返回 0 或伪造 ref。
- 项目范围：owner/finance/auditor 全 org；pm 只看 `visible_projects`/manager 项目；member 不扫描 role/project 来源。
- 窗口：`as_of` 为业务日期（Asia/Shanghai，含当日），默认 `timezone.localdate()`，不得未来；`period` 为可选 `YYYY-MM`，只影响来源日期过滤，不改变 posting period；逾期项保持逾期，不移动/复制到本月。
- 到期窗口：`due_date < as_of` 为逾期（warning/blocker）；`due_date == as_of` 为到期日；`due_date <= as_of+30d` 为临期 info。来源无 due_date 返回 null+missing，不猜。
- 同一事实跨期重复出现时，reference 只放原始 due/occurred 日期；不得用扫描日改来源日期。
- 单次输出 refs/item 上限 50；超出标记 `truncated=true` 并保留稳定排序 `(issue_code, due_on, source_ref.namespace, source_ref.kind, source_ref.id)`；分页/游标不在本片范围。

## 4. 去重键、幂等与扫描 envelope

### 4.1 reminder_key（冻结）

```
reminder_key = sha256(canonical_json({
  "organization_id": "<org uuid>",
  "source_ref": {"namespace","kind","id","version"},
  "issue_code": "<issue_code>",
  "recipient_scope": {"kind","id"},
  "source_state": "active"
}))
```

- 必须排除：`as_of`、`generated_at`、请求 token、扫描批次、调用渠道、展示文案、金额/日期格式化差异。
- 同一来源同一 issue_code 同一 recipient_scope 至多一个 `reminder_key`；同一事实重复扫描返回同一 `reminder_key`，不重复计数。
- 来源事实关闭/解除后该 key 不再出现在 active 结果；历史/已读由 PH-301 持久化，不在本片。
- 日报类 info 如需按日聚合，只能由后续实现片另行冻结 `daily_bucket`，不得改 key 定义。

### 4.2 扫描 envelope（冻结）

```json
{
  "contract_version": 1,
  "contract": "core.reminders.read/v1",
  "scan_key": "<64位sha256>",
  "scan_digest": "<64位sha256>",
  "as_of": "YYYY-MM-DD",
  "period": "YYYY-MM|null",
  "role": "owner|finance|auditor|pm|member",
  "generated_at": "<ISO8601>",
  "read_only": true,
  "notifications_sent": 0,
  "reminders": [],
  "missing": [],
  "issues": [],
  "truncated": false
}
```

- `scan_key` = `sha256(canonical_json({"organization_id","as_of","period","role","scope_kind","scope_id","contract_version"}))`；同请求稳定。
- `scan_digest` = 对除 `generated_at` **与 `scan_digest` 自身**外完整 envelope 规范化后的 sha256（避免自引用/循环定义）；同一输入、同一来源事实必须得到相同 digest。`generated_at`、`scan_digest` 均不参与自身计算。
- 重复扫描：同 org/as_of/period/role/scope/source facts 返回相同 `reminders`/`scan_digest`；不写收件箱、不写已读、不发外部消息、不写 audit/outbox（只读）。
- `missing` 排序去重；`issues` 只含 `issue_code/refs/expected/actual`，不得含客户/凭据原文。
- `read_only=true`、`notifications_sent=0` 为冻结常量；任何实现若发送外部消息即违反契约。


### 4.3 scan_digest golden vector（PH-355 必须断言）

将 envelope 去掉 `generated_at` 与 `scan_digest` 后按 UTF-8、`json.dumps(sort_keys=True, separators=(',', ':'), ensure_ascii=False)` 规范化；下列输入必须得到固定 digest：

```json
{"as_of":"2026-10-31","contract":"core.reminders.read/v1","contract_version":1,"issues":[],"missing":[],"notifications_sent":0,"period":null,"read_only":true,"reminders":[],"role":"owner","scan_key":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa","truncated":false}
```

预期 `scan_digest`：

```
7e9894b14caea9a07a28855a35eb44193a74466775f79fdd518d298ed7921a65
```

- PH-355 测试必须复算该向量；实现若使用其他规范化（空格/键序/ensure_ascii）即 fail。
- 该向量不包含 `generated_at`/`scan_digest`；同一输入重复扫描 digest 不变。

来源事实变化的固定对照向量（在上一输入加入一条 `settlement_open_item_overdue` reminder；其余相同）：

```json
{"as_of":"2026-10-31","contract":"core.reminders.read/v1","contract_version":1,"issues":[],"missing":[],"notifications_sent":0,"period":null,"read_only":true,"reminders":[{"as_of":"2026-10-31","deeplink":"/modules/settlement/coverage/","due_on":"2026-10-01","issue_code":"settlement_open_item_overdue","missing":[],"project_ref":{"id":"33333333-3333-5333-8333-333333333333","kind":"project","namespace":"core","version":1},"recipient_scope":{"id":"finance","kind":"role"},"refs":[],"reminder_key":"bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb","reminder_ref":{"id":"11111111-1111-5111-8111-111111111111","kind":"reminder_ref","namespace":"core","version":1},"severity":"warning","source_owner":"settlement","source_ref":{"id":"22222222-2222-5222-8222-222222222222","kind":"open_item","namespace":"settlement","version":1},"summary":"只读派生","title":"未清项逾期"}],"role":"owner","scan_key":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa","truncated":false}
```

预期 `scan_digest`：

```
42d1a265ac5ce9176fd8938233628cd698cb1f117fc63fd0de3f6847ba4036b8
```

- PH-355 必须断言：空列表向量 digest = `7e9894b1…7921a65`；同输入重复扫描同 digest；来源事实变化（如加入上述 reminder）digest 变为 `42d1a265…4036b8`；两者必须不同。
- 任何非 canonical 序列化（空格/键序/ensure_ascii/时间字段参与）即 fail。

## 5. 权限、停用与拒绝路径

- `_reader(member)`：同 org、active membership/user；owner/finance/auditor/pm/member 角色按 §2.4；跨 org/无效上下文/停用账户 → 403 或等价的拒绝，零 item。
- pm 非管理项目、member 读 role/project/他人 item、auditor 写/已读操作、跨 org、无效 as_of/period、未来 as_of → 拒绝，零 notification/业务事实。
- 模块停用：只读历史（如已有快照）或返回 `module_disabled_history` + missing，不写队列、不补发；启用后按当前事实重新派生，不重放历史。
- 撤权后：原 pending refs 对新成员不可读；不得因缓存/去重表泄露；持久化清理由 PH-301 实现。
- 客户端不得提交 `reminder_key/reminder_ref/source_ref/recipient_scope/scan_digest` 作为可信输入；这些均由服务端派生。

## 6. 与 PH-301/314、PH-355 的边界
