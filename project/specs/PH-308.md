# 多币种/汇率契约冻结正文（PH-308，2026-10-31，docs-only）

> 本正文是本片唯一交付物：把 PH-308 的多币种/汇率**契约**冻结在 spec 内，供 PH-321 写侧实现与后续规划引用。
> 本片不新增/修改 `docs/adr/` 文件（BASE `15cf20c` 的 PH-308 精确白名单不含 `docs/adr/`；Lead 裁决改为 spec 内冻结）。
> 本片不写产品代码、路由、模型、迁移、schema、canonical topic/command，不改变任何已交付写路径。

## 1. 冻结状态与不变量

- 状态：**FROZEN（契约冻结）**；写侧实现仍为 proposed（PH-321），本片不解除任何 proposed。
- 冻结日期：2026-10-31；BASE：`15cf20c`。
- 现有金额持久化口径继续有效：**整数分**（1 元 = 100 分），单笔上限 `10^12` 分；计算用 `Decimal`，**禁止 float**；舍入 **ROUND_HALF_UP**。
- 现有单币种事实（合同行/结算/管理收入/现金/成本）在未启用多币种前全部按 `CNY` 记账；本契约不追溯改写这些事实。
- **不可无迁移重算历史**：任何已持久化金额、汇率引用、确认/结算/现金事实不得因新增汇率、修正汇率、功能升级或展示口径变化而被原地重算；历史纠错只能追加负值/新事实，或经显式规划迁移/回填任务并保留原始来源。

## 2. 币种定义（记账本位币 ≠ 功能币种）

- `reporting_currency`（记账本位币）：组织级唯一，冻结为 `CNY`；报表/对账/合计只以记账本位币展示。组织级字段/命令的实现由 PH-321 在真实 BASE 复核后申请，本片不建字段。
- `functional_currency`（功能/交易币种）：合同行、结算、发票、现金事实各自记录其业务币种；实现片每个金额事实必须**同时持久化币种代码**（ISO 4217 三位大写）与**该币种整数分金额**。
- 币种代码校验：ISO 4217 白名单（至少 `CNY`、`USD`、`EUR`、`HKD`、`JPY`；`JPY` 等零小数位币种仍以“分”=最小货币单位整数存储，展示按币种小数位）。未登记币种一律拒绝，不猜测、不按 1:1 处理。
- 合同/结算/发票的功能币种在**创建时冻结**进 terms/confirmation 快照；后续修改只能产生新版本，不得改写已生效快照的币种。

## 3. 汇率快照契约

未来实现的所有汇率事实必须是**只追加、版本化、按业务日期冻结**的 owner 事实（拟名 `FXRateSnapshot`；最终表名/字段名由 PH-321 在真实 BASE 复核并申请，本节冻结语义）：

| 字段语义 | 冻结要求 |
|---|---|
| 组织 | 必填；跨 org 汇率不可复用 |
| 基准币种 / 报价币种 | 必填，ISO 4217；`1 quote` 的基准币金额 = rate |
| 业务日期 | 必填；汇率的生效业务日期（`effective_on`），按业务发生日取用 |
| 汇率值 | 十进制定点，至少 8 位有效、6 位小数（建议 `DecimalField(max_digits=18, decimal_places=8)`）；不得用 float |
| 来源 | 必填（`source`：`manual`/`bank`/`provider` 等受控枚举）；人工维护需记录维护人 |
| 版本/审计 | 版本化、创建人/创建时间、不可更新/删除；修正只能新增版本并在新业务日期/新版本生效 |
| 唯一性 | `(organization, base_currency, quote_currency, effective_on, version)`；同一业务日期同一币种对默认唯一有效版本 |
| 生效规则 | 取业务日期 `on` 的汇率；若当日无快照，只读展示 `missing`，**不得**取最近汇率或 0/1 猜测；显式“回退到最近可用日”只能作为未来独立口径，需规划，不在本契约默认行为内 |
| 未来日期 | 允许登记未来生效汇率，但业务日期尚未到期的汇率不得用于历史换算；服务层按业务日期取用 |
| 跨币种方向 | 仅支持 `base→quote` 方向；反向必须显式登记反向汇率或由实现片定义可逆换算（需避免舍入不对称；默认不自动求倒数） |

汇率快照是**换算边界的唯一授权来源**；任何展示/记账换算都必须携带 `fx_rate_ref`（版本化引用：namespace/kind/id/version），无 ref 的换算金额视为无效，不得写入。

## 4. 换算与舍入边界（冻结口径）

- **边界**：功能币种金额在“进入记账/报表聚合”或“跨币种结算/核销/收入确认”处显式换算一次，形成记账本位币整数分派生值；边界必须记录 `fx_rate_ref`、业务日期、原币种与原币金额。
- **换算公式**：`reporting_cents = ROUND_HALF_UP(original_cents × rate / 10^scale)`，其中 `rate` 为 Decimal，`scale` 为报价币种对基准币的精度（实现片固定 scale 并写入契约常量；默认 rate 已含 8 位小数，按 Decimal 精确乘除后再 ROUND_HALF_UP 到整数分）。
- **舍入点**：**每一笔换算边界只舍入一次**；聚合/合计对已舍入的整数分求和，**不得**先汇总原币再统一换算（避免逐笔 vs 汇总差异）。若未来需要“按组统一舍入”，必须作为新口径经规划并迁移，不可无迁移切换。
- **正负号**：冲销/退款/负值调整沿用原币符号；换算按绝对值乘汇率后恢复符号，ROUND_HALF_UP 对 .5 远离零（Decimal `ROUND_HALF_UP` 语义）。
- **零/极小值**：换算结果为 0 分是合法结果，但仅当原币非 0 且乘积舍入为 0 时可出现；展示必须保留原币金额与汇率 ref，不得用 0 替代缺失。
- **禁止**：客户端传入换算后金额、汇率或“等价 CNY”作为权威值；所有换算由服务端按已冻结汇率快照重算并写 ref。禁止先写记账币金额再补汇率。

## 5. 跨 owner 边界（谁拥有什么）

- **contracts**：拥有合同行/收费模板的功能币种与条款金额；合同行金额以功能币种整数分冻结；条款快照携带币种。
- **settlement**：拥有结算/未清/核销的功能币种金额与结算条款 ref；跨币种结算必须在结算事实中携带 `fx_rate_ref` 与记账币派生金额；不得自行维护第二套汇率。
- **management_revenue**：收入确认以批准条款的币种/金额为准；确认事实携带功能币种与原币净额；记账币展示为只读派生（带 fx ref），不得改写确认历史。
- **cash**：现金事实记录银行账户实际币种与金额；外币现金账户/汇兑损益**不在**本契约实现范围；同币种收付优先按原币核销，跨币种核销需显式 fx ref。
- **costing/time/delivery**：成本与工时以人民币/公司成本口径为主；本契约不引入外币成本；若未来引入，按同一边界规则追加规划。
- 任一 owner 不得复制另一 owner 的余额或汇率表为可编辑副本；跨 owner 只读聚合只引用既有事实与 ref。

## 6. 只读展示与对账口径

- 只读投影必须同时展示：**原币金额 + 币种**、**记账本位币金额（若可换算）**、**fx_rate_ref/来源/业务日期**、**是否 missing**。
- 缺汇率、缺币种、缺 fx ref、跨 org 引用、汇率业务日期晚于业务日期、同一业务日期多有效版本、重复换算等必须产生稳定 `issue_code`（实现片定义并测试），并显示 `missing`/异常，**不得显示 0、不得静默取默认汇率**。
- 对账口径：合同额、已确认收入、已结算、未结清、现金覆盖的记账币合计 = 各边界已舍入整数分之和；原币合计单独展示，不与记账币混加。
- 展示层不得写事实、不得生成 canonical 事件、不得作为审批/记账依据；只读接口无副作用（无 audit/收据/事件/事实写）。
- 权限（沿用产品既有角色）：owner/finance 可维护汇率（未来实现片）；auditor 只读全量；pm 仅其管理项目摘要；member 拒绝；模块停用后历史只读仍可读；未登录 403。

## 7. Canonical / API / 迁移边界

- 本片**不新增** canonical topic/command/query/model/migration/route；写侧实现若需新增 canonical（如 `fx.rate_snapshot.recorded.v1`），由 PH-321 在真实 BASE 走规划与核号，不在本片预占。
- 未来实现片必须：新插件/模型迁移叶按实际 BASE 申请；金额持久化整数分、汇率 Decimal、审计只追加；不修改已应用迁移；不关闭触发器；不直接编辑余额；汇率修正新增版本。
- 历史回填/重算必须是**显式迁移任务**（可审计、可重放、保留原始事实），本片不授权任何隐式重算。

## 8. 反例清单（实现片必须拒绝/报 issue）

1. 缺少汇率即按 0 或 1 换算、静默取最近汇率；
2. 同一 org/币种对/业务日期出现多条有效版本且无版本裁决；
3. 汇率更新/删除历史版本（应新增版本）；
4. 客户端提交换算后金额/汇率作为权威值；
5. 先汇总原币再统一换算（与逐笔边界舍入口径冲突）；
6. 无 `fx_rate_ref` 的跨币种结算/核销/收入事实；
7. 跨 org 复用汇率或跨项目错位引用；
8. 用 float 计算或未 ROUND_HALF_UP；
9. 以展示口径回写/重算历史金额；
10. 在未迁移情况下切换逐笔↔分组舍入口径；
11. 币种代码非法/未登记仍继续处理；
12. 在只读核对中写入事实或 canonical 事件。
