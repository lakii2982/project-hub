# PH-269 · time 可计费确认实现首片：BillableConfirmation 客户确认分钟（新建 time 插件）

## 开工资格、价值与范围

PH-268 规划槽消费；来源：1.0 需求 WP-BILLABLE（legacy PH-154 客户可计费投入确认）与 PH-266 决策产出 `docs/adr/0011-time-plugin-ownership.md`（方案 A：新建 `pmo_plugins.time` 插件，首片只承载 `BillableConfirmation`）及其 DoR 骨架。依赖 PH-025（项目级工时核算，done）、PH-214（三模板合同批准含 confirmed_time，done）、PH-217（月度人工确认/分配，done）、PH-224（客户结算/未清，done）、PH-266（time 归属决策，done）；上述事实均已交付，本片据此登记 ready。PH-153/PH-150 legacy 仍 proposed，本片不改变其状态（工时审批/合同条款能力已由 PH-025/PH-217/PH-214 交付）。

承接客户确认可计费分钟最小闭环：引用已批准 `core.Timesheet` 与有效 `contracts` 条款行（`confirmed_time` 收费模板），记录客户确认分钟、确认日与证据；draft 可保存/修改，`time.billable.confirm/v1` 语义确认后不可改；不写收入/账本/现金/未清/合同模板。**不做**：PH-152/153 工时填报/审批迁移、reversed 撤销路径（契约保留枚举，留后续）、收入确认、发票、结算核销、税额、多币种、批量/导入、附件上传。

## 行为（冻结 DoR）

- **canonical 命令**：`time.billable.confirm/v1`（payload：`timesheet_ref`（kind=timesheet）、`contract_line_ref`（kind=contract_line）、`confirmed_minutes`、`confirmed_on`、`evidence≥1`；顶层 `expected_version`/`dry_run`/`request_token`）。首片只经具名服务与浏览器工作流承载，不接 PAT/MCP/公开 API（ADR 0011 §5）。
- **draft 保存**：owner/finance 创建 draft（引用 timesheet/条款行、分钟、确认日、证据），创建/修改草稿（仅 draft），草稿禁删（append-only；实现已按禁删）；同 token 重放原结果、改输入冲突；版本+1。
- **确认**：`confirm_billable` 仅 owner/finance；draft→confirmed；创建人不能确认自己创建的草稿（独立确认，自审禁止）；`confirmed_on` 不得未来、不得 ≤ `org.locked_through`、所在 `AccountingPeriod` 必须 active 且未关闭；确认后不可改/不物理删除，纠错只追加（reversed 本片不实现）。
- **字段校验**：`confirmed_minutes` 为正整数分钟（禁 bool/float），≤ 对应 timesheet 的已批准分钟；`evidence` 为 1..20 项 JSON（含 kind/reference/sha256/evidence_id 之一，值标量、单条≤500字符）；timesheet 必须同 org、status=approved、未撤销、项目与条款行所属项目一致；条款行必须经 contracts 具名只读接口校验为 approved/唯一批准版本/`confirmed_time` 模板且 confirmed_on≥条款生效日；跨公司/跨项目/未批准/已终止条款拒绝。
- **规范事件**：恰一条 `time.billable_confirmed.v1`（source=confirmation ref、changed_refs=[confirmation ref, timesheet ref, contract_line ref]、posting_event_refs=[]）；draft 保存不写 canonical 事件，只写 generic audit `time.billable.draft_saved`；确认写 generic audit `time.billable.confirmed`（无第二个同 topic 的 generic audit）。
- **幂等/并发**：`BillableConfirmationReceipt`（org、request_token 唯一、action∈draft.save/confirm、input_digest、result_ref、created_by）；同 timesheet+contract_line 至多一条 confirmed（`UniqueConstraint` 条件 status='confirmed'）；公司锁 + 行锁 + 唯一约束保证并发只一胜；同 token 重放原结果、改输入冲突；拒绝零半笔。
- **只读**：列表/详情（状态/分钟/确认日/证据/确认人/项目），PM 只读其项目、auditor 只读、member 拒绝，模块停用写拒绝、历史只读。
- **明确不做**：收入/账本/现金/未清/发票/结算核销写；工时/审批事实复制或迁移；reversed；批量/导入/附件；PAT/MCP/公开 canonical 通道。

## 模型与字段

- `BillableConfirmation`（time 新增 owned_fact，canonical 字段对齐）：id、organization FK、status∈draft/confirmed/reversed（本片只产生 draft/confirmed）、timesheet_ref JSON、timesheet_id UUID（用于唯一校验/索引）、contract_line_ref JSON、contract_line_id UUID、confirmed_minutes PositiveInteger（1..1440 分钟）、confirmed_on Date、evidence JSON≥1、version、created_by_member FK、confirmed_by_member FK null、confirmed_at null、create_token/create_digest、created_at。约束：`UniqueConstraint(organization, timesheet_id, contract_line_id, condition=Q(status='confirmed'), name='time_billable_one_confirmed')`、Unique(org, create_token)、status/分钟边界 Check、禁改删（触发器）。
- `BillableConfirmationReceipt`：org、action、request_token（org 内唯一）、input_digest、result_ref/snapshot、created_by、created_at。
- 迁移：time 新 app 自有 `0001_initial`（不新增/不改 core 0010、contracts 0003、settlement 0005、cash 0006 等已应用迁移）；SQLite/PostgreSQL 双实现触发器（禁删；仅 draft→confirmed 单次状态更新与 draft 内容修改由触发器放行；confirmed 后全字段不可改）。
- 复用只读：core `Timesheet`（经本片新增的 `core.services.approved_timesheet_for_billable` 只读接口）、contracts `approval_services.approved_line_snapshot`（只读）；不复制工时/合同表、不改其模型。

## 服务

- `save_billable_confirmation_draft(member, *, timesheet_ref, contract_line_ref, confirmed_minutes, confirmed_on, evidence, request_token, confirmation_id=None, expected_version=None, dry_run=True)`：公司锁、fresh 重读角色/模块/工时/条款；草稿创建/修改；版本+1；幂等收据；返回草稿投影。
- `confirm_billable(member, confirmation_id, *, expected_version, request_token, dry_run=True)`：draft→confirmed，创建人≠确认人；校验工时/条款/期间/锁期/金额；写 canonical 事件与审计；幂等/并发一胜。
- `list_billable_confirmations(member, *, project_id=None)`、`get_billable_confirmation(member, pk)` 只读投影。
- 浏览器：列表/表单/确认动作；模板 `time/billable_confirmation_list.html`、`time/billable_confirmation_form.html`；`domain_metadata.py` 路由 read/write 元数据；`plugin.py` manifest 恰 8 字段（id=time、requires={contracts}、capabilities=[]）。
- root 单写：`pmo/settings.py`（INSTALLED_APPS/PMO_PLUGIN_MODULES 各加 `pmo_plugins.time`）、`pmo/urls.py`（plugin entry 分支如既有模式需要）、`pmo_plugins/delivery/urls.py`（绑定 time views）、`core/services.py`（仅新增 approved_timesheet_for_billable 只读）；`core/management/commands/verify_integrity.py` 新增本片检查。

## 权限与拒绝

- 写 owner/finance；读 owner/finance/auditor、PM 只读其管理项目、member 拒绝；time 模块停用写拒绝、历史读保留。
- 拒绝：未批准/已撤回/跨 org timesheet、跨项目/跨公司/非 confirmed_time/已终止条款、confirmed_minutes>已批准/≤0/bool/float、未来/locked_through/关期、同 timesheet+条款重复确认、缺证据/证据非法、创建人自审、模块停用、token 改输入、expected_version 不符、`time.timesheet.*` 传本片字段。
- 拒绝零半笔：Confirmation/Receipt/AuditEvent/DomainEvent 无半笔；不得写收入/账本/现金/未清。
