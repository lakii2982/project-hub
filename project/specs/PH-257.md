# PH-257 · 期间预检与对账差异清单只读首片：ReconciliationCase 生成、责任人分派与差额追踪

## 开工资格、价值与范围

PH-248 规划槽消费；来源：1.0 需求 WP-RECONCILE（工资、成本、银行和收入核对，S4）与 WP-CLOSE/WP-INSIGHT-METRICS 上游。拟依赖 PH-180（期间预检、只前移锁定与调整，proposed）与 PH-181（四类核对与差额追踪，proposed）；依赖未 done，故 proposed。承接期间核对最小闭环中的**只读差异清单**：期间预检生成/刷新四类（人工、成本、银行、收入）对账差异的 ReconciliationCase，记录差额与责任人、支持分派/关闭（case.update 仅状态与责任人，不改账），**不做**自动更正、不写账本/现金/未清、不做经营指标/工作台/导出（留 PH-182/184/186 后续片）。不解除 PH-180/PH-181/PH-182/PH-184 proposed。

## 行为

- **预检**：owner/finance 选定会计期间与类别（labor/cost/bank/revenue），服务端重算来源 vs 账本/现金/未清口径的差额（只读复用既有 owner 具名接口）；预检本身零写入（除 generic audit `insights.precheck.run`），返回各类差异计数/金额与缺口清单；期间必须 active 未关闭、非未来、> locked_through。
- **差异清单（ReconciliationCase）**：按差异类别生成/刷新 case（append-only 事实或草稿+状态机；首片采用 append-only case + 状态更新）：kind、period、category、difference_cents（SignedCnyCents，可为正负）、status（open/assigned/resolved/dismissed）、assignee、reason/evidence、version、created_by/created_at；同一期间+类别+来源键至多一条 open case；重复刷新按服务端幂等（同输入返回原 case 集）。
- **分派/关闭**：`insights.reconciliation.case.update/v1` 语义（契约目录存在）——owner/finance 可 assign/resolve/dismiss，必须填 reason/evidence；状态机 open→assigned→resolved/ dismissed（resolved 可 reopen 一次，历史保留）；不改任何业务金额/账本/现金/未清。
- **只读**：差异列表/详情（按期间/类别/责任人/状态）、差异汇总（服务端派生，拒绝调用方余额/证明）；auditor 只读、pm/member 按项目只读（首片可仅 owner/finance/auditor）。
- **事件/审计**：每 case 生成/状态变更写 generic audit `insights.reconciliation.case.created/updated`；契约目录若无对应 canonical topic，本片不新增/伪造 topic（报告披露）。
- 明确不做：自动更正/调整过账、锁定/关期动作、经营指标/完工结果、工作台、通知/待办、导出底稿、批量/导入。

## 模型与字段

- `ReconciliationCase`（insights 新增，append-only）：org、period_id、category（labor/cost/bank/revenue）、source_key、difference_cents（SignedCnyCents，≤1e12）、status（open/assigned/resolved/dismissed）、assignee、reason（1..500）、evidence（≥1）、version、created_by、created_at、updated_at；约束：每 org+period+category+source_key 至多一条非 dismissed 有效 case；仅状态/assignee/reason/evidence 更新由触发器放行，其余不可改、不可删。
- `ReconciliationRun`（insights 新增，草稿/只读）：org、period、categories、result_summary JSON、mode=precheck_only、created_by/created_at；不落金额副本。
- 迁移：insights 按实际叶节点下一号；SQLite/PostgreSQL 双实现触发器。
- **前置决策点（PH-267 ADR 0012 已单列）**：insights 归属**不并入** onboarding 插件；ADR 0012 建议由下一规划槽登记独立归属决策片（新建 insights app vs 既有 app/只读读模型归属）后再冻结实现；本片保持 proposed，待 PH-180/PH-181 done 且独立归属决策完成。
