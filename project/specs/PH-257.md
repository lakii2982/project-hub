# PH-257 · 期间预检与对账差异清单只读首片：ReconciliationCase 生成、责任人分派与差额追踪

## 开工资格、价值与范围

PH-248 规划槽消费；来源：1.0 需求 WP-RECONCILE（工资、成本、银行和收入核对，S4）与 WP-CLOSE/WP-INSIGHT-METRICS 上游。拟依赖 PH-180（期间预检、只前移锁定与调整，proposed）与 PH-181（四类核对与差额追踪，proposed）；依赖未 done，故 proposed。承接期间核对最小闭环中的**只读差异清单**：期间预检生成/刷新四类（人工、成本、银行、收入）对账差异的 ReconciliationCase，记录差额与责任人、支持分派/关闭（case.update 仅状态与责任人，不改账），**不做**自动更正、不写账本/现金/未清、不做经营指标/工作台/导出（留 PH-182/184/186 后续片）。不解除 PH-180/PH-181/PH-182/PH-184 proposed。

## 行为

- **预检**：owner/finance 选定会计期间与类别（labor/cost/bank/revenue），服务端重算来源 vs 账本/现金/未清口径的差额（只读复用既有 owner 具名接口）；预检本身零写入（除 generic audit `insights.precheck.run`），返回各类差异计数/金额与缺口清单；期间必须 active 未关闭、非未来、> locked_through。
- **差异清单（ReconciliationCase，canonical 字段）**：按差异口径生成/刷新 case（append-only owned_fact + 状态更新）：`source_refs`（1..1000 个 SourceRef）、`difference_cents`（SignedCnyCents，可正负）、`owner_member_id`、`resolution_note`（1..1000 或 null）、`status`（canonical 枚举 draft/pending/approved/rejected/superseded/closed），只读 `case_key`/`rule_code`/`coverage_key`/`snapshot_watermark` 由服务端派生；**不写** period/scope/category/assignee/due_date/note 等非 canonical 列（additionalProperties=false，无法通过冻结实体校验）。同一 `case_key`（org+期间+口径+来源键派生）至多一条非 closed/superseded 有效 case；重复刷新按服务端幂等（同输入返回原 case 集）。
- **分派/关闭（canonical 状态映射）**：`insights.reconciliation.case.update/v1` 语义——owner/finance 可把 draft→pending（分派，写 owner_member_id）、pending→approved/rejected（必须写 resolution_note）、approved→closed（结案）；刷新替代旧快照时旧 case 置 superseded；历史只追加，不引入 open/assigned/resolved/dismissed；不改任何业务金额/账本/现金/未清。
- **只读**：差异列表/详情（按期间/类别/责任人/状态）、差异汇总（服务端派生，拒绝调用方余额/证明）；auditor 只读、pm/member 按项目只读（首片可仅 owner/finance/auditor）。
- **事件/审计**：每 case 生成/状态变更写 generic audit `insights.reconciliation.case.created/updated`；契约目录若无对应 canonical topic，本片不新增/伪造 topic（报告披露）。
- 明确不做：自动更正/调整过账、锁定/关期动作、经营指标/完工结果、工作台、通知/待办、导出底稿、批量/导入。

## 模型与字段

- `ReconciliationCase`（canonical 实体，append-only）：org、version、source_refs（1..1000 SourceRef）、difference_cents（SignedCnyCents）、owner_member_id、resolution_note（1..1000 或 null）、status（draft/pending/approved/rejected/superseded/closed）、只读 case_key/rule_code/coverage_key/snapshot_watermark；约束：case_key 唯一（同 org+期间+口径+来源键至多一条非 closed/superseded 有效 case）；append-only，仅 status/owner_member_id/resolution_note 更新由触发器放行，其余不可改、禁删。
- `ReconciliationRun`（insights 新增，草稿/只读）：org、period、categories、result_summary JSON、mode=precheck_only、created_by/created_at；不落金额副本。
- 迁移：insights 按实际叶节点下一号；SQLite/PostgreSQL 双实现触发器。
- **前置决策点（已由 PH-270 ADR 0013 决定）**：采用方案 A——新建 `pmo_plugins.insights` 插件 app（canonical x-owner=insights），承载期间预检/核对差异单/只读读模型；本 spec/tasks 白名单已补 bootstrap（__init__.py/apps.py/plugin.py）与 `pmo/settings.py`、`pmo/urls.py`；本片仍 proposed，待 PH-180/PH-181 done 且规划 PR 复核后才可开工。

```sh
python scripts/projectctl.py check
```

- 金样例：期间内注入 3 条差异（人工 100、银行 -200、收入 0）→ 预检返回 3 类计数/差额；生成 3 条 open case、分派→resolve 后列表状态正确、账本/现金/未清不变。

- `verify_integrity`：case 引用来源（source_refs）存在且同 org、非 closed/superseded 的 case_key 唯一、差额与只读派生一致（若可校验）、status 仅 canonical 枚举、无账本/现金/未清写入。
