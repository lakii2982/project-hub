# PH-240 · 退款与银行退回：原现金覆盖内的真实退款/退回（无分类、无账本、无抵扣）

## 开工资格、价值与范围

PH-231/PH-233/PH-238 规划候选；拟依赖 PH-230（已过账现金，done）与 PH-232（核销首片：posted 现金对未清项的核销覆只读，ready 未合入）。须规划 PR 正常合入可信 BASE、依赖 done 且任务 ready 后才可实现，本文不是开工许可。承接 PH-171 第 1 片：对 posted 现金按原来源覆盖办理退款（refund）与银行退回（bank return），生成真实反方向现金事实与规范事件，不删除旧现金、不自动冲收入/成本/未清。**不做**：预收/预付抵扣 Offset（PH-241）、现金分类与账本桥接（PH-239）、手续费、内部转账、更正、更正链、批量、导入、期初、收入/成本/应收/应付/未清写、核销写（只读复用 PH-232 的核销覆盖）；本片不解除 PH-170/171 proposed。

## 行为

- **可退覆盖（服务端派生）**：可退额 = 原 posted 现金 gross_cents − 该现金 active 核销合计（settlement 具名只读）− 该现金已发生 active 退款合计 − 该现金已发生 active 银行退回合计；任何时刻不得为负，调用方传入的余额/可退额/证明一律拒绝。Offset 尚未实现，接口按“未来扩展 offset 覆盖”注释，不伪造已有抵扣。
- **退款（refund）**：owner/finance 对同企业、posted、direction=in 的 CashTransaction 发起退款（客户/预收退回，现金实际流出）。refund_date 不得未来、不得 ≤ org.locked_through、不得落已关闭期间；gross_cents 为正整数分且 ≤ 可退额；reason 必填（1..500）。服务在同一事务内生成：一条新的 posted CashTransaction（direction=out、funding_account=原账户、external_source_key 由服务器生成且组织+账户内唯一、payee=原有效往来方、evidence 引用原现金）、`Refund` 事实（original_cash_ref、refund_date、gross_cents、reason）、generic audit `cash.refund.recorded`、恰一条 `cash.refunded.v1`（source=refund ref、payload changed_refs=[refund ref, 新现金 ref]、posting_event_refs=[]）、幂等收据。原现金、核销记录不改不删。
- **银行退回（bank return）**：owner/finance 对同企业、posted 的 CashTransaction 登记银行退回，方向取原现金的反向：原 direction=out（付款被退回）→ 新现金 direction=in；原 direction=in（收款被退回）→ 新现金 direction=out。return_date 不得未来/锁期/关期；gross_cents>0 且 ≤ 原现金未退款/未退回剩余（同覆盖口径，核销部分不可退）。生成一条反方向 posted CashTransaction、`BankReturn` 事实（original_cash_ref、return_date、gross_cents）、generic audit `cash.bank_return.recorded`、恰一条 `cash.returned.v1`（source=bank_return ref、payload changed_refs=[bank_return ref, 新现金 ref]、posting_event_refs=[]）、收据。
- **零账本**：本片不写 AccountingEvent/LedgerPosting/收入/成本/应收/应付/未清；退款/退回现金事实的账本桥接由 PH-239 现金分类片后续覆盖（新现金可被其分类/桥接），报告须披露“现金事实已记、账本尚未入账”。
- **幂等**：`request_token` 唯一收据（复用 CashReceipt，action=refund/bank_return；若需新收据表须在报告说明），同 token 同输入重放原结果、改输入冲突；业务不提供“同金额可重复”豁免，重复提交须换 token 并重新通过可退额校验。
- **期间**：新现金 transaction_date 必须等于 refund_date/return_date，且非未来、不 ≤ org.locked_through、所在 AccountingPeriod 为 active 未关闭。
- **只读**：退款/退回列表与详情（按原现金/账户/日期）、`cash_refund_coverage(member, cash_transaction_id)` 返回 posted_gross_cents、cleared_cents、refunded_cents、returned_cents、refundable_cents（全部服务端派生）；owner/finance/auditor 可读，pm/member 拒绝。
- 模块停用后历史只读、写路由 403；不新增公开 canonical 通道（`cash.refund.record/v1`、`cash.return.record/v1` 仅私有服务承载，首片不暴露，报告披露）。

## 模型与字段

- `Refund`（cash 新增，append-only owned_fact）：org、original_cash_transaction FK(related_name='refunds')、refund_cash_transaction FK(related_name='refund_source')、original_cash_ref JSON、refund_date、gross_cents(>0，≤1e12)、reason(1..500)、status(active)、version、created_by、created_at。约束：Unique(org, refund_cash_transaction)；gross>0；不可改、不可删。
- `BankReturn`（cash 新增，append-only owned_fact）：org、original_cash_transaction FK(related_name='bank_returns')、return_cash_transaction FK(related_name='return_source')、original_cash_ref JSON、return_date、gross_cents(>0，≤1e12)、status(active)、version、created_by、created_at。约束：Unique(org, return_cash_transaction)；不可改、不可删。
- 幂等收据：复用 `CashReceipt`（org、request_token 唯一、action、input_digest、result、created_by、created_at），action∈{refund, bank_return}；不新增可编辑余额列。
- 迁移：按实际叶节点生成 cash 下一号（若 PH-239 先落则为其后一号；当前叶 0003_cash_posting_guard，不抢号、不改已应用迁移）；SQLite/PostgreSQL 双实现触发器保证退款/退回记录与阻断性新现金不可改删。

## 服务

- `record_refund(member, *, original_cash_transaction_id, refund_date, gross_cents, reason, request_token, dry_run=True)`：公司锁；fresh 重读角色/企业/原现金/期间/核销覆盖/既有退款退回；校验 posted、direction=in、同 org、金额/上限/日期/期间；dry_run 零副作用；事务内创建 posted 反方向新现金 + Refund + audit + 规范事件 + receipt；同 token 重放、改输入冲突。
- `record_bank_return(member, *, original_cash_transaction_id, return_date, gross_cents, request_token, dry_run=True)`：同上，方向按原现金取反；audit `cash.bank_return.recorded`；规范事件 `cash.returned.v1`。
- 覆盖只读由 settlement 提供具名只读接口 `clearance_coverage_for_cash(member, cash_transaction_ref)`（整合者在 `pmo_plugins/settlement/clearance_services.py` 新增，跨 owner 只读；本片只读消费，不写 settlement）。Offset 覆盖预留同一接口扩展位，不在本片伪造。
- `cash_refund_coverage`、`refund_snapshot/list`、`bank_return_snapshot/list` 只读投影。

## 权限与拒绝

- 写：owner/finance；读：owner/finance/auditor；pm/member 拒绝；模块停用写拒绝；撤权后写拒绝。
- 拒绝：草稿/未 posted 原现金、跨 org/账户、refund 对 direction!=in、bank return 方向非法、超可退额、gross≤0/bool/float/非整数/超 1e12、未来日/locked_through/关期、缺 reason、重复 token 改输入、并发超退、调用方传余额/可退额/证明/新现金 posted 字段或状态。
- 所有拒绝零半笔：新现金/Refund/BankReturn/receipt/generic audit/canonical 事件/核销/未清计数不变（generic audit 与其非 canonical DomainEvent 除外）。

- 金样例：posted 收款 53000、已核销 30000 → refundable=23000；退款 23000 → 新现金 out 23000、refundable=0、原核销不变；再退 1 分拒绝。posted 付款 10000 → 银行退回 10000 → 新现金 in 10000。

- PG 并发（CI 双连接）：同一原现金并发退款各只一胜且可退额不为负；与核销并发时覆盖不超原额。
