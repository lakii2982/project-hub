# PH-264 · 成员账号生命周期与项目范围首片：角色/项目范围变更、停用与令牌即时撤销

## 开工资格、价值与范围

PH-263 规划槽消费；来源：1.0 需求 WP-IDENTITY（legacy PH-143/PH-144 的账号生命周期、授权与敏感字段薄片）与 WP-PEOPLE（PH-145 员工/账号绑定的既有实现 PH-024）。依赖 PH-024（基础资料唯一维护服务与权限边界，done：员工档案、账号绑定、员工停用与费率快照已在 `core/masterdata.py` 落地）。依赖全部 done，PH-263 规划槽据此晋级 ready；实现仍须规划 PR 正常合入可信 BASE 且任务 ready 后才可开工。

承接成员账号最小生命周期闭环：按 canonical `identity.membership.change/v1` 语义实现具名服务与浏览器工作流——变更公司内成员角色、设置可见项目范围（`project_scope`）、停用/恢复成员；停用时**立即撤销该成员个人 Agent 令牌**、要求先完成员工绑定停用与项目经理交接；每次变更写审计。**不做**：新建账号/邀请、密码与 MFA、敏感字段（个人费率/工资）新展示、跨公司迁移、角色权限矩阵扩展、AgentToken 新能力、canonical 事件新 topic。不解除 PH-143/PH-144/PH-145 proposed；本片只覆盖其成员生命周期子集。

## 行为（冻结 DoR）

- **canonical 命令**：`identity.membership.change/v1`（payload：`membership_id`、`role`∈owner/pm/finance/member/auditor、`project_scope`（project id 数组）、可选 `active`；顶层 `expected_version`/`dry_run`/`request_id`/`idempotency_key`）。本片只实现具名服务与浏览器承载（`x-exposure=authenticated_application_service`），不新增 PAT/MCP/公开 API 通道；报告披露。
- **写入前置**：owner 写；公司锁后 fresh 重读 member/organization/项目/员工/令牌；`expected_version` 不匹配拒绝；每成功变更 `Membership.version+1`；同 `request_token` 重放原结果、改输入冲突；`dry_run=True` 零副作用。
- **角色变更**：owner 可把成员设为 owner/pm/finance/member/auditor；不可把最后一个 active owner 降级/停用（服务端计数校验）；不可自降级最后一个 owner；角色变更不清空历史。
- **项目范围**：`project_scope` 是可见项目 id 集合，服务端以 `ProjectMember` 增删差集维护；项目必须同公司；重复 id 拒绝；owner/finance/auditor 必须为空数组（公司级角色不接受项目范围）；pm/member 允许为空（表示仅公司级可见范围为空，不等于全公司）。
- **停用（`active=false`）**：必须满足——不是最后一个 active owner、不是操作者本人、名下无 active Employee 绑定（先用 PH-024 员工停用/解绑）、不是任何 active 项目的 manager（先由项目主档改派 manager）；满足后同事务：`Membership.active=False`、撤销该成员全部未撤销 `AgentToken`（`revoked_at` 立即生效）、删除其 `ProjectMember` 行（项目范围归零）、写审计。停用后该成员所有写/读入口按既有 `require_member` 立即 403。
- **恢复（`active=true`）**：owner 可恢复此前停用成员，版本+1；项目范围需显式重新设置（不自动恢复历史范围）；不自动恢复 AgentToken。
- **审计与敏感字段**：写 generic audit `identity.membership.changed`（含 changed_fields/role/active/project_scope_ids/request_token，不含邮箱、密码、令牌明文、费率）；审计链保持 append-only。既有个人费率仅财务可见的脱敏不变；本片不扩大敏感字段展示。
- **明确不做**：邀请/注册/邮件、密码/MFA、跨公司成员迁移、删除账号、角色权限矩阵扩展、canonical 事件 topic、账本/金额/期间写。

## 模型与字段

- 复用 `core.Membership`（organization、user、role、active）；**新增** `version = PositiveIntegerField(default=1)`（canonical Membership 必备乐观版本），不做账号克隆；保留既有唯一约束 `(organization,user)`。
- 复用 `core.ProjectMember`（项目范围关系，服务端增删差集，不新建表）、`core.Employee`（绑定与 active 校验）、`core.AgentToken` 既有字段 `revoked_at`（只撤销，不改模型）。
- 迁移：core 当前叶 `0009_relax_ledger_posting_scope`，本片新建下一号 `0010_membership_version`（仅新增 version 列 + 回填 1；SQLite/PostgreSQL 双实现；不动已应用迁移；不新增触发器）。
- 不新增 business 表；不写 `SourceConsumption`/`AccountingEvent`/`LedgerPosting`；`Membership.version` 是唯一结构变更。

## 服务

- `change_membership(member, *, membership_id, role, project_scope, active=None, expected_version=None, request_token, dry_run=True)`：公司锁；fresh 重读操作者角色/目标成员/员工绑定/项目管理/令牌/项目集合；校验 owner、最后 owner、自停用、员工绑定、manager 交接、项目同公司/去重/角色范围；事务内更新 Membership.version/role/active、ProjectMember 差集、撤销令牌、audit；返回成员投影（id/role/active/version/project_scope_ids）。
- `membership_snapshot(member, membership_id)`：只读投影（含 role/active/version/project_scope ids；owner/finance/auditor 可读，pm/member 只能读自己）。
- UI：`templates/settings.html` 增加成员表（角色、状态、项目范围、最近变更）与 owner 可见的角色/项目范围/停用/恢复表单；错误信息可读；停用前提示先处理员工绑定与项目经理交接。

## 权限与拒绝

- 写：owner；finance 可读全部成员、不可写；pm/member 仅读自己；auditor 只读。
- 拒绝：非 owner 写、跨 org member、最后 active owner 降级/停用、自停用、名下 active Employee、名下 active 项目经理、项目 id 跨 org/重复、owner-finance-auditor 带非空 project_scope、停用成员再写、expected_version 不符、同 token 改输入、bool/float 型 version、未知字段、客户端传审计/令牌明文。
- 所有拒绝零半笔：Membership/ProjectMember/AgentToken/AuditEvent 计数与值不变（generic audit 及其非 canonical outbox 行除外）。
