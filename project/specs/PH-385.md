# PH-385 · 通知中心调度、同步诊断与归档生命周期

## 开工资格与范围

PH-411 重基线：PH-340 已完成当前成员收件箱、去重、已读/忽略、权限与 PG 并发；PH-380 因重复取消。本片只补调度/有限重试、append-only 同步诊断和归档，不重复实现收件箱，不做邮件/短信/Webhook、自动业务动作或 canonical 实体。

## 冻结行为

- 新增非 canonical `NotificationSyncRun`：organization、member、scan_key（失败可 null）、status、succeeded/failed、attempt_count、error_code、started_at/completed_at。每次尝试追加一行，不覆盖历史；错误只存类型代码，不存客户原文、凭据或堆栈。
- `sync_notifications` 和 `scan_due --sync` 使用同一运行记录；成功/失败均可诊断，重试不重复 Notification。命令支持有界 `--retries` 与可选 `--watch/--interval`；watch 是前台运维命令，不宣称系统级常驻调度器。
- `Notification` 新增 `archived_at`；本人可归档，重复归档幂等。默认列表排除 archived，`archived/all` 筛选可见。读取与状态修改继续共用当前角色/项目范围，auditor 只读。
- 通知页展示同步运行状态、次数、错误代码和时间；不得把无持久队列说成有队列。无外部发送，运行诊断不改业务事实。
- 0013 由整合者按当前叶生成，不改 0011/0012；SyncRun 同样强制 member/organization 匹配。
