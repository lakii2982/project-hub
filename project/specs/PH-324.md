# PH-324 · canonical 币种字段/类型扩展（契约物化）

- 里程碑：v1.0.0 / 批次 B（写侧前置，契约）
- 风险：S
- 依赖：PH-308（多币种/汇率契约冻结，含 §9A）
- 状态：ready（PH-323 晋级）

## 目标

把 PH-308 §9A 冻结的多币种契约**物化到 canonical 契约文件**，为 PH-321 实现提供真实 schema。仅契约与治理记录变更，不实现业务写侧、不改已应用迁移。

## 行为 / 契约

1. `docs/v1.0-development/contracts/entities.schema.json`：目标实体增加币种/原币字段——Invoice、InvoiceLine、InvoiceAllocation、InvoiceReversal、ContractLine、Settlement、OpenItem、RevenueRecognition、CashTransaction（至少 `currency` ISO 4217 + 保留既有 `*CnyCents` 记账本位币字段；原币金额用 `original_*_cents`；Money/CurrencyCode 定义按 contract-bundle）。`BankCharge` 的模型/迁移不在本任务白名单（costing 插件），其币种字段由 PH-321/后续 costing 切片承接，PH-324 不在 canonical 中提前声明未物化字段。
2. `contract-bundle.schema.json`：Money/CurrencyCode 类型（ISO 4217 校验、`amount_cents` 整数 + `currency`）。
3. 按需同步 `write-dtos.schema.json`、`commands.schema.json`、`relationships.json`、`source-registry.json`；`validate_contracts.py` 必须通过。
4. 兼容策略：旧 `*CnyCents` 保留（CNY 回填/双读）；非 CNY 写入在 PH-321 实现前拒绝（契约注明）；历史重算须显式迁移回填。
5. `docs/v1.0-development/promotion-draft/extension-freeze.json` 的 `canonical_sha256` 仅按被修改文件同步更新（合法扩展步骤）。

## 反例

- 只新增旁路 schema 而不修改 entities（契约未物化）→ 拒绝。
- 修改 canonical 但不更新 extension-freeze 哈希 → validate_contracts 失败 → 拒绝。
- 新增非整数分/浮点金额、或删除旧 `*CnyCents`（破坏兼容）→ 拒绝。
