# PH-230 · 现金过账与账户可用覆盖：草稿→posted、规范事件与只读覆盖（无账本桥接）

## 开工资格、价值与范围

PH-229 规划候选；拟依赖 PH-214、PH-219、PH-222、PH-224、PH-228（均 done）。须规划 PR 正常合入可信 BASE、依赖 done 且任务 ready 后才可实现，本文不是开工许可。承接 PH-169 第 2 片的最小可用部分：把 PH-228 的银行流水草稿过账为不可变现金事实（status draft→posted）、写一条登记 canonical 事件 `cash.transaction_recorded.v1`、提供只读账户覆盖，为 PH-170 核销/PH-171 退款提供“已过账且不可改”的现金来源。**本片不写 AccountingEvent/LedgerPosting/LedgerEntry、不做分类/分配/核销/抵扣/退款/更正/转账/导入/期初**；现金账桥接与分类仍为后续片（PH-231 优先），本片不解除 PH-169/170/171 的 proposed 状态。

## 行为

- **过账**：owner/finance 对 draft CashTransaction 执行 record；本片不对外暴露 canonical cash.transaction.record/v1 命令通道（其 payload 是完整银行事实、无 transaction_id，避免客户端重传事实制造第二份流水）；仅私有服务按已登记草稿 id 过账；公司锁内 fresh 重读公司/账户/流水/期间；事务日期不得未来、不得 ≤ org.locked_through、不得落已关闭期间；draft→posted 一次性条件更新（version+status 条件），仅胜者写规范事件与收据；已 posted 不可再次过账、不可改、不可删。
- **audit 命名**：generic audit action 冻结为 cash.cash_transaction.posted（audit 按既有机制生成非 canonical DomainEvent），与 canonical topic cash.transaction_recorded.v1 区分。
- **规范事件**：每个 posted 流水恰一条 `cash.transaction_recorded.v1` DomainEvent：source=cash_transaction ref（namespace=cash/kind=cash_transaction/id/version），payload changed_refs=[该 ref]、posting_event_refs=[]（本片无账本过账）；事件与状态/审计/收据同事务；重复调用不产生第二条事件。
- **只读覆盖**：`cash_account_coverage(member, funding_account_id, *, as_of=None)` 返回私有估算字段 posted_in_cents、posted_out_cents、posted_net_estimate_cents、cleared_cents=0（本片无核销）、available_estimate_cents=posted_net_estimate_cents、posted_count、draft_count；as_of 含端点；仅 owner/finance/auditor；零写入；不暴露 canonical cash.account_coverage.get/v1（其 account_refs/known_available_cents/coverage_complete/missing_coverage 形状留待分类/核销片）。UI 文案必须写“已过账净额估算，非现金余额/可用余额”。
- **只读投影**：流水 snapshot/list 增加 status/status_display、can_post、posted 时间取 audit/事件时间；不新增 posted_at 字段；账户列表显示私有覆盖估算小计（posted net estimate），文案标注非现金余额。
- 模块停用后历史只读、写路由 403；不写收入/成本/应收/应付/未清/消费。

## 模型与迁移

- 复用 CashTransaction.status(draft/posted) 与 version；不新增业务字段。
- 迁移 0003_cash_posting_guard：收紧 PostgreSQL/SQLite 触发器——UPDATE 仅允许 OLD.status='draft'；NEW.status ∈ {draft,posted}；当 NEW.status='posted' 时要求旧为 draft 且 status/version 外字段不变；posted 后 UPDATE/DELETE 拒绝；DELETE 仍全拒。
- 不新增表；不修改已应用迁移。

## 服务与状态机

- `record_cash_transaction(member, transaction_id, *, request_token, occurred_on=None, posting_period=None, expected_version, dry_run=True)`：occurred_on 必须等于流水 transaction_date（或省略）；posting_period 必须等于该日期所属月（或省略）；布尔/字符串类型严格；dry_run 零副作用；同 token 同输入重放原结果、改输入冲突；撤权/停用/跨企业/版本过期/重复过账拒绝且零半笔。
- `cash_account_coverage(member, funding_account_id, *, as_of=None)`：只读；账户同 org；跨企业拒绝。
- `cash_transaction_snapshot/list`：增加过账态字段（status/posted_display、can_post），不改变既有私有投影语义。

## 权限与拒绝

- 过账：owner/finance；读：owner/finance/auditor；pm/member 拒绝。
- 拒绝：已 posted/非 draft、未来日期、locked_through、关闭期间、跨 org 账户/流水、版本过期、撤权、模块停用、重复事件、bool/float、并发双过账只一胜。
- 所有拒绝无半笔：CashTransaction/CashReceipt/DomainEvent/AuditEvent/LedgerEntry/AccountingEvent/Settlement/OpenItem/SourceConsumption 计数不变（generic audit 的审计与其非 canonical 事件除外）。
