## 3. 分摊算法与账本重归属（执行口径）

### 3.1 pool 来源

- 仅取 **costing 已过账**、`scope_kind='nonproject'`、同 org、同 period 的 `LedgerPosting`（`book='cost', origin='current', status='posted'`），且其目标 destination 属于 pool_kind 白名单（映射见上）；**冲销符号规则冻结**：包含 `reverses_posting IS NULL` 的原 posting，并排除其 `reverses_posting` 指向的负值冲销行（成对排除，净额 0）；即「已冲销原 posting 与其 reversal 成对排除」而非单边按符号计入，避免全冲销来源得到 −amount 或双重计入。
- 明确排除：project scope 成本（含 PH-250 项目手续费）、现金流水、收入、未过账/草稿、跨 org/跨期、已直接冲销来源；`source_in_multiple_pools` 由只读核对检测，不在此处静默去重。
- pool amount = 合格来源 posting 的 `amount_cents` **签名合计**（同 org/period/nonproject，含负值冲销）；要求 `pool_amount_cents >= 0` 且来源存在；若合计 ≤0 或来源缺失 → `missing`，拒绝分摊，不猜 0/不取绝对值。
- source_refs 逐 posting 记录原始 scope/amount；重归属不得改这些原始 posting。

### 3.2 权重与末项吸收（冻结算法）

- 权重输入：
  - `fixed_weights`：owner/finance 传 `[{target_kind:'project',target_id,basis_points}]`；服务端校验同 org、项目 active/非 cancelled、target 唯一、bp 1..10000、合计 10000；客户端不得传金额。
  - 其他 driver：服务端从 owner 只读接口派生每项目权重（`revenue_cents` 用 management_revenue 的已确认收入；`approved_minutes` 用 time/costing 已批准分钟；`direct_cost_cents` 用 costing 项目直接成本），再按最大余数法量化为整数 bp 合计 10000；若 driver 数据缺失/全 0 → `missing` 拒绝，不猜 0。
- 金额：
  - `exact_i = amount * bp_i / 10000`（Decimal）；按 target_id 稳定升序。
  - 前 N−1 项 `alloc_i = min(ROUND_HALF_UP(exact_i), remaining)`，`remaining` 先扣减；末项 `alloc_last = remaining`。该 **clamped half-up last-absorb** 保证每项 ≥0 且合计恰等于 amount，是 PH-305“末项吸收 + 每项≥0”的唯一无歧义实现；`algorithm_version='basis_points_clamped_half_up_last_absorb_v1'`。
  - 零分摊项目保留明细（0 合法）；不因 0 删除行。
  - 冲销：不重新计算，逐项复制原 line 的 target/sequence/bp 并取负；最后一项也精确镜像，不做任何舍入/吸收。
- 该 clamp 是对 PH-305“末项吸收”的必要实现细化：原式 `round_half_up` 逐项 + 末项吸收在极端比例下会产生负末项（如 amount=4、8 个 1250bp：前 7 项四舍五入各 1，末项 −3），与契约“每项≥0”冲突；因此**契约不变量优先**，采用 prefix clamp + 末项剩余，并写入 `algorithm_version`。历史批次按各自 algorithm_version 解释，不得换标签重算。
- 权重合计/舍入残差若无法满足（如 bp 非法/amount 负向入口），返回 `basis_points_not_10000`/`rounding_residual` issue 并拒绝，零写。

### 3.3 账本重归属（净零，不重复计公司总成本）

- 分摊执行在同一事务内追加**一个** `core.AccountingEvent`（`source={namespace:'costing',kind:'shared_cost_allocation',id:batch.id,version:1}`、`event_type='costing.shared_cost.allocated'`、`algorithm_version` 同批、`occurred_on=period 首日`、`posting_period=period`）+ 一个 `SourceConsumption`（`consumer='costing_shared'`, `coverage_key='shared_cost:'+batch.id`, `source_id=batch.id`, `amount_cents=abs(amount_cents)`, `event_ref` 指向 event）+ postings：
  - 每个 source posting 一条负数 posting（同 scope_kind='nonproject'/scope_id/book/origin），金额 = −该 source 的 `amount_cents`；
  - 每个 allocation line 一条正数 project posting（scope_kind='project', scope_id=target_id）金额=allocated_cents；
  - 全部 postings 合计 **0**，净零；公司总成本不变；`origin='current'`，`line_index` 稳定（sources 在前按 digit，targets 按 sequence）。
- reversal：新增一个 `AccountingEvent`（source kind=`shared_cost_allocation_reversal`、event_type `costing.shared_cost.reversed`）+ claim + 镜像 postings（source scopes 正数、project 负数，合计 0）；原 event 不改，原 batch 只置 `reversed`。
- 禁止：直接 UPDATE/DELETE 原 postings/事件、改 source scope、把 pool 成本再计入一次公司成本、写现金/收入/结算/未清、生成第二套账。
- 期间：event occurred_on/posting_period 必须 = batch.period，且 period active 未关闭、日期非未来、>`org.locked_through`；关期后写拒绝。
- 审计：`core.audit(member,'plugin.costing.shared_cost_allocated'/'plugin.costing.shared_cost_reversed', batch, payload)`；`plugin.` 避免新增 DomainEvent topic。

```text
create_budget_version(member, project_id, *, period, effective_from, lines, request_token, dry_run=True, based_on_version_id=None) -> dict
approve_budget_version(member, version_id, *, request_token, expected_version, dry_run=True) -> dict

```
- 权限 owner/finance 写；auditor 只读；pm 仅项目摘要；member 拒绝；模块停用 history_read 写拒绝；未登录 403。
- `create`: 新草稿版本号=max+1；校验 lines 科目/金额/引用；dry_run 零写；`request_token` 收据。
- `approve`: 四眼（approver ≠ created_by/submitted_by），expected_version 匹配，公司锁；原子：校验当前无其他 approved（若有置 superseded）→新版本 approved/effective_from 冻结→审计/收据；`dry_run` 零写。
- `reject`: draft→rejected（reason 必填），非 draft 拒绝；不触发 supersede。
- 期间/锁：budget period 若 `AccountingPeriod.status='posted'`（或 closed_through 覆盖）→ `period_closed` 拒绝；未来 period 允许建草稿/批准（effective_from 在期间内且非过去 closed）；不得 retro 改已批准历史。
- 审计：`plugin.costing.budget_approved`/`budget_rejected`（避免新增 canonical topic）。**偏差披露**：PH-306 §2.1 期待写侧实现时定义 canonical 审批/取代 topic，本片改用 `plugin.` 审计以规避新增 canonical；后续由规划槽决定是否补 canonical topic 或显式允许 plugin audit，已记入 report.deviations。
- `budget_etc_snapshot`：按 PH-306 冻结 `budget_residual_v1` 派生，输入=as_of 最近 approved 预算（含 subjects/lines refs）+ costing 已过账成本（book=cost, origin=current, 同 org/project, period/as_of 过滤；负值冲销计入；**排除**现金付款、结算/收入、未批准手续费、预算本身、未过账/草稿成本；正是 PH-306 §3.1 口径）；输出 budget/actual/ETC/EAC/variance/over_budget/remaining、subject actuals（仅可归属时）、missing/refs/method/algorithm_version；缺失 null+missing 绝不 0；只读无 audit/收据/写。
- `budget_etc_issues` codes（冻结）：`budget_missing`、`budget_lines_exceed_total`、`budget_duplicate_active_version`、`cost_missing`、`subject_attribution_missing`、`over_budget`、`budget_period_closed`、`budget_contract_ref_invalid`、`historical_budget_missing`；每条 refs/expected/actual/severity。

## 6. 幂等/并发/期间（两片共用）
