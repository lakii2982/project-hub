# ADR0003 · 四角色工作台只读同源事实

状态：PH005信息契约，不是工作台后端实现。字段及权限继续取已冻结的1.0政策和canonical查询，不新增业务实体、指标公式或授权。

项目是共同中心。老板、PM、成员、财务分别看同一组事实的授权投影，不各维护一份合同额、余额、成本或“老板决策账本”。合同、履约、成本、管理收入、结算和现金仍由原owner写；工作台只通过具名查询读取。待拍板及补录动作链接回原记录/原服务，退回后不在首页复制新单据。

insights.workspace.get/v1与insights.data_gaps.get/v1负责汇总/缺口，planning.eac.get/v1、cash.forecast.13week/v1等具体查询按canonical目录与同名query-results调用；精确ID和源字段说明以owner-workspace契约及JSON定义为准。前端不得直接联查别的域表、保存可编辑汇总余额或重算货币。聚合结果应属于同一as_of_date/watermark，失配、未定日期、缺ETC、缺覆盖单列，不填0，不拼不同快照。

actual是不含已发生暂估成分的核对事实；已发生暂估计入provisional，未来计划只进forecast。现金、预计收付、应收应付、预算余额及经营结果分别呈现。没有完整价款/完工总成本依据，不给预计结余；没有账户覆盖/期初/匹配，不给银行余额；不以任务数量完成率推收入。

角色来自服务端身份/授权项目和敏感可见范围。静态角色开关只演示信息结构，不能作为权限执行。PM只看授权项目汇总且遮蔽个人工资/费率；成员看本人办理；公司资金与核对由有权owner/finance查询。原型演练来源附录只对owner/finance展示，HTML仍含合成数据，不能据此声称服务端隔离已实现。

当前工程验证版只有既有项目、成本/现金等能力。正式合同、新收入/结算/新ETC/EAC、目标读模型及工作台尚待相应PH实现。源字段结构、黄金夹具及离线浏览器通过，只能证明信息契约与交互；不代表真实产品、生产或客户验收。资源冲突没有可靠来源，默认不展示，若要新增排程必须另规划。

验证记录与截图位于docs/product/owner-workspace-assets；源码HTML与唯一共享tokens、截图绑定SHA。后续实现先通过相应业务依赖和统一UI规范，再用真实服务/权限/接口及目标数据重复验收，不拿本原型当产品完成。
