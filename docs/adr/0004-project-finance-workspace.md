# ADR-0004 · 以项目成本与现金流为中心的工作区

2026-10-25，来源用户新需求/Issue #41。规划，代码尚未实施。

决定：Project/Employee/CostRate是唯一基础资料；单独模块与统一服务维护，其余业务只引用ID。任务收敛为里程碑/收付款计划的关键节点，取消日常工作分解和预计工时录入；工时按项目/员工/业务日归集，以当日费率快照计算成本。旧Task和Timesheet.task保留，API的task_id弃用兼容，不迁移猜测历史关系，不重算历史成本。付款/审批/锁账仍由既有确定性服务授权，不因关键任务完成自动记账。

前端Kimi先交付视觉系统/令牌/规范与样张，再做所有产品前端。项目详情用页签，每次只展示当前内容；有真实时间维度的成本、现金与工时提供可访问图表和数表，无时间维度不编造趋势。Linear/Atlassian公开规范仅作借鉴，不引入其依赖或品牌。

五薄片：PH-023视觉规范、PH-024基础服务、PH-025关键任务领域可按互斥文件并行；PH-022项目页签/成本图依赖规范与关键任务；PH-026全站前端/趋势集成依赖前述完成。所有模板/CSS/JS/Django表单呈现交Kimi，GLM/DeepSeek只做后端与测试，公共接线/迁移/文档/PR由主控单写。

代价：保留旧字段兼容期，短期底层不是所有业务插件化；本轮仅重整现有对象不引入合同/结算新域、不扩大core新业务。SQLite通过不能声明PG并发/生产验证。PH-005老板决策工作台研究及PH-016目标仍保留，不把本轮成本/现金图称为管理收入或利润。
