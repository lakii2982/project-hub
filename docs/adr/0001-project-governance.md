# ADR-0001：跨Agent持续迭代基线

状态：Accepted。日期：2026-10-22。业务所有者：仓库维护者；技术整合：当前任务主代理。

## 决策

采用Apache-2.0，GitHub公开源码，main加短分支与PR，包版本以pyproject.toml为唯一来源。首次建库允许一次main初始化；之后按任务分支工作，不强推main或重写已发布标签。

项目事实保存在版本化manifest/tasks、Git和CI，不依赖聊天记忆。GitHub Issue是讨论镜像；任务契约为实现分支开始前main上的版本。范围变化走规划PR，verify-change从BASE读取白名单，不能用实现PR里改大的范围自我授权。

跨Agent入口为AGENTS.md、project/manifest.json及活动handoff；其他工具的入口只指回同一份规则，不复制不同版本。CLI使用Python标准库，无模型SDK或提供方硬依赖。任何coding agent都可以按同样的契约、证据和退出条件开发。

S级金额/权限/迁移/插件内核与治理门禁需要独立复核。独立代理记录不是第二个GitHub身份，也不是机器可验证的模型身份；CI验证实际代码、报告结构和基线范围，审阅者验证判断与证据。不能把报告里写pass当成测试真实执行的证明。

## 取舍

一个个人维护者无法批准自己创建的GitHub PR，因此初始策略为强制PR与检查、审批人数0；S级仍要求具名独立评审证据。增加协作者后可要求独立GitHub审批。远端保护是否生效单独记录；若平台或权限不允许，保留可复制设置与实际差距，不宣称已保护。

任务契约检查仅控制已提交差异；工作区脏改动必须交接并在提交前审阅。CI还必须从可信BASE取治理检查器，防止本PR同时修改检查器后自我放行。CI权限只读，发布job在标签上单独取得contents:write；不使用pull_request_target执行外来PR代码。

## 持续性

可恢复路径包括任务被中断、模型失效/限流、迁移冲突、失败CI、需求变更、已部分发布和秘密泄漏，见docs/engineering/recovery.md。恢复先核实Git与现有文件，不重置用户工作、不重跑有副作用动作猜测状态。自动化CI不调用付费模型；换模型只改变执行者，不改变验收要求。
