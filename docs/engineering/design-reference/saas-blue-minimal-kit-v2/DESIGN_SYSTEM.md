# UI 设计规范 v1.0｜Blue Minimal SaaS

## 0. 设计意图和原则

设计来自**方案 04 的信息组织和留白**，融合**方案 01 的品牌蓝**。侧栏浅色、不做全深蓝侧栏；白底卡片+暖灰蓝画布；蓝色只给当前导航、主 CTA、选中状态、关键趋势与超链接；橙、绿、红只表达经营指标与状态，不能当作第二品牌色。

面向少于 50 人的小微企业：使用者不一定是专业项目经理或财务；屏幕应回答三个问题：**“现在做得怎样？”“哪里有风险？”“下一步怎么操作？”**。优先读数与可执行动作，减少复杂菜单、彩色大面积背景和不必要动效。

## 1. 品牌基础

- **临时产品品牌**：津津项目（演示用途，真实品牌名、Logo、域名由原系统配置决定；禁止擅自更改真实品牌）。
- 图形标：蓝色圆角方形内几何环形/立方图形。默认标志 36×36；菜单/移动端允许 28×28。矢量优先；暂不创建依赖专有字体的 LOGO。
- 风格关键词：干净、可信赖、专业而不沉重、数据可读、工作效率、少负担。
- 图片：以数据和功能组件为主，首页无需巨幅装饰插图。插画仅可在空状态/引导页小面积使用。
- 语气：简洁行动导向；图表轴、成本科目、时间范围与单位要准确。

## 3. 字体与数值排版

系统字体栈：`-apple-system, BlinkMacSystemFont, 'PingFang SC', 'Microsoft YaHei', 'Noto Sans SC', sans-serif`。未确认商业字体授权前不得引入商业字体文件。中文系统字体回退可用。

| 用途 | 字号/行高 | 字重 | 补充 |
|---|---|---|---|
| 一级页面标题 | 24/32 px | 750 或 700 | 单行优先，窄屏可换行 |
| 二级模块标题 | 18/26 px | 700 | 少用于密集仪表盘 |
| 卡片标题 | 14/22 px | 650–750 | 视觉层级由间距建立 |
| 主体文本 | 14/22 px | 400–500 | 主要表单、说明 |
| 数据表格 | 12/18 px | 400–650 | 只用于高密度桌面表格 |
| 辅助标注 | 11/16 px | 400–650 | 非关键次要提示 |
| KPI 数值 | 26/34 px | 750 | 千分位，数字建议 tabular-nums |

- 金额用 `¥ 286,000` 或用户原系统的货币格式；除非业务规则不同，负值用 `−` 并明确核算口径。
- 时间：优先 `YYYY-MM-DD`；短表格可 `10-27`，但行内/表头要能确认年份。
- 百分比：同类指标小数位一致；财务精度不得由视觉稿指定替代原系统财务计算精度。
- 多维比较同时呈现单位、区间、同比/环比的比较基准。

## 4. 布局与响应式

- 桌面侧边栏：232px，白色固定栏，右侧 1px 分割线。导航按“工作台 / 项目协作 / 经营分析 / 组织设置”分组。激活项用淡蓝底+蓝字+图标；每个分组当前至多 1 项 active。
- 桌面顶栏：68px，左侧路径，右侧搜索/通知/用户。固定时需确保内容不被遮挡。
- 页面区：左右内边距 32px，顶部 30px；卡片间距 16px；内容宽度随可用空间延展。禁止以死宽度导致普通笔记本必须水平滚动。
- 卡片：白底、`1px solid #E5EBF3`、圆角 14px、阴影 `0 3px 16px rgba(25,53,103,.035)`，内部留白 18–22px。
- 默认 KPI 4 列。双图表可用约 55% / 45% 的权重；表格全宽；次级布局“说明/事项”可占右 35%–40%。
- `≥1440px`：舒适桌面密度；`1280–1439px`：缩短内边距/缩略辅助信息；`1024–1279px`：允许侧边栏折叠为 72px，卡片/图表重排；`768–1023px`：侧栏折叠，复杂两栏布局变单栏；`≤767px`：侧栏用抽屉，顶栏约 59px，页面边距 14px，KPI 两列、分析卡单列，表格可横向滚动并优先考虑转卡片。
- 移动端交互靶心 ≥44×44px；操作菜单、弹窗不能溢出屏幕；不要通过删除业务功能解决响应式。

## 5. 间距、圆角与层级

使用 4px 基础节奏：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64`。按钮/输入框圆角 8px，细标签 5–6px，卡片 14px，模态框 18px。层级建议：画布 → 卡片 → popover/dropdown → modal → toast；遮罩 z-index 不得覆盖 toast 或阻断焦点。

## 6. 组件规范

### 6.1 基础 Button
- 主按钮：品牌蓝背景+白字，高 36–40px；一个局部主要操作最多一个 primary。
- 次按钮：白底强边框+次级字；文本链接蓝色。危险操作必须有危险语义，并按原系统的可恢复性决定是否二次确认。
- 状态必须有 `default / hover / focus-visible / pressed / disabled / loading`。loading 防重复提交；disabled 必须同时解释原因（必要时 tooltip）。

### 6.2 导航与标签
- 层级导航配 16–18px 线性图标；按钮、导航图标线宽约 1.8–2px。
- Tag/Badge 明确区分状态：进行中 蓝、已完成 绿、待启动 灰/橙、审批待办 橙、逾期 红。**“待支付”属于付款状态，不应混成项目进度状态**。
- 标签内容和颜色同时表意，不可只剩彩色圆点。状态由业务字段映射，不能随意重命名数据库枚举。

### 6.3 输入框与表单
- 控件高 40px，圆角 8px，标签在上，说明在下。日期、金额、工时、项目选择器使用现有验证流程。
- 必须有空值提示、校验错误、只读、权限禁用、加载、保存成功/失败及编辑冲突状态。错误说明靠近错误字段，可用 `aria-describedby` 关联。
- 输入金额时提供清晰币种与单位；工时输入明确 `h`；数值精度、最大最小值根据原系统业务规则。

### 6.4 KPI 卡
- 上行标签+32px 小图标，下行 26px 大数值，再下 11–12px 趋势+比较口径。趋势可以是“上升但不利”（成本增加），不能仅凭上箭头自动涂绿。
- 业务不可计算时显示 `—` 和原因，禁止假装为 0。

### 6.5 表格
- 表头 11–12px，行内容 12–14px，行高推荐 ≥44px；表格横向滚动时需保留关键列/操作可触达。
- 支持原系统已有分页、筛选、排序、导出、列宽、权限、批量操作。没有后端支持则不伪造“已保存筛选”功能。
- 单价/工时/金额右对齐，金额同精度；重要状态与动作不能仅在 hover 可见。
- 空状态：说明为何为空，提供安全可用的下一步操作；网络异常应带重试；加载时用 skeleton 保留结构。

### 6.6 图表
- 收入蓝 `#2563EB`，成本橙 `#F5AC4A`，余额青 `#0FADA9`；计划工时浅蓝，实际深蓝。
- 折线 + 柱形必须有真实数据单位、时间轴、0 基线（柱形）、解释图例、tooltip；缺失值不得连接成假的连续趋势。
- 现金余额是存量，月收入/支出是流量，必要时双轴且标注量纲，不能在错误尺度下直接叠线得出误导性含义。

### 6.7 全局反馈
- Toast：轻量成功/失败，可关闭；破坏性操作使用 Confirm Dialog；后台异步请求展示 loading/成功/失败；所有交互都可键盘到达。
- 维护表单已有校验、脏数据提示、取消确认、保存草稿、审批记录与操作日志。

## 7. 信息语义与财务特别要求

这个产品包含**成本核算、现金流、工时归集**，不允许为了视觉效果改变算法：

1. **合同金额 ≠ 确认收入 ≠ 已收现金**。三者需要不同字段/标题。
2. **项目实际成本 ≠ 现金支出**。现金流以银行/资金收支日期口径；成本以现有业务定义的入账/发生口径。
3. **工时填报 ≠ 已审批工时 ≠ 可进入人工成本归集的工时**。根据业务状态正确计入。
4. **毛利率**在展示前应明确口径，例如 `(已确认收入 − 对应已归集成本) / 已确认收入`，且 0 或无收入需要特殊处理；绝不能默认套用视觉稿数字。
5. 币种、税前税后、预算、费用分摊、预付款、尾款、数据刷新时间与用户权限由原系统提供。
6. 敏感经营数据应遵循现有租户隔离与角色权限；隐藏按钮不是权限控制。

## 8. 无障碍与稳定性

- 最低目标 WCAG 2.2 AA。普通文本对比度 ≥4.5:1；图形对象 ≥3:1，焦点需清晰；色觉障碍下状态仍可理解。
- 键盘 Tab 顺序符合视觉层级、Enter/Space 操作控件、Esc 关闭层、弹窗焦点管理、ARIA 标签明确。
- 尊重 `prefers-reduced-motion`。微动效 120–240ms，仅辅助状态反馈，不用于核心信息持续动画。
- 日期本地化、财务数据脱敏、长文本省略与完整内容 tooltip、深分页和大量数据加载要兼顾性能。

## 9. 原型说明

`demo/index.html` 是用 HTML/CSS/JS 写的**可点击视觉参照**，其内部的演示样式可作为初版校准；生产代码应适配仓库原有技术栈。原型图表和数据只为展示视觉，不能作为真实统计口径与数值实现依据。


## 10. v2.0 业务操作参考补充

除原有模块图之外，还提供可点击的 `demo/workflows.html`：创建项目、填报工时、录入成本、登记现金收付、审批。对应的 PNG 截图可在 `screens/11-flow-*` 至 `screens/15-flow-*` 查看。

- 创建项目：基础字段从简，但真实系统已有必填项、校验和权限不能删。预算与合同额使用不同字段和标签。
- 工时填报：高密度周表支持键盘、移动端局部横滚；演示规则为单格 0–24h、0.5h 递增，**不代表生产系统规则**。已填报 / 已提交 / 已审批 / 已归集成本为不同概念。
- 成本录入：核算期间、科目、审批状态由既有业务模型提供；不因录入成本自动创建银行支付记录。
- 现金收付：分清“计划”与“实际”；收付成功必须由服务端确认，资金余额不能仅按单笔录入在 UI 内假算。
- 审批抽屉：模态焦点保持、Esc 退出、恢复打开触发点焦点；拒绝意见和审核日志以真实规则为准。

扩展契约见 `COMPONENT_CONTRACTS.md`；经营数据不可混用清单见 `FINANCIAL_DATA_RULES.md`。
