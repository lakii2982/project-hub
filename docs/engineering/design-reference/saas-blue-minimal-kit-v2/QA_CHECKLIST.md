# 改造验收清单（Agent 逐项填写）

> 状态说明：`[ ]` 待检、`[x]` 已验证。正式验收应追加检查结果、截图路径或测试命令的证据。

## A. 视觉一致性

- [ ] 全局使用 `design-tokens.json`；无多套冲突主色和重复硬编码。
- [ ] 桌面白色导航侧栏、浅灰蓝画布、白色卡片，符合 04 布局和 01 配色。
- [ ] 1600/1440/1280 宽度下页面无整体水平溢出，表格滚动范围合理。
- [ ] 顶栏、导航、面包屑、页面标题、按钮层级一致。
- [ ] KPI、趋势图、明细表、状态标签跨页面复用统一组件。
- [ ] 默认/hover/focus/disabled/loading/empty/error 均有合理样式。
- [ ] 无效/误导性渐变、装饰插画和假按钮没有混入生产。
- [ ] 亮色主题的中文、英文、数字字阶统一，金额千分位和单位完整。

## B. 响应式与无障碍

- [ ] 1024 左右侧栏折叠正常，键盘可操作。
- [ ] 390×844 手机抽屉可开关，焦点管理正确。
- [ ] KPI 小屏两列，复杂模块按单列重排，表格/工时表可完整访问。
- [ ] 键盘 Tab、Enter、Space、Esc、可见焦点与 ARIA 正常。
- [ ] 正文与关键图标的对比度达到 WCAG AA；信息不只依赖颜色。
- [ ] `prefers-reduced-motion` 有效；无不可关闭弹窗/遮罩。

## C. 核心业务回归

- [ ] 项目：新增、编辑、详情、状态和负责人、归档/权限不退化。
- [ ] 任务：列表/看板、分派、筛选、详情和状态迁移不退化。
- [ ] 工时：草稿、提交、审核、驳回、撤回/修改（若存在）和成本回写不退化。
- [ ] 成本：费用类型、预算执行、权限、审批、导出和毛利核算正确。
- [ ] 现金流：实际收付、账户余额、待回款/预测和预警口径正确。
- [ ] 报表：筛选时间段、汇总口径、导出内容正确。
- [ ] 权限：企业/租户数据隔离、按钮权限、接口权限、数据范围均正确。
- [ ] 加载、无数据、接口异常、网络重试与失效登录都能处理。
- [ ] 相同数据与筛选条件下改造前后数值一致（有明确例外则留痕）。

## D. 工程与交付

- [ ] 按真实仓库技术栈实现，没有盲目重构框架/接口。
- [ ] 无生产 mock 数据或仅为展示存在的假功能。
- [ ] 通过已有 lint/typecheck/unit/e2e/build，附输出和命令。
- [ ] 核心页面有对照截图，记录设计图与生产数据密度差异。
- [ ] 提交或 PR 独立、可验证、可回滚；改动说明清楚。
- [ ] 标记无法实现的视觉/功能差异及确切阻塞原因。

## E. 建议验收设备

`1600×1000`、`1440×900`、`1280×800`、`1024×768`、`768×1024`、`390×844`。


## F. v2.0 关键操作状态验证（生产实现后逐项勾选）

- [ ] 项目表单的所有实际必填、联动校验、取消/脏数据、提交成功/失败均有明确反馈。
- [ ] 工时输入和跨日期/跨任务合计符合现有规则；草稿、提交、已审、成本归集状态互不混淆。
- [ ] 成本录入不会在没有收付交易的情况下更新现金余额；金额精度和预算口径不退化。
- [ ] 计划回款绝不进入实际回款或实际余额；资金流水、对账和现金账户权限正确。
- [ ] 审批驳回意见、附件、日志、权限、重复点击和并发冲突经过真实后端验证。
- [ ] 弹窗抽屉支持焦点管理、键盘 Esc、背景不可交互以及焦点恢复。
- [ ] 所有触发写操作的按钮均不会只弹“演示成功”，需要真实 API 响应才展示成功。
- [ ] 已记录每个 PR 的最小验证证据（命令、结果、截图、已知阻塞、回滚说明）。
