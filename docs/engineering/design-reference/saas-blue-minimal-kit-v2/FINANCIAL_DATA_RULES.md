# 数据语义、财务口径与权限边界｜迁移禁止项

> 这份文件明确的是**UI 如何正确表达数据**以及 Agent 改造时必须核对什么，不为未知的企业业务设计新会计规则，也不覆盖现有 API/DB 契约。

## 1. 三条平行数据链

### A. 项目交付链

项目主数据 → 任务/里程碑 → 进度 → 交付状态。**项目进度**需追溯现有系统实际完成比例的定义（工时加权、任务数量、里程碑权重或人工填报）；不得默认以完成任务数 / 总任务数替代。

### B. 经营成本链

预算 → 费用发生/成本归集 → 审核 → 按项目/科目计算实际成本 → 毛利相关展示。

### C. 现金收付链

收付款计划 → 实际到账/支出交易 → 资金账户期初 + 期间净额 + 调整/冲销 → 账户余额 / 回款预警。

**经营成本链 ≠ 现金收付链**。费用发生可能未付款；回款可能为预收；业务层和会计层有关联，但 UI 不能把二者折叠成一个指标。

## 2. 字段口径对照表（逐项定位真实 API）

| 页面标签 | 对应概念 | 不得替代成 | UI 展示必需上下文 |
|---|---|---|---|
| 合同金额 | 已签合同的价款或既有系统定义 | 已确认收入、已收现金 | 项目、币种、含/未税、变更单规则 |
| 确认收入 | 按现有项目收入确认规则 | 开票金额、合同额、现金回款 | 统计期间、收入确认口径 |
| 已收现金 | 实际到账交易 | 应收、合同额、预测回款 | 收款日、资金账户、期间、是否含冲销 |
| 实际成本 | 已归集项目成本 | 本期实际现金支出 | 发生日/核算期、科目、成本状态 |
| 成本预算 | 可使用预算 | 已付款、已发生成本 | 预算版本、生效日期、币种 |
| 付款支出 | 真实资金流出 | 成本总额、应付款 | 付款日、账户、对账状态 |
| 资金余额 | 时点账户存量 | 回款减成本、本期净现金流 | 截止时点、账户范围、期初及调整 |
| 已填报工时 | 输入/草稿/提交后的时长（依系统定义） | 已审批工时 | 人员、项目、任务、时间范围、状态 |
| 已批准工时 | 通过审批的时长 | 已进入人工成本金额 | 审批人/状态、薪酬与分摊口径 |
| 归集人工成本 | 工时 × 既有归集规则 | 工时简单 × 假设时薪 | 员工成本权限、费率版本、成本期 |
| 毛利率 | `(收入−对应成本)/收入` 的原系统版本 | `(回款−支出)/回款` | 收入/成本是否同口径、零分母处理 |

## 3. 财务图表 UX 防错规则

- 折线图和柱状图的 **0 基线要求**：柱状图以 0 起点；负值另设刻度。存量余额折线如使用非 0 起点必须清晰展示刻度，不能夸大波动。
- 收入/成本/现金余额不同量纲时：可分上下图；若双轴必须标注每条轴及对应图例，不要将金额单位与百分比混在一个轴。
- 空值/无权/数据缺失要区分，必要时显示 `—` 和具体原因；数据更新时点尽可能展示。
- 同一页面涉及含税/未税、币种、汇率或期初余额的，应根据既有模型显示筛选条件与解释，不可凭视觉稿推断。
- “趋势 +8%”不能自动涂绿：成本上涨、应收账款增加可能为负面；显示方向与业务解读分离。

## 4. 前后改造一致性验收（必须留证据）

| 测试对象 | 测试输入 | 预期 |
|---|---|---|
| 项目成本 | 相同项目、科目、统计期间、税制条件 | 改造前后金额及行明细一致 |
| 现金余额 | 相同资金账户、日期截止时点 | 余额及对账状态一致 |
| 回款统计 | 相同时间维度、到账状态 | 仅纳入真实收款交易 |
| 工时统计 | 相同人员、项目、审批状态、周范围 | 小时总数一致，不跨时区串日 |
| 毛利率 | 相同项目、收入确认与成本规则 | 分子/分母、零值处理一致 |
| 导出报表 | 相同筛选、权限、字段列集合 | 数据及权限不退化 |
| 租户隔离 | 两个不同租户/角色访问边界 | 前端不泄漏其他租户或高敏金额 |

## 5. 权限与安全执行规则

- 后端是最终授权边界，菜单/按钮显隐只是 UX，不能当安全措施。
- 项目负责人、财务人员、企业管理员、普通成员只是**常见角色称谓**，不得未经核对就引入新权限枚举。
- 成本费率、员工薪资、资金账户、应付款明细、审批意见等可为敏感信息；沿用现有字段级、行级和租户级权限。
- API 未确认写入成功，不更新 UI 为永久成功状态；采用乐观更新时必须具备回滚和冲突处理。
- 避免把截图中的演示用户、合同金额、资金余额或模拟客户写入生产默认值/测试种子。

## 6. 样板与实际系统的边界

`demo/workflows.html` 所展示的“保存”“同意”“驳回”都是**浏览器内状态模拟**：不会持久化，没有后端授权，不会登记真实财务数据。真实产品需完整复用业务层现有逻辑，且由测试验证结果。
