## 2. 方向定位与页面结构

- 包内定位（`DESIGN_SYSTEM.md` §0）：**方案 04 的信息组织和留白 × 方案 01 的品牌蓝**；浅色侧栏、白底卡片、暖灰蓝画布；蓝色只给当前导航、主 CTA、选中状态、关键趋势与超链接；橙/绿/红只表达经营指标与状态，不能当第二品牌色。
- 产品页面结构（用户选定 A）：**左侧模块导航 + 右侧页签**。映射为：全局白色侧栏（240px）→ 顶栏（68px，面包屑/搜索/通知/用户）→ 页面标题区 → 业务页签（`tablist`/`tab`/`tabpanel`）→ 筛选条 → 数据区；移动端侧栏改抽屉，页签条在自身容器内局部横滚。
- 包内 demo 的侧栏 + 顶栏 + 页面内 tabs 与上述结构基本同构，但**页签内容/命名不能照搬**（见 §4 第 15 项）。
- 参考优先级：真实业务/权限/数据口径 > 仓库规范（PH-023/PH-110）> 本包 `DESIGN_SYSTEM.md` 等文本 > `demo/*.html` 原型 > PNG 截图。

## 4. 前端规范必须解决的差异（逐项，含建议与证据）

> 这些是「包内/方向 A/仓库现状」三方不一致或存在风险、必须在 `visual-system.md` / `frontend-standards.md` / `ui-tokens.css` / `ui-specimen.html` 中明确选择并留痕的项。**建议**仅供规范实施者参考，最终由 PH-110 实施 PR 决定；任何选择不得违反 §6。

1. **主色与派生色统一**：A 选定 `#2563EB`；仓库现为 `#365fc7` 系列。建议把 `--color-accent`、hover、active、subtle、info 一并更新为一套，**不得新增 `--brand-*` 平行变量**。实测 `#2563EB` 对白 5.17:1、对画布 4.90:1、白字对主色 5.17:1，满足正文 AA（§5）。
2. **画布/边框最终值**：包内边框 `#E5EBF3`、A 指定 `#E7ECF5`、仓库 `#d9dee7`。建议采用 A 的 `#F7F9FD` + `#E7ECF5` 写入唯一语义令牌；注意 `#E7ECF5` 对白仅 1.19:1，属于装饰性边界，**不能**拿它充当控件边界或焦点指示（WCAG 1.4.11 需要可感知的 3:1）。
3. **侧栏宽度 232 vs 240**：包/仓库 232px，A 选定 **240px**。建议规范采用 240px 并同步 `ui-tokens.css` 与样张；这是纯布局值，不涉业务。禁止 232/240 两处并存（否则页面与样张对不上）。同步检查 1024 折叠为 72px、移动抽屉等派生行为。
4. **圆角体系**：包为 6/8/10/14/18，仓库为 4/6/8/12（无 14/18）。A 指定卡 14px。建议扩展**单套**语义圆角：小标签 5–6、控件 8、卡片 14、模态 18，并明确 10 的用途或删除；一次改 `ui-tokens.css` + 组件样式，避免页面私有圆角。
5. **字阶/正文基准**：包 H1 24/32、H2 18/26、卡片 14/22、正文 14/22、表格 12/18、辅助 11/16、KPI 26/34、display 28；仓库 rem 体系为 12/14/16/18/22/28。A 指定正文 14px。建议：新增 24px（H1）与 26px（KPI）语义令牌；正文基准定为 14px（PH-110 只要求「不小于 14」），并说明 16px 是否保留给长文段落；**11px/10px 一律不采纳**；行高按包内 22/32/34 校准；字重 650/750 需验证系统字体回退效果，避免伪粗体。
6. **移动页面边距 14 vs 16**：包内 mobile padding 14px，PH-110 明确规定 390px 内容边距 **16px**，且样张 `demo/index.html` 在 ≤760px 也用 14px（`content{padding:19px 14px 25px}`）。规范必须采用 16px，并检查 320px 起无整页横溢；样张 14px 是**反例**，不得作为覆盖依据。
7. **卡片间距 16 与区块间距 24**：包内 cardGap 16、区块用 24（`section-margin` 18–24 不等）。仓库规范为区块 24px。建议明确：紧凑 KPI/图表网格间距 16px，页面大区块间距 24px；禁止随手混用，样张统一。
8. **顶栏/移动导航高度 token 缺失**：包内 68px/59px，仓库没有顶栏高度令牌。建议新增 `--header-height` / `--mobile-nav-height` 并在样张与产品模板保持一致。
9. **控件高度 36 vs 40**：包内按钮 36–40、输入 40；仓库 `--control-height: 36px`。建议明确「按钮 36、输入 40」或统一 36，并保证移动触控 ≥44×44；同一规范内不得两种输入高度并存。
10. **焦点可见性（重点反例）**：包内 demo 使用 `outline: none` + `box-shadow: 0 0 0 3px rgba(37,99,235,.18)`（近透明，对白底几乎不可见），`#BFDBFE` 外框对白 1.42:1；仓库焦点为紫色 `#7c3aed`（5.70:1，但色相偏离 A）。规范必须定义**蓝色实色焦点环**（如 3px `#2563EB` + 2px offset，或等效 ≥3:1 组合），保留 `:focus-visible`，禁止 `outline:none` 且不以阴影代替焦点。包内做法列为反例，不采纳。
11. **卡片阴影冲突**：包内卡片有极弱阴影 `0 3px 16px rgba(25,53,103,.035)`；仓库 `visual-system.md` §2.2 明确「阴影仅用于抽屉、菜单、对话框和即时反馈，普通内容面用边框」。规范必须二选一并写入两份文档：建议维持仓库「内容面边框+圆角、浮层才阴影」的规则；若选择引入包内弱阴影，必须同步修改规范条文并验证层次不依赖阴影。
12. **状态色对比度**：包内警示文字 `#D97706` 对 `#FFF7E6` 为 **2.99:1**、成功 `#16A34A` 对 `#EAF8EF` 为 **3.01:1**、危险 `#DC2626` 对 `#FEF0F0` 为 **4.35:1**，均低于正文 4.5:1；仓库现有更深值（4.82/6.19/5.71）达标。建议保留包内色相作为语义参考，但采用可访问的文字色（加深）或仅用于图标/大字号，并按实际组合实测。另：状态不能只靠颜色（仓库规范），必须有中文/图标。
13. **图表颜色与编码**：包内成本橙 `#F5AC4A` 对白 **1.93:1**、余额青 `#0FADA9` 对白 **2.77:1**，低于图形对象 3:1；仓库 chart-2 `#a15c07`、chart-3 `#18794e` 更深。建议按语义角色（收入/成本/余额/计划/实际）映射图表令牌，并强制线型/点形/图例/文字/替代表格编码；若保留亮橙/青，需加深或仅作填充条形并配标签，不能只靠细线颜色。
14. **辅助文字与 11px**：包内辅助 `#93A1B3` 对白 **2.63:1**、对画布 **2.49:1**，且辅助字号 11px；PH-110 明确「不采纳参考稿的 11px 次要文字」，表格/辅助 ≥12px。建议使用仓库更深的 `--color-text-muted`（或等效值），辅助文字不低于 12px；非关键提示也不得用 2.5:1 级文字。
15. **页面结构与页签/客户对象**：A 为「左模块导航 + 右页签」；包内详情页页签为「项目概览/项目任务/成本核算/项目工时/项目文件」，而仓库冻结基线固定为「概览、关键任务、里程碑、项目财务（有权）、风险、团队」，且基础资料只含项目/员工/成本费率，**不设客户/供应商对象**，而包内项目列表出现「客户名称」列、详情出现客户信息。规范必须采用仓库页签与对象模型，包内客户列/客户页签不进入产品；「设计规范预览」也不进生产导航。
16. **演示数据与口径**：包内 KPI（¥286,000、¥1,260,000、毛利率 32.9%、8 个项目等）、趋势（↑12.8% 自动绿色）、工时 0.5h 递增、项目进度百分比均为虚构演示；不得写入产品默认值/测试种子/文档事实。金额按仓库整数分、工时按整数分钟；前端不重新求和或推算财务值；趋势需区分「方向」与「是否有利」（成本上升不能涂绿）。

补充待决（规范可一并处理）：图标尺寸/线宽（包 18px、线宽 1.8–2px）与仓库本地 SVG 图标体系如何统一；日期格式 `YYYY-MM-DD` 与短表格 `MM-DD` 的展示规则；图表 0 基线与缺失值不插值（包内 FINANCIAL_DATA_RULES 已给出要求，规范应引用而非复制）。

## 6. 业务规则：本参考包永远不得覆盖

> 来源：`AGENTS.md`「财务与数据不变式」、`docs/development-contract.md`、`docs/engineering/visual-system.md`、`docs/engineering/frontend-standards.md`、PH-110。设计包文本（尤其 `FINANCIAL_DATA_RULES.md`）与之一致，仅作补充核对。

| # | 规则 | 对参考包/前端的约束 |
|---|---|---|
| 1 | **金额以整数分持久化**，计算用 Decimal、`ROUND_HALF_UP`，禁止 float；单笔上限 10^12 分 | 包内 `¥ 286,000` 等展示格式、`Number(...).toLocaleString` 演示逻辑不得进入生产；前端只格式化，不重新求和/换算。 |
| 2 | **工时以整数分钟持久化** | 包内 0–24h、0.5h 递增、周表小计均为演示，不采用为业务规则；跨日期/时区/审批状态以服务层为准。 |
| 3 | **费用确认成本、付款确认现金**；同一费用付款不能再记一次成本 | 成本页与现金流页信息分区；不得把「实际成本」当「现金支出」或相反；不得由成本录入自动生成付款。 |
| 4 | **计划与实际分离**；过期未执行计划单列跟进，不自动移到预测当周 | 包内「计划回款/实际回款」KPI 与资金流水必须分栏、分字段；计划不得计入实际余额或实际回款。 |
| 5 | **净现金流 ≠ 利润 ≠ 银行余额** | KPI 命名、口径说明与时间范围必须分开；不得用「回款 − 支出」冒充利润或余额。 |
| 6 | 合同金额 ≠ 确认收入 ≠ 已收现金；毛利率按既有口径、零分母特殊处理 | 不照搬包内 32.9% 等数字与公式；展示前必须标口径与期间。 |
| 7 | 工时填报 ≠ 已审批工时 ≠ 可归集人工成本；项目进度定义按现有系统（工时/任务/里程碑权重） | 包内状态标签、进度百分比仅示意；不得用「完成任务数/总任务数」默认替代。 |
| 8 | 权限由**后端**最终授权；租户隔离、角色枚举以仓库为准；隐藏按钮不是权限控制 | 包内角色称谓/前端隐藏逻辑不得作为依据；包内示例邮箱/姓名/金额不得入库；无真实客户、员工工资、凭据、令牌。 |
| 9 | **占位品牌不是产品品牌** | 「津津项目」、LOGO/favicon/app-icon 不采用；产品名称/Logo/域名以现有系统为准。 |
| 10 | 模型只提取候选/解释/建议，**不构成审批或记账授权** | 任何原型/AI 文案不得渲染为审批外观或操作特权。 |
| 11 | 不新增业务审批阶段、权限规则或金额口径；不改 API/DB/状态机 | 本包只用于视觉/交互规范；规范实施 PR 不得借机改业务。 |
| 12 | 账本与审计只追加；不得关闭触发器、直接改余额或通过插件改历史账 | 演示图/原型不得暗示可编辑余额或绕过审计。 |
