# 页面地图与功能交互规范 v1.0

## 一、总体导航与角色

一级导航采用固定顺序：**工作台**（经营总览）、**项目协作**（项目管理、任务协作、工时填报）、**经营分析**（成本核算、现金流监控、经营报表）、**组织设置**（团队与权限；设计规范预览仅供开发/演示，不放进生产导航）。项目详情通过项目列表进入，不单独占据一级导航。

建议现有角色延续：超级管理员/企业管理员、项目负责人、财务、普通成员。**不要凭视觉稿新建角色系统**；如果原系统不同，以既有角色与接口为准，并做前端菜单可见性与后台权限双重核查。

## 三、核心流程（状态示意，Agent 必须先核查真实系统）

### A. 项目创建与管理

`项目列表 → 新建项目 → [校验必填/权限] → 保存 → 项目详情 → 编辑信息/成员/里程碑 → 项目归档或关闭`。

- 项目名称、编号、客户、负责人、开始/结束日期、合同及预算等字段按原系统既有要求。
- 取消编辑时，如果表单有改动则提示是否放弃；后端提交失败不丢弃输入值。
- 阶段进度不能仅以效果图颜色推断，需从真实状态计算。

### B. 任务分派与跟踪

`项目详情/任务协作 → 新建任务 → 分派负责人 → 状态更新 → 评论/附件/验收 → 完成`。

- 看板列数以原系统状态机为准；可显示列标题但不得在无 API 支持时更改任务业务状态。
- 拖拽只有在已有权限和业务能力时才加入；默认静态卡片点击打开详情。
- 临期提醒需要真实的截止日期、时区和“已完成/取消”排除条件。

### C. 工时与成本

`选择项目和任务 → 填写每日时长 → 保存草稿 → 提交审批 → 审批通过/驳回 → 根据现有规则计入人工成本`。

- 工时允许范围、跨日期统计、节假日与加班倍率都取实际业务系统。
- 拒绝、撤回、更正记录不能被简单覆盖丢失；要留存需要的审批/审计信息。
- 当前用户只看本人数据，经理/管理员按授权查看团队工时。

### D. 成本和现金流

`成本归集 → 按项目分解 → 预算偏差 → 毛利核算` 与 `收付款登记/同步 → 现金账户更新 → 回款预测/风险提醒` 是**两条不同的计算链**。

- 不可用“已确认收入”代替“实收现金”，或用“项目成本”代替“现金支出”。
- 任何金额更改要尊重已审核/已结算状态。明确是否为含税金额、币种、单位和时区。
- 缺少可靠真实数据时展示“暂无数据/无法计算”，禁止填充截图演示数据。

## 四、关键交互与反馈

| 场景 | 默认态 | 加载中 | 空态 | 失败/权限不足 |
|---|---|---|---|---|
| 项目列表 | 筛选栏+表格+分页 | 表格骨架屏 | 项目插图/创建入口，视权限 | 重试；无权时说明原因 |
| 现金流趋势 | 时间范围、图例、轴单位、数据更新时间 | 图表占位骨架屏 | 指明所选区间暂无收支 | 不展示虚构曲线；给错误提示 |
| 成本明细 | 可筛选表格，金额右对齐 | 行骨架屏 | 引导录入或调整筛选 | 对审批/删除按原规则处理 |
| 工时填写 | 可编辑小时网格 | 保存按钮 loading | 新成员显示填报引导 | 行内错误、保存冲突和失败可恢复 |
| 任务看板 | 分列、任务摘要和优先级 | 列占位 | 当前列空状态 | 无权时不展示不可执行操作 |
| 通知 | 未读数/空提示 | 圆点或骨架 | “暂无通知” | 不允许仅装饰性红点常亮 |

## 五、页面优先级与迭代顺序

**P0：视觉底座**：令牌、字体、全局 Layout、按钮、输入框、状态标签、表格、卡片、抽屉/弹框、loading/empty/error。先适配一个小页面，证明不会污染老界面。

**P1：高频作业**：项目列表/详情 → 任务协作 → 工时填报；先保障记录数据的操作流稳定。

**P2：经营分析**：成本核算 → 现金流监控 → 经营总览/报表；涉及数据定义，需要独立验收财务口径。

**P3：收尾优化**：响应式细节、成员权限页、全局搜索/通知、性能与无障碍、移除无效样式。

## 六、响应式页面约束

- 桌面：侧边栏 232px；顶部 68px；KPI 四列；侧边导航常显。
- 小屏电脑：侧边栏 72px 图标模式，悬浮提示必须可用，支持键盘操作。
- 移动端：菜单抽屉；KPI 2 列；指标超过宽度允许数字字号到 20px 或换行；分析模块单列。
- 项目/财务表格数据项多，优先保留“名称/状态/下一动作”，其余横向滚动或点击详情。确保页面本体宽度不发生意外溢出。
- 工时周表可以在卡内横滚；必须显式提示可横向滚动，并保证键盘聚焦时可操作。

## 七、实物参考优先级

**真实仓库的业务行为、字段和权限 > 本规范数据语义 > 可点击原型布局 > PNG 视觉**。如果产生冲突，Agent 应在 PR/改造报告记录冲突与取舍，不能悄悄删业务。
