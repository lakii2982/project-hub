# 前端工程规范

状态：PH-023 冻结基线。所有产品模板、静态资源与前端审查必须先阅读本规范和 `visual-system.md`，并参照 `ui-specimen.html`。本任务只交付规范与静态样张，不表示产品页面已经改造。

## 1. 强制约束

1. 颜色、字体、字号、行高、间距、圆角、边框、阴影、焦点和图表色必须使用 `ui-tokens.css` 的语义令牌；组件样式不得新增十六进制色值或页面私有令牌。
2. 复用共享侧栏、移动导航、页头、操作组、页签、筛选、表格、表单、状态、空态、反馈和对话框模式。禁止各页复制后只换颜色，禁止只换色而不统一布局与交互。
3. 使用 Django 模板、系统中文字体、原生 CSS/JS/SVG；不引入远程字体、远程脚本、前端构建链、消息中间件或新依赖。第三方参考不是可复制的品牌资产。
4. 标准正文至少 14px；表格和辅助文字至少 12px。中文长标题正常折行，金额、工时和比较数字使用等宽数字。不得用截断隐藏关键业务信息。
5. 不通过前端规范新增业务审批阶段、权限规则或金额口径。前端只调用既有业务服务，不把禁用按钮当作服务端权限控制。

## 2. 文件与组件组织

产品实现时，令牌由共享样式在全局加载一次；组件样式按共享模式组织，页面只保留布局组合。模板使用语义 HTML：一个主标题、`nav`/`main`/`section` 分区、真实 `button`/`a`/`label`，不得用带点击事件的 `div` 替代控件。

建议的共享部分名为 `app_sidebar`、`page_header`、`tabs`、`filter_bar`、`data_table`、`form_field`、`status_badge`、`empty_state`、`feedback`；名称是组织约定，不要求为本任务新增产品文件。组件对外参数应包含标题、状态、空态、错误和加载/不可用状态，不能只实现理想数据。

操作层级：每页最多一个主按钮；次操作使用次要按钮，低频操作收进菜单，危险操作使用明确动词。链接用于导航，按钮用于操作。图标必须来自本地共享 SVG，装饰图标使用 `aria-hidden="true"`。

## 3. 令牌使用

- 背景使用 `color-canvas/surface`，正文使用 `color-text`，辅助文字使用 `color-text-secondary/muted`。
- `accent` 表示当前与主要交互；`success/warning/danger/info` 表示语义，不可互换作装饰。
- 间距取 `space-*`，布局以 4px 网格对齐。普通内容不用阴影，浮层才用 `raised/overlay`。
- 所有可交互控件使用统一 `:focus-visible` 焦点环，不得 `outline: none`；浮层和 sticky 区域使用已定义层级。
- 断点令牌记录 390/640/768/1024/1440px。CSS 自定义属性不能用于媒体查询条件，媒体查询可使用与令牌同步的字面值，修改时必须同时更新两者。
- 图表除 `chart-*` 颜色外必须有文字、线型/点形/纹理编码；禁止颜色成为唯一信息载体。

## 4. 响应式规则

桌面 1440px 使用侧栏加主内容；390px 使用单列与模态导航抽屉，16px 页面留白，触控目标至少 44px。DOM 顺序在两种布局保持一致，不能用 CSS `order` 改变阅读顺序。

表格默认桌面呈现。窄屏优先将每个 `td` 转为带 `data-label` 字段名的行卡片，保持列顺序和展开能力；只有无法重排的矩阵才允许表格容器局部横滚，页面 `body` 不得横滚。筛选和表单在窄屏改为单列，按钮组可纵向排列。项目与基础资料页签不换行，只在页签条内部横向滚动；页面不得因此横向溢出。

项目详情仅使用“概览、关键任务、里程碑、项目财务（有权）、风险、团队”页签；无权限的财务内容按不可用状态处理，不能借隐藏页签扩大权限。普通成员的本人费用从“我的费用”导航进入。基础资料仅提供“项目、员工、成本费率”三类列表与维护表单，不出现客户或供应商对象。

关键任务必须关联同项目里程碑或收付款计划，日常开发和服务执行不作为关键任务。工时表单只包含项目、员工、日期、时长、工作内容，不关联任务，不向普通成员展示个人费率。页签以面板 ID 作为刷新深链，默认只显示当前面板；无 JavaScript 时以锚点和展开的面板保证内容可达。

必须检查 320px 至宽屏之间的连续宽度，而非只看两个截图。不能依赖固定文字宽度、绝对定位或固定高度掩盖溢出；SVG 使用 `viewBox` 与弹性宽度。

## 5. 键盘、焦点与语义

- 页面开头提供跳到主内容链接； landmarks 与标题层级完整。
- 所有功能可用 Tab、Shift+Tab、Enter/Space 操作；页签左右方向键移动，Home/End 到首尾。焦点顺序符合视觉顺序。
- 原生 `dialog` 优先用于抽屉、登录和审批。打开时聚焦标题或首个控件，Tab 留在对话框内，Escape 可关闭，关闭后焦点回到触发按钮。
- 页面/页签切换后将焦点移至新视图标题；动态展开保持焦点在触发按钮，并同步 `aria-expanded`。不能隐藏或销毁当前焦点元素而不安排落点。
- 表单错误摘要和字段错误通过 `aria-describedby` 关联；提交失败后聚焦首个无效字段。即时成功信息使用 `role="status"`，阻断错误使用 `role="alert"`。
- 图标按钮有可访问名称；输入有永久标签；表格有 `caption` 或可访问名称；SVG 有 `title/desc` 或可访问数据表。

## 6. 状态与数据完整性

每个异步区域必须设计默认、加载、成功、空、筛选空、错误、不可用状态。加载保持尺寸稳定；错误保留输入并提供重试；无权限与无数据文案不得混用。按钮提交中防止重复触发，但服务端幂等与权限仍由业务层负责。

状态徽章采用“图标/形状 + 中文”。日期、期间、单位和时区明确；金额右对齐且不在 HTML 中重新计算。趋势图注明指标口径、区间、单位与数据来源，配套精确数据表；现金、利润、预计和实际不得混称。

空态必须给出下一步：初始空可创建，筛选空可清除筛选，无权限说明联系路径。错误不得只写“出错了”，不得仅依赖红色或自动消失的 toast。

## 7. 登录、审批与敏感操作

登录使用完整表单标签、密码显示开关、可聚焦错误和提交状态，不自动填充演示凭据。样张中的账号、项目和金额全部为虚构演练数据，不得加入真实客户、员工工资、令牌或凭据。

审批按“申请事实—证据—审批记录—意见与操作”排列。退回、驳回和通过使用不同文字，破坏性操作确认后执行。AI 内容只能标为建议或候选，不渲染为审批授权。

## 8. 变更与审查门禁

新增交互或视觉模式前，先在同次变更更新 `visual-system.md`、本规范和 `ui-specimen.html`，再进入产品实现；已有模式可复用时不得扩展。令牌变化需搜索所有使用点，避免半成品分叉。

每次前端交付至少提供：

- 1440px 与 390px 的真实浏览器检查，覆盖导航、页头、页签、长中文、表格、表单、图表和展开行；页面无横向溢出。
- 仅键盘完成导航、页签、筛选、展开、对话框与表单；焦点可见、顺序正确、关闭后焦点恢复。
- 默认、空、筛选空、错误、加载、不可用状态；状态不只靠颜色，文本缩放与减少动态效果可用。
- 自动化命令的真实结果与浏览器结果分开记录；静态样张通过不等于产品页面、生产兼容或业务验证通过。

整合者执行技术验收，不新增强制审批阶段。未实际运行的检查必须写“未验证”，不得以规范存在替代运行证据。
