# 项目中枢视觉系统规范 v2.0

状态：视觉与布局冻结基线。适用于项目中枢（PROJECT HUB）全部产品前端。
本文件定义视觉语言与页面结构；`frontend-standards.md` 定义工程与验收，`ui-tokens.css` 是唯一语义令牌来源，`ui-specimen.html` 是参考实现样张。
本文件是后续改造规范，不表示产品页面已经完成迁移。业务契约、财务口径与权限规则优先于本文件；设计参考包仅作风格参考。

## 1. 设计方向与原则

视觉方向确定为 **A：蓝白极简 SaaS**。白色侧栏、浅蓝灰画布、品牌蓝强调和细边框构成统一外观，服务老板、项目经理、成员与财务等既有视角，不为不同角色另建视觉体系。

本方向吸收设计参考包“04 极简留白”的信息组织与空间节奏，以及“01 蓝色科技”的品牌蓝；不继承其占位品牌、示例金额、虚构权限、样例路由和低于本规范下限的文字规格。三方向中的 B、C 不再作为产品页面备选方案。

- **层级来自排版、留白与细边框**：不用大段英文眉题、渐变、装饰插画或卡片堆叠制造层级。
- **表格优先**：经营数据以可扫描、可比较的表格为主；指标卡用于摘要，不用数字墙替代明细。
- **经营数据可比较**：同类数值保持单位、精度、对齐和时间范围一致；缺口与异常紧邻所属对象。
- **信息始终可理解**：状态同时使用图标或形状与中文；缺数据明确标注，不用假零或推测值填充。
- **渐进披露**：默认呈现常用字段、主筛选与主要操作；次要筛选、行明细和记录按需展开。
- **克制与一致**：同层页面共用侧栏、页头、页签、密度、控件和反馈位置，不以页面私有样式制造差异。
- **操作服务事实**：界面先回答“现状、异常、下一步”，不以解释性长文替代清晰标签和可执行入口。
- **业务不被视觉改写**：不得为对齐原型而修改字段含义、状态机、计算规则、权限或数据精度。

## 2. 布局基线

### 2.1 应用骨架

- 桌面采用固定 **240px 白色侧栏 + 弹性主区**；侧栏固定在左侧，主区设置 `min-width: 0`，不得被宽表格撑破。
- 主区内容最大宽度为 **1440px**；更宽视口中内容居中，侧栏与顶栏仍保持应用骨架，不无限拉宽表格列。
- 页面画布为 `#F7F9FD`，侧栏、顶栏和内容面为 `#FFFFFF`；不以大面积品牌蓝铺底。
- 桌面主区水平留白 **32px**，顶部留白 20–24px，底部至少 24px；区块间距 **16px**。
- 顶栏高 **60px**，允许在 56–64px 内统一调整；sticky 顶栏不得遮挡锚点、焦点或错误摘要。
- 页面先提供“跳至主要内容”链接；`main` 有稳定 ID，并程序化接收跳转焦点。
- 普通内容面用 1px 边框分层；阴影只用于抽屉、菜单、对话框、浮层和即时反馈，指标卡与表格面板默认无阴影。

### 2.2 色彩、字体与形状令牌

产品页面只能引用 `ui-tokens.css` 中的语义令牌；下列色值用于令牌校准，不得复制为页面私有十六进制值。

| 语义 | 基准值 | 用途 |
| --- | --- | --- |
| 画布 | `#F7F9FD` | 主区背景 |
| 内容面 | `#FFFFFF` | 侧栏、顶栏、面板、输入框 |
| 次级内容面 | `#F4F7FC` | 工作空间、表头、局部摘要 |
| 主文字 | `#0F1D33` | 标题、正文、关键数值 |
| 次要文字 | `#526175` | 次级字段、未选导航 |
| 辅助文字 | `#67758A` | 日期、计数、非关键辅助信息 |
| 默认边框 | `#E7ECF5` | 面板、分隔线 |
| 强边框 | `#DBE3F0` | 输入框、次按钮 |
| 品牌蓝 | `#2563EB` | 主按钮、链接、选中指示、焦点 |
| 品牌悬停 | `#1D4ED8` | 主按钮与链接 hover |
| 品牌浅底 | `#EAF1FF` | 当前导航、信息徽章、选中弱背景 |
| 品牌浅边框 | `#D6E3FF` | 选中面板或信息边界 |
| 成功 | `#0B7A53` / `#E7F6EF` | 文字图标 / 浅底 |
| 警告 | `#9A5B06` / `#FDF3E3` | 文字图标 / 浅底 |
| 危险 | `#B42318` / `#FDECEB` | 文字图标 / 浅底 |
| 中性浅底 | `#EEF2F8` | 草稿、未开始、普通计数 |

- 字体使用系统中文字体栈：`-apple-system, BlinkMacSystemFont, "SF Pro SC", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans CJK SC", "Source Han Sans SC", sans-serif`。
- 正文 **14px/1.5**；页标题 **24px/650**；面板标题 **14.5px/650**；表格 **12.5–13px**。
- 表格、辅助文字、徽章和表单帮助文字均不得小于 **12px**；不得沿用原型中的 9–11px 小字。
- 指标数值默认 24px/650，窄屏可降至 20px；不得为塞入内容继续缩小。
- 卡片圆角 **14px**，按钮 **9px**，输入框 **8px**，状态标签 **999px**。
- 数字使用 `font-variant-numeric: tabular-nums`；金额、工时和数量右对齐，文本左对齐。
- 图标使用本地 SVG，导航图标 18px、常规操作图标 16–20px，线宽与样张一致；装饰图标对辅助技术隐藏。

### 2.3 侧栏

侧栏自上而下固定为：品牌区、工作空间、主导航、底部状态与用户区。

- 品牌区包含本地品牌标记、“项目中枢”和可选“PROJECT HUB”；英文仅作品牌名，不作页面眉题。
- 工作空间显示当前空间名称；切换能力仅在真实业务支持时提供，不伪造空间切换器。
- 主导航顺序固定为 **工作台 / 项目 / 工时 / 费用 / 现金流 / 设置**；项目详情不占一级导航。
- 每项同时显示图标与中文；当前项使用浅蓝底、品牌蓝文字、左侧 2px 指示条和 `aria-current="page"`。
- hover 只改变当前项背景与文字，不位移、不放大；禁用项使用 `aria-disabled` 并提供原因。
- 底部仅放当前用户、角色和工作空间状态；不得把页面主操作塞入侧栏。
- 导航数量增加时侧栏内部可纵向滚动，底部状态保持可达，不让整页横向溢出。

### 2.4 页头

- 页头由可选面包屑、页面标题或计数、操作区组成；面包屑与标题不得重复表达同一层级。
- 每页只有一个 `h1`；页签下面板标题用 `h2`，面板内分组用 `h3`，不重复堆叠相同文案。
- 标题右侧最多一个实心主按钮；次操作使用描边或文字按钮，更多低频操作进入可键盘访问的菜单。
- 标题旁计数采用短文本，如“12 个项目”；不得添加卡片副标题、经营说明或重复口径段落。
- 主操作必须与当前页面或页签匹配；切换页签后不得保留会误导提交对象的页面主按钮。

### 2.5 页签与面板

- 页头下直接放业务页签，页签下才是当前面板的筛选与内容；不得再插入描述横幅。
- 使用 `tablist` / `tab` / `tabpanel`，选中项有 `aria-selected="true"`、品牌蓝文字和底部 2px 下划线。
- 每次只显示一个面板；非当前面板使用 `hidden`，不得仅靠透明度或移出屏幕隐藏。
- 页签与面板通过稳定 ID 关联，支持面板 ID 深链、刷新恢复与浏览器前进后退。
- 无 JavaScript 时仍可通过锚点阅读目标面板；不得形成空白页或无法到达的内容。
- 键盘支持 ←/→ 循环切换、Home/End 到首尾；漫游 `tabindex` 与焦点策略由样张统一实现。

### 2.6 密度、对齐与窄屏骨架

- 全部间距采用 4px 网格，常用值为 4/8/12/16/20/24/32/40/48/64px。
- 卡片与面板内距为 **16–18px**，表格首末列可与面板边缘对齐，不层层嵌套卡片。
- 桌面按钮和输入控件高 **36–40px**；触控环境点击目标至少 **44×44px**，可用透明扩展区域但不得互相覆盖。
- 卡片只包裹边界明确的独立内容；同一面板中的字段组、明细和说明优先用分隔线与留白分区。
- 390px 及更窄视口使用单列，侧栏改为原生 `dialog` 或等价可访问抽屉，主区不再保留 240px 左边距。
- 窄屏页头保留菜单、标题和一个主操作；其余操作进入“更多”菜单或内容区操作组。
- 390/320px 内容留白均为 **16px**，顶栏高 56px；指标卡可两列，空间不足时改单列，数值不得溢出。
- 禁止通过缩小字体、裁切内容、隐藏关键功能或整页横向滚动完成窄屏适配。

## 3. 导航、页头与页签规则

- 当前模块必须由背景、指示条、文字和 `aria-current` 共同表达，不得只改变颜色。
- 移动导航打开后焦点进入抽屉并停留在其中；Escape、关闭按钮和遮罩可关闭，关闭后焦点回到菜单按钮。
- 抽屉打开时背景不可交互、不可被辅助技术误读；页面滚动锁定不得造成布局跳动。
- 每页一个主操作；危险操作使用独立危险样式和明确动词，不与主操作并列为相同样式。
- 删除、作废等不可逆或高风险操作按业务规则确认；确认文案写出对象与后果，不能只问“确定吗”。
- 页签只表达同一对象的同级视图，不代替步骤条、向导、分页或保存按钮。
- 页签顺序与结构树一致，不能因角色权限重排剩余页签；无权页签按产品权限契约隐藏或说明不可用。
- 窄屏页签在自身容器内横向滚动，保持单行、不换行、不截字；选中项自动滚入可见区域。
- 页签容器为焦点环预留至少 2px 外扩空间，不得被 `overflow` 裁切；页面本体始终不横滚。
- 页签切换不重置未保存表单；离开有修改的面板时按既有脏数据规则提醒。

## 4. 模块与页签结构树

左侧负责选择模块，右侧负责模块内页签。除“项目列表”外，不得把模块页恢复为全部区块堆叠的长滚动页面；项目详情从项目列表进入，沿用同一壳层。

### 4.1 工作台

目标：让经营者先看到收益与现金、到期事项和项目变化，再进入来源处理。

- **收益与现金**
  - 区块：4 张等宽指标卡“本月开票 / 本月已收款 / 本月已支出 / 未收款合计”；资金账户余额条“现金余额 / 8 周预计缺口”；项目收益排行表；到期提醒摘要列表。
  - 排行表列：项目、合同额、已开票、已收款、人工成本、费用、毛利、项目现金净额、缺口徽章；项目名可进入详情。
  - 使用：经营总览与跨项目比较；不用：代替发票、收款或费用明细的编辑入口。
  - 空态/缺口：无项目时给“新建项目”或“查看项目”；缺费率、未开票等用徽章和计数，汇总不可算时显示“—”。

- **到期提醒**
  - 区块：到期未收、待开票、费用待确认、合同到期四个分组；每项显示对象、到期日、金额或数量、状态和来源链接。
  - 使用：定位需要跟进的事项并点回发票、项目或费用来源；不用：新建一套提醒状态或审批流程。
  - 空态/缺口：显示“暂无到期事项”；某组为空可省略该组，页面保留其他分组与总计数。

- **项目动态**
  - 区块：最近项目与状态变化只读流，包含项目、变化类型、时间、操作者和来源入口。
  - 使用：查看近期事实变化；不用：把动态流当作可编辑审计日志或任务评论区。
  - 空态/缺口：显示“暂无项目动态 / 查看项目”；动态缺失不影响收益数据展示。

### 4.2 项目与项目详情

目标：从列表比较项目，再进入单个项目处理交付、财务、风险和团队信息。

- **项目列表**
  - 区块：状态、负责人、关键词筛选；结果计数；桌面表格或等效项目卡片；分页沿用既有能力。
  - 字段：项目、客户、合同额、进度、毛利、缺口；操作进入项目详情，不在每行重复全部财务字段。
  - 使用：筛选与比较项目；不用：在一个页面同时展开所有项目详情。
  - 空态/缺口：初始空给“新建项目”；筛选空保留条件并给“清除筛选”；毛利不可算显示“—”和缺口徽章。

项目详情页签固定为以下六项：

- **概览**
  - 区块：项目状态、负责人、客户、起止日期、关键任务进度、合同额与少量关键事实；最近里程碑和风险摘要可进入对应页签。
  - 使用：快速确认项目当前事实；不用：重复项目财务完整链路或堆叠全部任务。
  - 空态/缺口：未设日期、负责人等按字段显示“未设置”；关键进度无数据时不显示 0% 假进度。

- **关键任务**
  - 区块：状态/负责人筛选、任务表或列表、截止日期、状态与既有操作；详情按现有能力展开。
  - 使用：跟踪影响交付的关键任务；不用：自造看板状态、拖拽规则或新审批阶段。
  - 空态/缺口：显示“暂无关键任务 / 新建任务”；无权限时不展示可执行假象。

- **里程碑**
  - 区块：按日期排序的里程碑列表，包含名称、计划日期、完成日期、状态和关联事项。
  - 使用：检查交付节点；不用：把里程碑与关键任务混为同一状态模型。
  - 空态/缺口：显示“暂无里程碑 / 新建里程碑”；过期未完成用警告徽章，不自动改期。

- **项目财务**
  - 区块：固定链路“合同额 → 已开票 → 待开票 → 已收款 → 未收款 → 人工成本 → 直接费用 → 毛利 → 项目现金净额”，下方提供发票、收款、工时成本与费用明细表。
  - 链路是字段导航而非视觉加法公式；页面仅保留一次“合同额≠收入”和一次“毛利≠现金净额”。
  - 使用：核对项目收益、成本与现金；不用：展示成本预算余额燃尽图，或用现金净额替代毛利。
  - 空态/缺口：缺费率工时、未确认费用等显示缺口计数；受影响指标显示“—”，不得按零成本计算虚假毛利。

- **风险**
  - 区块：风险列表，包含风险、等级、状态、负责人、日期和既有处置入口。
  - 使用：记录并跟踪真实风险；不用：仅凭指标颜色自动编造风险结论。
  - 空态/缺口：显示“暂无风险记录”；无数据不等于业务无风险，不展示“风险为零”。

- **团队**
  - 区块：成员、项目角色、负责人状态与既有成员管理操作；成本费率不在此暴露给无权用户。
  - 使用：确认项目成员与职责；不用：替代设置中的全局成员和费率管理。
  - 空态/缺口：显示“暂无成员 / 添加成员”；无管理权限时仅展示只读列表或无权限状态。

### 4.3 工时

目标：按周完成填报，并分别查看个人明细与项目汇总；页面输入小时，内部仍按整数分钟记账。

- **按周填报**
  - 区块：上一周/下一周与周区间导航；项目、日期、小时、说明编辑行；本周合计；“保存本周”为唯一主按钮。
  - 小时输入允许 **0.1–24**，步进 0.1；显示小时与内部整数分钟转换必须无损，禁止浮点误差进入账务。
  - 使用：当前用户按周录入或修改既有权限范围内的工时；不用：把保存、提交、审批、成本归集混为一个状态。
  - 空态/缺口：无记录时提供一行可填写空行；保存失败保留全部输入并定位错误。

- **工时明细**
  - 区块：周区间、项目、成员等权限内筛选；日期、项目、成员、小时、说明、状态表格；可展开查看来源记录。
  - 使用：核对单条工时；不用：在只读明细中伪造批量编辑能力。
  - 空态/缺口：筛选空保留条件；缺费率以“缺费率”徽章表达，不将人工成本填为 0。

- **项目汇总**
  - 区块：按项目汇总小时与人工成本，必要时按成员展开；统一区间和单位。
  - 使用：比较项目投入；不用：用汇总小时直接推断已审批或已归集成本。
  - 空态/缺口：显示“所选区间暂无工时”；成本不可算时保留小时数并显示成本缺口计数。

### 4.4 费用

目标：登记费用、完成既有确认、查看未来计划与全部记录；费用确认成本，付款确认现金，二者不得重复计算同一支出。

- **登记费用**
  - 区块：项目、类别、金额、日期、说明及既有必填字段；“登记费用”为唯一主按钮。
  - 使用：创建一条费用事实；不用：登记费用时同时伪造付款成功或银行流水。
  - 空态/缺口：项目不可选时说明权限或数据原因；提交失败保留输入，金额按整数分校验。

- **待确认**
  - 区块：待确认费用表、金额、项目、提交人、日期、证据与既有确认操作。
  - 使用：处理当前业务已有的费用确认；不用：新增审批层级或用确认代替付款。
  - 空态/缺口：显示“暂无待确认费用”；证据缺失用徽章标明，不静默通过。

- **8 周计划**
  - 区块：按周展示计划支出、已确认未付支出、合计与来源；过期计划单列。
  - 使用：观察未来八周支出安排；不用：把计划写成实际支出或自动把过期计划挪到本周。
  - 空态/缺口：显示“暂无支出计划 / 登记计划”；同一来源只计一次，并给出来源链接。

- **全部记录**
  - 区块：项目、类别、状态、日期筛选；费用记录表；可展开查看确认、付款和审计事实。
  - 使用：检索完整费用历史；不用：把待确认筛选结果复制成第二张重复页面。
  - 空态/缺口：初始空给“登记费用”；筛选空给“清除筛选”；付款缺失不等于金额为 0。

### 4.5 现金流

目标：合并原开票与收款、现金入口，统一查看发票、实收、资金账户和八周预测，避免同一笔钱出现两个事实入口。

- **概览**
  - 区块：4 指标“已开票 / 已收款 / 未收款 / 资金账户余额”；项目开票收款表；必要缺口计数。
  - 使用：比较项目开票与回款；不用：把已开票当已收款、把净现金流当利润或银行余额。
  - 空态/缺口：无记录给对应登记入口；账户余额不可用时显示“— / 余额缺失”，其他指标继续展示。

- **发票**
  - 区块：项目、状态、开票区间筛选；发票号、项目、金额、开票日、到期日、已收、未收、状态表。
  - 使用：登记、查看和跟踪既有发票；不用：用开票动作直接生成收款事实。
  - 空态/缺口：显示“暂无发票 / 登记发票”；到期未收用状态徽章并链接收款来源。

- **收款**
  - 区块：收款记录表、关联发票、资金账户、金额、收款日期与既有登记操作。
  - 使用：记录实际到账；不用：把计划收款、开票或未收金额记为现金。
  - 空态/缺口：显示“暂无收款 / 登记收款”；缺账户或未关联发票按业务规则标注，不自动补值。

- **资金账户**
  - 区块：账户列表与余额；账户流水表，包含日期、摘要、收入、支出、余额和来源。
  - 使用：核对实际账户与流水；不用：在前端按单笔录入假算服务端余额。
  - 空态/缺口：显示“暂无资金账户”或“暂无流水”；余额未同步时给缺口状态与既有恢复入口。

- **8 周计划**
  - 区块：未收计划、已确认未付支出、每周净额与预计余额；来源链接；过期计划独立分组。
  - 使用：评估未来八周现金安排；不用：混合计划与实际、重复计入同一来源或自动挪动过期周。
  - 空态/缺口：预计余额为负时显示“预计缺口”徽章和金额；计划缺失显示空态，不画零值预测。

### 4.6 设置

目标：集中管理既有成员、成本费率和审计查询，不新增业务审批阶段，不借视觉改造扩展权限模型。

- **成员**：成员、角色、状态与既有管理操作；用于组织成员维护，不用于项目内角色替代；空态给真实可用的邀请或添加入口，无权时只读。
- **成本费率**：成员、费率、生效区间与状态；用于维护人工成本依据，不展示真实工资示例；缺失费率用计数和列表定位，历史记录不被覆盖。
- **审计日志**：对象、操作者、时间、动作与来源筛选及只读记录；用于追溯事实，不用于编辑业务数据；空态保留筛选，日志不可用时明确错误而非显示“无日志”。

## 5. 数据与经营表达

### 5.1 数据口径与格式

- 金额在服务和存储层使用整数分，工时内部使用整数分钟；界面格式化不得改变精度或触发二次计算。
- 金额使用统一币种、千分位和既有小数规则；负值使用真正的负号并右对齐，不用红色单独表达盈亏。
- 工时输入与汇总显示小时，单条输入 0.1–24h；分钟转换、舍入和校验遵循业务契约。
- 费用确认成本、付款确认现金；同一支出在计划、成本与现金视图中按来源去重，不重复计。
- 计划不等于实际，过期计划不自动挪周；净现金流不等于利润，也不等于银行余额。
- 缺数据、缺费率、未确认或不可计算时显示“—”与缺口徽章；只有真实零值才显示 0。

### 5.2 筛选

- 时间、项目、状态等主筛选直接显示，次要条件放入“更多筛选”可展开区域。
- 筛选控件始终有可见标签，不用 placeholder 代替；生效条件以可移除条件文本或徽章呈现。
- 提供明确“查询”和“清除”操作；自动筛选时不得造成焦点丢失或整页跳动。
- 空结果保留筛选条件、结果计数和清除入口，不把筛选空伪装成系统初始空。
- 筛选、排序、分页与导出只暴露后端真实支持的能力，不制作无功能控件。

### 5.3 表格与可展开行

- 列按“对象 → 业务属性 → 状态 → 金额/日期 → 操作”组织；首要对象使用行表头 `th scope="row"`。
- 桌面行高约 **44px**，表头 12–13px/600，单元格内容 12.5–13px；使用细分隔线，不使用斑马纹。
- 金额、数量、工时右对齐并使用等宽数字；文本左对齐；操作列位于语义末尾且关键操作不只 hover 可见。
- 长文本优先截断并提供可访问完整名称；关键缺口、错误和状态不得被截成不可理解符号。
- 可展开行使用独立按钮，设置 `aria-expanded` 与 `aria-controls`；展开区放定义列表或关联记录，不嵌入另一套完整页面。
- 排序按钮写出当前方向；分页、加载和展开不得导致键盘焦点丢到页面顶部。
- 窄屏优先转为带字段名的行卡，字段顺序与桌面一致，金额仍右对齐或按标签—数值对齐。
- 只有周矩阵等无法合理转卡的结构允许局部横滚；滚动仅发生在表格容器内，并提供可见提示和键盘可达性。
- 表格容器不得撑宽页面；首列或操作列是否固定必须保证焦点环和触控目标完整可见。

### 5.4 摘要、缺口与状态

- 工作台和现金流概览使用 **4 张等宽指标卡**；工作台在指标卡后接白色资金账户余额条。
- 指标卡只含标签、数值、必要单位或极短状态，不放副标题、公式、趋势解释长句。
- 资金条显示现金余额与 8 周预计缺口；预计值必须写“预计”，不得伪装成实际余额。
- 缺口计数靠近所属指标、行或分组，如“缺费率 2”“未开票 1”；点击只进入真实来源。
- 状态徽章统一为“图标/形状 + 中文”：成功用勾、警告用三角、错误用叉、进行中用圆点、草稿用空心形状。
- 信息、成功、警告、危险、中性五类语义不得互换；项目进度、付款状态、发票状态分别使用各自业务文案。
- 不得只靠红绿、箭头或圆点表达结果；徽章文字不得缩写成无意义单字。

### 5.5 趋势图

- 只使用原生 SVG 和本地样式实现折线或柱形，不引入图表库、远程脚本或画布依赖。
- 图表标题附近标明单位、时间区间、业务口径与来源；图例、坐标和精确值均可读取。
- 多系列除颜色外，再用实线/虚线、不同点形或纹理区分；余额存量与收支流量不得误导性叠在同一尺度。
- SVG 提供 `title` 与 `desc`，相邻数据表提供精确值；键盘和读屏用户不必依赖悬浮 tooltip。
- 柱形使用真实零基线；缺失区间断点呈现，不连接成假的连续趋势。
- 空数据、加载失败和无权限分别显示对应状态，不画全零线，不使用演示数据代替真实结果。
- 禁用面积渐变、3D、无意义动画和自动轮播；趋势图不是每个页签的必配装饰。

## 6. 表单、审批与反馈

- 表单按业务逻辑分组，标签在控件上方；必填项同时使用“必填”文字与星号，星号不能成为唯一提示。
- 不用 placeholder 充当标签；金额、日期、工时和单位紧邻控件，帮助文字保持一句且仅在必要时出现。
- 字段错误就地显示，通过 `aria-describedby` 关联；控件设置 `aria-invalid`，提交后聚焦错误摘要或首个错误。
- 错误摘要列出可定位到字段的错误链接；保留所有合法输入，不因服务端失败清空表单。
- 长表单操作区可吸底，但必须为内容预留空间，不遮挡字段、错误摘要和焦点环。
- 保存中防止重复提交并保留按钮宽度；成功后用 `role="status"` 反馈，重要失败用 `role="alert"` 且不可只自动消失。
- 取消有修改的表单时按既有规则确认；并发冲突提供重新核对路径，不静默覆盖他人修改。
- 审批页顺序固定为 **申请事实 → 证据 → 审批记录 → 意见与操作**；金额、期间、提交人和来源先可核对。
- 通过、退回、驳回使用不同明确文字；危险或不可逆操作按后果确认，并保留真实审计记录。
- AI 建议只作为候选内容，必须可编辑、可忽略并标明来源；不得获得审批通过外观、默认选中或操作特权。
- 权限禁用不仅置灰：若控件可见，应提供不可用原因；无权限操作不得暗示已经执行。

## 7. 空态、加载、错误与不可用

| 状态 | 触发条件 | 文案与呈现 | 可用操作与下一步 |
| --- | --- | --- | --- |
| 初始空 | 无筛选且确实没有记录 | 简短对象名，如“暂无项目”；不用插画和长说明 | 有权限时给“新建项目”等一个主下一步 |
| 筛选空 | 有数据但当前条件无结果 | “没有符合筛选条件的记录” | 保留条件，提供“清除筛选” |
| 无权限 | 用户无权查看对象或数据 | “暂无查看权限”或业务规定文案，不泄露敏感内容 | 返回可用页面；不展示伪造操作 |
| 加载 | 数据请求或提交尚未完成 | 骨架或“正在加载”，保持既有尺寸和布局 | 防止重复提交；不把空白当空态 |
| 可重试错误 | 请求失败、超时或服务异常 | 简述失败对象，不使用技术堆栈 | 提供“重试”，保留筛选和表单输入 |
| 字段错误 | 输入未通过校验 | 字段旁给出具体修正要求 | 聚焦并修改字段，已填内容不丢失 |
| 不可用 | 功能被权限、状态或依赖禁用 | 说明短原因，不仅降低透明度 | 给真实恢复入口；无入口时保持只读 |

- 空态只允许标签级短句与一个下一步，不附加产品教学、指标定义或营销文案。
- 骨架屏使用稳定块面，不闪烁、不无限加载； reduced-motion 下取消 shimmer 等动画。
- 页面局部失败不应清空其他已成功区域；错误边界尽量落在对应面板。
- 重要失败、冲突和不可恢复错误必须持续可见，直到用户处理或离开当前任务。

## 8. 响应式与可访问性

### 8.1 断点与必检宽度

| 断点 | 布局要求 |
| --- | --- |
| 320–389px | 最小支持宽度；单列、16px 留白，内容不裁切、不整页横滚 |
| 390–639px | 抽屉导航、页签容器内横滚、表单单列、表格优先转行卡 |
| 640–767px | 可增加双列表单或指标列，但不得提前恢复桌面侧栏 |
| 768–1023px | 复杂双栏改单栏；侧栏按空间折叠为抽屉，主操作保持可见 |
| 1024–1439px | 恢复 240px 侧栏；指标与双栏按实际宽度重排，避免拥挤 |
| 1440px 及以上 | 完整桌面基线；内容最大宽度 1440px，不无限拉伸 |

- **1440px、390px、320px 为每次迁移必检**，同时检查 640/768/1024 附近及中间任意宽度。
- 断点只改变布局，不改变字段、金额、状态、权限、默认页签或业务含义。
- 页面在 200% 文字缩放下仍可操作；允许增高、换行和转单列，不通过裁字保持原高度。
- 长项目名、长中文标签、大金额、空态和错误摘要必须纳入溢出检查。

### 8.2 键盘、读屏与视觉可达性

- 正文与背景对比度至少 **4.5:1**；大文字至少 3:1；控件边界、关键图形和焦点指示至少 **3:1**。
- 所有功能支持键盘；Tab 顺序符合阅读顺序，Enter/Space 激活相应控件，Escape 关闭浮层。
- `:focus-visible` 使用 **2px 品牌蓝焦点环**，外偏移至少 2px，不得被卡片、页签或表格滚动容器裁切。
- DOM 顺序与视觉顺序一致；不得用 CSS `order`、绝对定位或表格重排制造不同的读屏顺序。
- 图标按钮有可访问名称；装饰 SVG 使用 `aria-hidden="true"`，状态徽章文字可被读屏直接获取。
- 弹窗与抽屉管理初始焦点、焦点约束和关闭后的焦点恢复；背景内容不可误触。
- 动态成功消息使用适当 live region；避免重复播报整表、计时器或无变化数字。
- 尊重 `prefers-reduced-motion`：关闭非必要动画与平滑滚动；状态理解不得依赖动画。
- 动效仅用于反馈，常规时长 120–180ms；不使用循环脉冲、自动滚动或大面积过渡。
- 触控目标至少 44×44px，目标之间保留足够间距；窄屏不以密集图标按钮替代清晰操作。

## 9. 去注释化写作规则

产品页面只保留 **标签、数值、状态徽章、缺口计数、操作、空态下一步** 及完成任务所必需的字段提示。规范文档可以解释规则，产品页面不得把规范说明复制成界面正文。

**禁止：**

- 页面副标题、卡片副标题、经营口号、大段英文眉面和重复模块说明。
- 公式小字、指标定义段、重复口径脚注、表格底部解释性长文。
- “这里可以……”“帮助企业……”“通过以下步骤……”等教学或营销句。
- 用 tooltip 永久隐藏关键错误、权限原因或必须理解的财务差异。
- 在每个指标、每张表、每个页签重复同一条口径说明。

**允许：**

- 精确字段名、单位、日期区间、结果计数、状态、缺口与操作动词。
- 一句字段级输入要求或校验错误，如“小时需为 0.1–24”。
- 初始空和筛选空的短句与一个下一步。
- 必要财务差异只使用极短短语，如“合同额≠收入”“毛利≠现金净额”，且同一页面每处口径只出现一次。

| 场景 | 坏示例 | 好示例 |
| --- | --- | --- |
| 页面文案 | “从交付到回款，掌握项目经营全过程。” | “工作台” |
| 表格缺口 | “由于部分历史工时未配置费率，以下成本可能偏低。” | “缺费率 2” |
| 指标口径 | “毛利是收入扣除人工和费用后的结果，不等于现金。” | “毛利≠现金净额” |
| 初始空态 | “还没有任何内容，赶快开始你的数字化管理之旅吧。” | “暂无项目 / 新建项目” |
| 筛选空态 | “暂无数据”并隐藏全部筛选 | “没有符合筛选条件的记录 / 清除筛选” |
| 表单帮助 | “请输入一个合理且有效的小时数，注意不要超过限制。” | “小时需为 0.1–24” |
| 状态说明 | 仅显示绿色圆点或“正常” | “✓ 已完成”“△ 待确认”“× 已逾期” |
| 加载失败 | “发生未知错误，请稍后再试。”并清空输入 | “保存失败，输入已保留 / 重试” |

## 10. 模式扩展与冻结规则

- 后续改造必须先读本文件与 `frontend-standards.md`，复用 `ui-tokens.css` 和 `ui-specimen.html` 的共享模式。
- 禁止页面私有十六进制色值、临时字体、远程资源、重复页头、重复页签和一次性交互实现。
- 现有模式能够表达时不得新增模式；新增模式必须说明适用场景、状态、响应式和可访问性行为。

- **配色**：A 方向蓝白极简替换旧奶油底与深绿侧栏；统一为 240px 白侧栏、`#F7F9FD` 画布和 `#2563EB` 品牌蓝。

- **结构完整化**：明确工作台、项目详情、工时、费用、现金流、设置的固定页签与各自空态、缺口和使用边界。
- **工时单位**：填报与汇总显示小时，单条输入 0.1–24h；内部仍以整数分钟记账，不以显示单位改变存储精度。
- **去注释化**：删除页面副标题、卡片副标题、公式小字与长说明，只保留短标签、数值、状态、计数和空态下一步。
