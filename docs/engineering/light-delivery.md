# 轻交付协议（light delivery）

状态：2026-11-03 起生效，取代按切片多段 PR 的重流程。历史规划/验收材料在
[docs/archive/v1.0-planning/](../../docs/archive/v1.0-planning/README.md) 只读保留，不再是开工依据。

## 0. 只看六个入口

| 文件 | 回答什么 |
| --- | --- |
| [docs/product-scope.md](../../docs/product-scope.md) | 1.0 产品范围：目标用户、核心链路、简化口径、保留/简化/移出清单与发布标准 |
| [project/QUEUE.md](../../project/QUEUE.md) | 1.0 剩余范围的唯一有序清单：下一条做什么、验收检查、演示方式、映射的历史 PH 与 V1 需求 |
| [project/STATUS.md](../../project/STATUS.md) | 现在能做什么、还缺什么（一页） |
| [project/ACCEPTANCE.md](../../project/ACCEPTANCE.md) | 当前候选的验收清单与模板（一页） |
| [project/DECISIONS.md](../../project/DECISIONS.md) | 已定的产品/工程决定，避免重复讨论 |
| 本文件 | 交付怎么做：队列、票据、PR、复核、合并、节奏、失败与停止规则 |

`project/tasks.json` 只作历史台账（331 条旧任务，编号不复用）；不再新增任务、不再要求 per-task report/handoff。

## 1. 一条需求 → 有序成果队列

1. 用户给出需求。维护者把需求拆成 1–N 个**用户可观察成果**，按"发布门禁价值 → 业务价值 → 依赖解锁"排进 QUEUE.md。
2. 每条成果有唯一 `Q-nn` 编号、波次、3–5 条验收检查、演示方式、映射的历史 PH 与 V1 需求编号。
3. 队列顺序即开工顺序。同一波次最多 2 条在制；需要并行时只能动互不覆盖的成果。
4. 队列只增不改历史：完成后把条目改成 `状态：已交付`；范围变化时新增条目并在 PR 说明理由，不重写已完成条目。

## 2. 一条成果 = 一个票据 = 一个 PR

票据就是 QUEUE.md 里的一条，不另建规划/契约/收口单。

**票据模板**（写进 PR 描述即算票据，不需要另建文件）：

```text
Queue: Q-nn
（过渡期可同时保留 Task: PH-nnn；两者都只允许各一行）

## 成果
用户从哪个入口完成什么操作、看到什么结果。

## 验收检查（3–5 条，逐条写真实结果）
- <来自 QUEUE 条目，逐条 pass/not_run/blocked + 证据>

## 演示
命令或浏览器步骤 + 截图/录屏/命令输出。

## 证据
命令与退出码、测试、CI run、独立复核结论。

## 风险与未验证
剩余风险、未验证项、需要谁决定。
```

约束：一个 PR ≤1 天工作量、生产代码 ≤约 300 行（测试、迁移、文档不计入但必须同 PR）；跨模块契约变化写成 ≤1 页设计说明放进同一个 PR，不单独开契约 PR。

## 3. PR 规则

- 分支 `feat/Q-nn-short` 或 `fix/Q-nn-short`；base 为 `main`；禁止推 main、禁止强推 main、禁止改写已发布标签。
- PR 标题沿用 `docs(...)`/`feat(...)`/`fix(...)` 前缀；body 顶部保留自动化徽章行
  "This is by an automated agent, not a human."，随后是票据模板内容。
- 每个 PR 自带证据：代码 + 测试 + 必需 CI + 一条真实演示（UI 变更必须是浏览器或真实命令演示，不接受"配置存在"）。
- 迁移只新增、不改已应用迁移；同时最多两条产品主线；共享写域串行。
- 不做规划 PR、契约冻结 PR、收口 PR、状态更新 PR。报告/交接/合并 SHA 随原 PR 或下一次必要变更完成。

## 4. 复核规则

- 每个 PR 恰好一次独立复核，覆盖：正确性、金额与权限不变式、测试有效性（测试是否真能失败）。复核人不能是作者，不能自批。
- 复核只看当前 HEAD；旧的通过结果不覆盖新提交。有未解决 finding 不合并。
- 财务/权限/期间/迁移相关变更额外要求：拒绝路径（越权、跨租户、锁期、超额、重复）有真实测试，不以 SQLite 冒充 PostgreSQL 并发。
- 复核结论写进 PR 评论（复核人、HEAD SHA、结论、finding）。不需要单独 reviews 文件。

## 5. 合并条件

一个 PR 只有同时满足下列条件才合并：

1. 9 项必需检查全绿：`CodeQL (javascript-typescript)`、`CodeQL (python)`、`Container smoke`、`MCP protocol`、`SQLite domain`、`PostgreSQL domain`、`Public hygiene`、`Project governance`、`Delivery arbitration`。
2. 独立复核通过且作用于当前 HEAD。
3. 可合并（mergeable）且按线性历史合入；未解决讨论为零。
4. PR body 恰好一条 `Queue: Q-nn`（过渡期可用 `Task: PH-nnn`）。

**没有人工合并步骤。** 维护代理在必需检查和复核通过后开启自动合并：

```sh
gh pr merge <n> --auto --squash --match-head-commit <sha>
```

- `--match-head-commit` 绑定被复核的 SHA：复核后若 HEAD 变化，自动合并失效，需重新复核。
- 被复核的提交就是被合并的提交（squash 到 main 的那一个），不再追加"合并后"补丁。
- 自动合并只由维护代理开启；执行代理不合并、不开启 auto-merge、不改保护规则。

## 6. 验收节奏

- **每个 PR**：上面第 3、4、5 节的证据与复核。
- **每两周一个候选（release candidate）**：一次真实环境走查 + 一份 [ACCEPTANCE.md](../../project/ACCEPTANCE.md) 清单。走查只写真实结果：pass / not_run / blocked + 证据；缺环境写清前提。
- **发布资格**仍按 gate 判定，不用文档或配置替代运行证据；L3（CI/PG）、L4（浏览器）、L5（真实环境/客户）分层记录，低层不冒充高层。
- 候选走查发现的缺陷：记入 QUEUE.md 新增条目或原条目追加检查，不另开"验收 PR"。

## 7. 失败 → 新票据循环

1. CI 红、复核 finding、演示失败：修在本 PR；修不完就缩小 PR 到能交付的最小成果。
2. 问题超出当前条目范围：关掉当前 PR 或缩范围，在 QUEUE.md 新增一条成果（写清阻塞原因与解除条件），下一轮做。
3. 连续 3 个 PR 没有带来可演示能力或真实验收证据：停止扩展，先解除一个具体阻塞。
4. 需要用户判断（产品口径、范围、花钱、对外承诺）：写进 DECISIONS.md 的"待定"，在 PR 里点名要谁决定，不反复确认技术细节。

## 8. 停止规则

出现下列任一情形，停下来，不继续扩范围：

- 队列里没有能带来可演示成果的条目，只剩文档/配置工作。
- 三个连续 PR 没有新增可演示能力或真实验收证据。
- 需要越权实现（改产品口径、改财务规则、扩范围绕过 gate）。
- 环境缺失且没有明确解除条件（真实域名、PG、客户验收）。
- 发现真实客户数据/凭据进入仓库或代理上下文。

## 9. 不可让步的底线

轻量的是流程，不是正确性。以下条款任何 PR 都不放宽：

- **财务不变式**：金额整数分、工时整数分钟、Decimal、ROUND_HALF_UP、禁 float；费率按业务日期快照；成本与现金不重复记；账本/审计只追加，纠错用负值冲销；不关闭触发器、不直接改余额。
- **权限与期间**：服务层统一做租户/项目/角色/期间/状态/来源检查；过期未执行计划单列；锁期、未来日期、自审、超额核销的拒绝路径必须存在且被测试。
- **迁移**：只新增迁移；不原地修改已应用迁移；生产并发结论只能来自 PostgreSQL。
- **必需 CI**：9 项必需检查、线性历史、可合并、独立复核规则由 `project/delivery-policy.json` 与 BASE 门禁强制，不因流程简化而减少。
- **独立复核**：每个 PR 一次，作用当前 HEAD，作者不得自审。
- **安全**：不使用真实客户/工资/凭据；不引入共享管理密钥；不把示例或演练数据写入正式账；不自动发布、不打标签、不改分支保护。

## 10. 与旧流程的对应

| 旧 | 新 |
| --- | --- |
| 规划入口 PR + 契约冻结 PR + 实现 PR + 收口 PR | 1 个 PR（票据 = QUEUE 条目） |
| 12+ 状态/验收/发布文档、每切片五层矩阵 | 4 个活文档 + 每两周一份 ACCEPTANCE 清单 |
| per-task spec/report/handoff 三件套 | PR 内票据 + 演示 + 复核评论 |
| 331 条任务台账驱动 | QUEUE.md 有序成果驱动（tasks.json 只读历史） |
| 人工合并 | 维护代理 `--auto --squash --match-head-commit` |

门禁脚本只做必要调整：交付门禁接受 `Queue:` 行（同时继续接受 `Task:` 过渡），其它治理要求不变。
