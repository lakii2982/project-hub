# 项目管理产品业务需求

任务ID：PMO-DESIGN-01  
版本：1.0；日期：2026-10-22  
适用对象：面向中国大陆、100人以下公司的项目管理产品。本文定义业务行为与验收，财务计算以同目录 `accounting-rules.md` 为准。

## 1. 已确认约束与产品目标

以下为已确认条件，不再作为可选假设：

1. 首批业务为软件开发、实施与技术服务，以项目为管理与核算中心，覆盖机会到售后和归档。
2. 财务范围仅为项目财务，包括预算、工时成本、费用、经营收入、应收应付、收付款和现金预测。产品不承担企业完整总账、法定报表、纳税申报、个税计算和工资代发。
3. 假定客户没有财务信息化系统和OA。所有本产品需要的信息必须能在系统内新增、审核、导入、查询和纠错；任何核心流程不得以“等待ERP/OA同步”为前提。
4. 自有服务器或云主机部署，浏览器使用。首版是有持久数据、权限、审批和结算闭环的可用产品，不能用静态页面或浏览器内临时状态代替。
5. 首版技术方向为Django ORM、Auth、Forms、迁移与服务层；SQLite用于本地，PostgreSQL用于生产。本文不限定架构实现细节，但要求业务状态迁移、金额和权限在两种数据库下结果一致。
6. AI辅助真实业务操作；低成本模型能够通过边界清楚的任务、结构化输入和确定性规则稳定参与。付款、审批通过、费率生效、锁账等动作不能由模型输出直接执行。

产品目标是让负责人在一个项目中回答：交付到了哪里、还要花多少钱、账面赚多少、现金何时进出、谁需要采取行动，以及这些数字来自什么业务证据。

## 2. 业务假设与上线前决策

以下为设计默认值，不能当作任何客户的既有事实。租户初始化时必须展示、确认并保存版本。

| 编号 | 首版默认 | 待定事项与影响 |
| --- | --- | --- |
| D01 | 一个租户对应一个核算主体；本位币人民币；时区Asia/Shanghai | 多法人集团与合并报表留待后续；主体不能在已有凭证后直接更换 |
| D02 | 管理收入不含销项税；项目成本不含已确认可抵扣进项税 | 纳税人身份、抵扣资格、合同计税条款必须由客户填写；系统不猜测税率 |
| D03 | 软件和实施以人工确认的履约/验收依据确认管理收入；技术服务支持工时或固定服务期 | 确认依据、金额、合同上限和客户争议处理需要财务与业务共同确定；不是法定收入政策自动判定 |
| D04 | 人力成本按月度标准完全人工费率快照×已批准工时分配 | 实际薪酬差额是否分配、有效工时口径、奖金归属月由租户确认；不默认把全部工资强摊给客户项目 |
| D05 | 固定顺序审批链起步；支持项目负责人、财务复核、授权人三个节点及金额条件 | 代理审批、阈值、退款和银行付款复核人上线前配置；禁止自审规则不能关闭 |
| D06 | 单项目可有多合同/订单、多个工作包；合同明细可标记三类业务 | 首版同一合同明细/服务记录只采用一种主收入计量方法，切换方法必须变更，不能把历史工时重算两遍 |
| D07 | 无期初数据时必须由财务显式确认“从零开始” | 有存量项目时录入截止日余额与来源，不得把缺数据显示成零 |
| D08 | 按月锁账；工时粒度为整数分钟；金额以最小货币单位整数持久化 | 工时最小录入步长默认15分钟、每日异常阈值、逾期审批天数可配置并留版本 |

实际税率、社保公积金比例、客户付款周期、售后期限、加班补偿方式均未知；不预填为客户事实。关键待定项未确认时可使用演练数据，禁止生成声称可结账的正式结果。

## 3. 范围与交付顺序

### 3.1 首版必须形成的纵向闭环

首版按下列顺序实现，每个切片都需真实落库、权限检查、异常处理和自动化业务测试：

1. **建立项目**：租户、成员、客户、机会、合同及三类模板；项目立项与初始预算基线。
2. **交付和成本**：工作包、任务、里程碑、工时填报审批、薪酬/费率输入、人工成本快照；采购验收、外包服务确认、费用报销。
3. **项目结算**：合同付款计划、管理收入确认、应收应付、发票登记、收付款及部分核销、退款、质保金、期初数据。
4. **项目经营**：预算变更、ETC/EAC、预算偏差、项目现金流水和13周预测、暂停取消、售后、结项与归档、月度锁账和冲销。
5. **低负担辅助**：可预览和纠错的CSV导入、证据链、异常队列、基础AI提取/摘要/风险提示；AI服务不可用时上述流程完整可操作。

不以切片上线替代整体交付验收。首版必须完整支持第15节三类端到端场景。

### 3.2 首版明确保留的边界

首版提供单主体项目管理账、手工汇率、多币种原币收支及人工汇兑记录、基础合同附件和人工里程碑验收。工资只录入项目核算所需汇总与费率基础，不建设员工劳动合同、人事考勤和薪税系统。

未来能力：法定总账与申报、银行直连及自动付款、复杂合同履约义务分摊、自动合并报表、多法人跨主体结算、实时报价汇率、复杂资源排程、库存资产/折旧引擎、电子签章、完整工单台、可编程审批引擎、客户供应商门户及ERP/OA连接器。连接器只是补充输入渠道，不能替代内置入口。

## 4. 用户、权限和租户边界

### 4.1 角色与字段级授权

角色可以组合；“角色允许”与“项目成员范围允许”同时成立才可访问，财务专用字段另行校验。角色变更即时生效，已完成审批保留当时身份快照。

| 角色 | 可操作范围 | 默认不能做的事 |
| --- | --- | --- |
| 租户所有者 | 初始化、成员、角色、审批与会计参数；查看经营汇总 | 不因拥有租户就自动获得个人工资明细或付款审批权；通过显式财务授权取得 |
| 业务负责人/销售 | 自己负责的机会、客户、报价、合同草稿、回款跟进 | 修改已批准成本、工资明细、银行流水或财务结账 |
| 项目负责人 | 授权项目计划、预算草稿、任务、工时初审、验收申请、ETC、项目经营汇总 | 查看个人工资明细、批准自己的工时/报销、改已入账金额、执行真实付款 |
| 成员 | 参与项目任务、自身工时和报销、本人单据状态 | 其他项目与他人工资、费率、客户全量合同价；经授权才见汇总 |
| 财务录入员 | 项目财务单据、工资汇总/费率草稿、税额、发票、银行/现金收支、匹配建议 | 复核本人录入的正式财务凭证、越权解锁、替业务确认交付 |
| 财务复核员 | 财务凭证复核、核销、费率批准、对账、锁账申请 | 自审、篡改已过账来源、替付款授权人授权 |
| 付款/重大事项授权人 | 在授权额度内批准付款计划、退款、预算和取消决策 | 因批准付款计划就自动写入实际银行支付结果 |
| 审阅者 | 授权项目的只读视图、审计与导出；可区分是否有敏感财务权限 | 修改、审批、导入提交 |
| 平台运维 | 租户状态和系统运维元数据 | 默认读取租户合同、工资、附件；例外支持访问须限时、授权、留审计 |

工资明细、费率、项目利润、银行账号、身份证明、供应商账户分别授权；只授权看项目总成本时，API、导出、搜索、AI上下文及通知均不得泄露个人工资/费率。首版不开放跨租户共享员工、客户、合同或费用。

### 4.2 分权和小团队替补

- 单据提交人不能审批本人单据；代他人录入时保留实际申请人和录入人，二者均不能担任最终财务复核人。
- 业务验收与财务复核分开：项目负责人证明服务已发生，财务检查金额、归属、税额和付款。
- 至少两名真实授权人员才能正式过账、退款和锁账；单人租户可准备草稿和演练，不能用同人多账号绕过分权。
- 临时代理必须指定代理人、范围、期限和原因；审批时重新检查代理与自审冲突，不自动把待办授予任意管理员。
- 审批配置不足时单据进入“待指定复核人”，不能默认为通过；任免/停用员工不删除其历史工时和审批证据。

### 4.3 多租户隔离验收

所有业务记录、附件、审计、导入批次、后台任务和AI结果绑定租户；项目ID与租户必须一起解析。表单选项、搜索建议、导出、下载签名、缓存、报表、异步任务和AI检索都按租户授权过滤。不能仅在页面隐藏按钮。

验收：A租户成员持有B租户真实项目/附件/导入批次ID，读取、修改、导出、枚举和异步重跑均失败，返回不暴露对象存在性的结果；B租户数据和审计不被A的操作改变。同名客户、相同业务单号、相同导入外部ID可分属不同租户。禁用用户的旧会话不能继续提交审批。

## 5. 内置入口与最低录入负担

### 5.1 导航与责任

| 入口 | 必须能输入的数据 | 降低负担的默认行为 |
| --- | --- | --- |
| 首次启用向导 | 主体、本位币、人员角色、月历、费率口径、审批人、期初截止日 | 提供三类模板；只问必填条件；未设置项进入设置待办 |
| 我的工作台 | 周工时、任务进展、报销、验收申请、待审批 | 只列参与项目；复制上周项目与任务，不复制实际工时 |
| 客户与机会 | 客户、联系人、机会金额、概率、预计签约日、下一步 | 客户可在机会/合同页就地创建，按租户提示疑似重复 |
| 项目工作台 | 工作包、任务、里程碑、负责人、交付证据、售后期限 | 模板创建，允许精简任务；计划与财务数据联动但独立状态 |
| 合同与变更 | 合同明细、不含税/含税价、税额、币种、收付款条件、质保约定 | 付款计划按比例生成后预览分币差；保存原合同与变更版本 |
| 人员与成本月历 | 薪酬成本组成、企业承担社保公积金、有效工时、月度费率、加班 | 表格批量录入、复制上月待确认；可仅使用已批准费率，不强制上传工资单 |
| 采购与费用 | 供应商、采购/外包、验收、费用归属、发票、报销、员工借支、预付服务分期 | 一个工作台分步完成；一次服务验收可关联多个项目分摊 |
| 项目结算台 | 收入确认、应收应付、发票登记、核销、预付款、质保金 | 从合同/验收生成草稿；不凭生成草稿直接过账 |
| 资金流水台 | 银行/现金账户、交易日、原币金额、对方、方向、流水标识、费用 | 手工录入与CSV导入；可拆分匹配，多余金额保留未分配 |
| 月末检查台 | 缺工时/费率/汇率/票据、对账差异、计提/冲销、锁账 | 按阻断/待处理分类，一键跳到原单；不创建伪数据补齐 |
| 数据导入与异常 | 期初、成员、工时、费用、结算、现金的CSV预览与纠错 | 下载字段模板、枚举说明、示例金额；逐行显示错误和来源 |

每项核算信息必须至少有手工表单；批量入口为补充。首版不以OCR作为唯一输入方式。附件不是必需字段的替代：金额、币种、日期、项目、税额、交易对手必须为结构化数据。

### 5.2 表单和日常使用验收

- 工时常用字段：日期、项目、任务或工作包、时长、工作类型、简短说明；同日批量填写，周视图提交；缺有效费率时允许业务审批但不允许成本过账。
- 小额无采购单费用可从报销直接创建；大额/外包是否必须事前申请由租户阈值决定，不能默认所有费用走三张同内容表单。
- 保存草稿不要求全部财务字段；提交时集中展示缺项，错误保留已填内容。重复点击、浏览器重试不产生重复单据。
- 业务表单展示元，注明币种并最多接受两位小数的人民币；API/导入字段区分 `amount_yuan` 与 `amount_minor`，禁止根据数值大小猜单位。
- 所有派生金额可打开“计算依据”：来源、公式、费率/汇率版本、取整分差、审批及冲销。页面中“无数据”“未核算”“金额为零”三者不同。
- 模板继承字段可改，重要规则变更生成版本；从复制记录继承的金额、日期和证据必须逐项确认。

## 6. 业务对象与状态约束

关键对象包括：租户、核算主体、成员及月历、客户/供应商、机会、项目、合同及行、变更单、预算基线、工作包/任务、里程碑与验收、工时及版本、费率快照、采购/服务验收、报销/费用、收入确认、结算项、发票及分配、应收应付未清项、收付款、核销、共享分摊、ETC快照、现金预测、期间、审计事件、附件、导入批次和异常。

业务单号在租户与单据类型内唯一；系统ID不能代替业务幂等键。所有财务来源记录具有：业务发生日、归属期、记账期、项目/工作包、金额与币种、来源和版本、审批状态、过账状态、制单/复核人、创建时间及冲销关系。

首版单据状态统一使用：草稿→已提交→业务已确认（如适用）→待财务复核→已过账；驳回返回新草稿版本；撤回只能发生在尚无最终生效动作时。审批实例绑定内容哈希/版本，审批后修改金额、币种、项目、日期、税额、账户或证据需重新审批。已过账单据只能冲销或追加更正。

### 6.1 最小业务字段契约

以下字段组为业务契约，具体表结构由架构实现；字段值不能仅塞在附件或AI文本中。公共字段包括租户、ID、版本、状态、创建/更新人与时间，财务对象另有记账期、来源键和审批实例。

| 对象 | 必需的结构化字段 |
| --- | --- |
| 合同明细 | 项目、客户、业务类型、计量方法、原币、含税/不含税/税额、上限、履约期间、结算条件、关联工作包、有效版本 |
| 工时 | 员工、业务日期、整数分钟、项目/内部池、工作包、工作类型、加班标志、计费确认分钟、成本覆盖渠道、费率快照ID |
| 费率快照 | 员工、归属年月、成本池或外部核定来源、有效分钟、费率十进制字符串、含加班标志、计算规则版本 |
| 成本来源 | 费用类别、发生/耗用日期、交易对手、合同/验收/报销引用、原币金额及税拆分、分摊范围、现金是否已发生 |
| 未清项 | 应收/应付/预收/预付类型、项目、交易对手、原币、初始原币与本位币金额、到期条件/日期、质保属性、业务来源 |
| 现金交易 | 账户、银行来源标识、交易日期、收付方向、币种与原币毛/净金额、手续费分解、汇率、待匹配状态、项目分配 |
| 核销/抵扣 | 双方来源ID、各自币种与可用额、本次原币及账面本位币额、汇兑差、确认人与版本、解除关系 |
| 预算/ETC项 | 项目、工作包、成本类别、期间、数量与单价、金额、基线/预测版本、来源、承诺/未入账/风险互斥分类 |
| 核算事件 | 类型、来源ID/版本、方向、金额及币种、本位币金额、归属/记账期、有效/冲销关系、计算入参引用 |

余额、AC/EAC和利润是派生读模型，不能接受用户直接编辑。所有敏感金额字段的读取授权与写入授权分别定义。

## 7. 项目生命周期

### 7.1 机会、立项与基线

机会状态：线索→资格确认→方案/报价→谈判→赢单/输单/搁置。机会金额和加权金额只属于销售预测，不属于合同收入或应收。赢单可生成项目和合同草稿；正式立项由授权人批准，生成唯一项目编号。

允许签约前立项，但必须标记“预售/风险投入”、负责人、投入上限和到期复核日。预售成本保留来源；转正式项目时重归属同一成本记录，不再复制成本。立项前已发生的可归属成本通过期初或补录进入，不能回填虚假工时。

初始预算按工作包/成本类别/月份编制；签批后形成B0。预算、合同额和收款计划各自独立；项目有预算不代表已签合同。无合同项目的收入和收款计划必须显式为待定。

### 7.2 执行、里程碑与验收

项目运行状态：草拟→待立项→执行中→交付完成→售后中→已结项→已归档。暂停和取消为独立受控分支；财务结清状态独立于交付状态。

里程碑分计划日期、实际提交日、客户验收日、付款条件满足日；可以有关联但不能等同。验收可为全部、部分、驳回，必须附交付范围、数量/金额依据和客户确认记录。负责人标“完成任务”不能自动形成客户验收、收入或应收。

验收生效后按合同条件生成收入确认、结算项或应收草稿；各自显示依据，重复生成应命中同一来源键。退回验收必须评估下游收入/应收/收款影响，存在下游时走更正链，不直接清除历史。

### 7.3 暂停、恢复与取消

- 暂停单注明原因、起始日、预计恢复日、允许发生的保全/售后支出、人员与供应商承诺处理；暂停期间禁止普通交付工时新增，授权保全工时单独分类。
- 恢复需确认人员、预算、里程碑和现金预测变更，保留暂停段，不自动顺延合同付款条件。
- 取消单包含停止日期、已发生成本、未履约采购、可退预付款、客户退款、已确认收入/应收的处理和证据。取消后冻结新增普通任务，不删除历史数据，不自动冲销全部收入与成本。
- 取消项目仍可发生有依据的解约、退款、清算和售后单据；需要专门权限及取消后费用类别。业务终止与财务清算完成分开记录。

暂停/取消的工时限制按实际业务发生日判断。此前已发生、延迟录入的工时或费用仍可经专门复核补记，保留原类型和历史日期；不能为规避状态限制伪填为取消后费用，也不能因项目暂停就漏记已发生负债。

### 7.4 变更

范围、合同价、时间、人员、里程碑、预算和计量方式的重大变更必须建变更单：旧值、新值、生效日、成本/收入/现金影响、外部确认、审批人。报价中/待客户确认的变更只进情景预测，不增加已批准合同额、预算或应收。

批准后生成合同版本和预算Bn；旧版本不可覆盖。已有工时、成本、收入、核销不因未来变更自动重算。追溯生效的变更须列出更正凭证和期间影响，锁账月份通过开放期调整。

### 7.5 售后、结项与归档

交付完成可进入售后，保修工时和支出归入原项目售后工作包，并计入原项目实际成本及EAC。超出原合同的付费技术服务新建合同明细或关联项目，避免把新收入塞进免费保修。

结项检查：交付/取消手续完成、工时费用无未决、ETC清零或经批准结转、供应商承诺已释放/结转、应收应付与预收预付有处置方案、质保金与售后责任有后续负责人。允许“业务已结项、财务未结清”，不得显示“已全部结清”。

归档为只读业务视图，附件、审计和结算仍可查；归档时未收质保金可在结算台继续收款。新增售后成本或重大更正需授权重新打开相关工作包并在开放期入账。删除项目仅允许无任何生效业务的草稿；其余按停用/归档处理。

## 9. 工时、人力与费用

### 9.1 工时

工时分项目交付、售后、预售、内部管理、休假等类型。系统只将可归属项目且已批准工时核算到项目；内部管理和休假不伪装成项目投入。任务可不计费但仍有人工成本。

每日总分钟不能超过1440；与请假/加班重叠、超过租户日阈值、跨项目同时计时、未来日期列异常。首版无需实时打卡，手动填报为主；同一自然人跨项目总量统一检查。工时批准后补报或改动产生增量或冲销版本；原记录不覆盖。合同可计费小时由另一个确认字段确定，不能把所有成本工时直接开单。

加班必须标记是否已包含在费率中、额外补偿成本来源及审批；调休不自动生成加班工资。系统不自行判定合法加班倍数。

### 9.2 人力费率与外部成本

费率入口支持“人工成本组成+有效工时自动计算”和“外部核定费率手工输入”两种来源，均需财务批准。月度快照绑定员工、费用组成、有效分钟、精度、币种和生效月；项目负责人只按权限看汇总。

外包按供应商服务验收记成本；即使供应商人员填报工时，也默认只作交付/对客计量，不再乘员工费率入成本。确需按工时计价外包时，由外包合同与服务确认单统一生成一次成本。

采购、报销和共享费用可以无发票先确认已发生的费用，税额处于待确定；票据补齐后更正可抵扣税与成本。未验收采购作为承诺，预付采购款是现金和预付余额，不是当期项目成本。细则与案例见核算规则。

员工出差借支有内置申请、支付、报销抵扣和余款退回入口；已支付借支不能在报销时再全额支付。云资源/许可等预付服务可输入服务起止日及按月/按用量的成本计划，到期由人员确认实际耗用后过账；不把全年预付一次作为当月成本，也不强建资产管理模块。

## 10. 项目财务工作台

### 10.1 必备视图

同一页面提供不同标签及可追溯联动，不混加为一个“项目金额”：

- 合同：原始金额、已批准变更、含税/不含税、未生效变更。
- 经营：已确认管理收入、人工/外包/采购/费用实际成本AC、毛利、毛利率、未核算项。
- 预算：B0、当前批准预算BAC、AC、未结承诺、ETC、EAC、完工偏差和版本。
- 结算：客户结算项、应收、预收、供应商应付、员工报销应付、预付、质保金、逾期与争议。
- 资金：实际流入/流出、净流量、资金缺口、未分配流水、未来13周基准/保守情景。
- 发票：开具/收到/红冲、已分配额、与结算及费用的差异、待补票。

所有视图必须展示数据截止日、记账期间、币种、本位币口径和缺失项数量。“毛利率”在收入为零时为无定义；累计净流入不是利润。收入预测、应收余额、发票余额和现金预测独立命名。

### 10.2 应收应付与资金

应收可以依据合同到期条件建立，不强制先开票；同一结算项不能因开票再建立一份应收。预收、预付支持部分抵扣、退回、跨明细分配；首版跨项目抵扣必须专项审批并提供双方明细，禁止静默挪用。

付款计划批准表示内部授权；银行外部实际操作仍由人员完成。登记实际付款需录入交易日期、账户、币种、金额、对方及凭证。收付款可先存在未匹配状态，再核销；银行实际发生记录不因业务单据待审而被隐藏。

对客户退款和供应商退款必须区分：退预收/预付、退货/折让、核销错配的更正，以及退款产生的银行现金动作。一个“退款”按钮不能默认同时逆转成本、收入、应收和现金。

### 10.3 预算与现金预测

项目负责人至少每月更新剩余人时、外包/采购/费用、售后ETC；预算不自动等于ETC。系统必须提示已验收未入账、待批工时和取消订单等尚未反映在AC中的事项。

现金预测覆盖收款计划、已结算应收、未结采购、应付、工资分配、报销、税费及质保金的预计日期；同一来源升级后替换旧预测，不叠加。实际收付款替代同一预测的已执行部分，剩余部分仍留在预测。机会只进单独销售情景。

首版预测无需AI也能人工调整，所有调整有理由、负责人和有效期。概率只用于加权情景，不改变法定/合同债权或实际现金。

## 11. 审批、审计与月末

审批事件记录单据版本、节点、申请人与操作者、业务/财务/付款权限、结论、理由及时间。驳回有理由，超期通知不自动批准；邮件或消息提醒是辅助渠道，工作台待办为主。

月末顺序：收齐工时→批准费率和成本→确认验收/费用/管理收入→核销与流水对账→处理阻断异常→项目负责人确认ETC→财务复核→独立授权人锁账。锁账需要两人参与，业务负责人只能确认本项目数据。

锁账冻结已过账金额和期末快照，允许原始业务事实补录为“发生于历史期、记账于当前开放期”的调整。首版不提供解锁重写历史金额；需重述历史报表时走未来专项能力。已锁期间的附件补充保留追加记录及哈希，不改变原审批版本。

审计覆盖登录/授权变更、导出、敏感字段读取、财务新增/审批/过账/冲销、导入提交、AI建议采纳、归档、后台修复。普通用户和租户管理员都不能从产品界面删审计。可导出期间凭证、来源映射、期初/发生/期末平衡与附件清单，用于独立复核。

## 12. 证据、导入与异常队列

### 12.1 证据链

最小证据链：原始附件/表单/外部流水→结构化事实→业务确认→财务复核→核算事件→余额/报表。每一跳可双向打开，显示租户、来源ID、版本、文件哈希、发生时间、归属期、操作者及冲销关系。

发票号、银行流水号和合同编号用于查重，不作为孤立的全局唯一ID。相同附件哈希提示重复，但同一合同被多个合法单据引用不禁止。证据缺失须填写原因和预计补齐日；租户可配置某类费用无票审批，但不能把“有内部批准”显示成“税务可抵扣”。

### 12.2 导入

首版CSV覆盖客户/供应商、项目/合同期初、成员月历和费率、工时、费用、应收应付/预收预付期初、发票、收付款。提供系统内逐项表单作为同等能力入口。

流程：上传→字段映射/币种与单位确认→预校验→错误预览→形成不可变导入计划→提交草稿或提交已批准期初→业务/财务复核→过账。默认整批验证通过才提交；用户可显式剔除错误行，系统保存剔除清单和新批次，禁止悄悄跳行。

幂等键为租户+来源系统/导入类型+外部业务ID+版本；无外部ID时使用系统生成并要求复用的模板行ID。文件哈希仅识别完全重复上传，不能替代行级幂等。相同键相同内容重传返回已有记录；相同键不同金额/项目/币种进入冲突队列，不覆盖已存在记录。相同文件名或行号变化不改变业务身份。

期初按截止日录入历史累计经营收入/成本、未清应收应付/预收预付、银行项目资金累计或明确未知。累计历史成本不能再通过历史工时逐行过账；两种方式按项目/期间/成本类别选择互斥范围。缺失历史现金时显示“从启用日起现金净额”，不拼出虚假全生命周期现金。

### 12.3 异常队列

每项异常包含类型、严重度、租户/项目、来源、责任人、发现时间、期望处理日、阻断动作、修复入口和解决证据。状态为待处理→处理中→已解决/经授权接受；接受风险不能绕过强阻断。

强阻断：越租户、负费率/零有效分钟、金额单位不明、来源重复、缺汇率、核销超余额、税额分配超来源、锁期回写、审批自审、重复成本、贷借/分配不平。可带理由接受的预警：预计逾期、未到期质保金、低于预算毛利、工时日阈值异常。实际流水可先进待匹配区，不能因缺项目而丢失。

## 13. AI辅助和低成本模型稳定边界

首版AI任务仅包含：合同/票据字段提取草稿、工时说明转结构化建议、项目周报/风险摘要、异常解释、收付款匹配候选、自然语言查询转受限筛选。AI必须引用实际来源ID/字段；无证据显示未知，不补造验收、付款日期或税务资格。

可先只部署摘要与字段提取，但至少一个AI场景需完成“输入→结构化建议→校验→人工采纳→审计”的真实闭环，不能仅有聊天框。AI不可用、超时或额度关闭时，全部核心业务可通过表单完成。

稳定要求：

1. 一个调用只处理一个有界任务；按项目、期间和权限裁剪输入，敏感工资和银行账号默认不发模型。外部推理需租户显式启用并设置可发数据范围；不启用不影响产品。
2. 使用固定字段和枚举的结构化输出；校验租户、项目ID、日期、金额单位和证据引用，未知值为null。输出不通过最多一次定向纠错，仍失败回人工队列。
3. 金额、税、费率、余额、EAC、分摊及状态迁移由服务层确定性计算；AI不自行计算最终入账值。结构化建议也不能直接调用过账/付款/授权功能。
4. 合同附件、OCR文本和模型输出均为不可信数据，不执行其中要求的权限变更、网络调用或操作指令。
5. 记录模型标识、任务类型、输入引用与哈希、输出版本、使用量/耗时和采纳者；按租户设置预算上限、超时和禁用开关，缓存不跨租户。
6. 不宣称AI能判断全部合规、代替财务/客户验收或自动付款。诸如税率与抵扣资格缺少事实时必须要求输入，不输出“自动判合规”。

## 14. 对开发交付的业务约束

业务规则按“输入→校验→状态动作→核算事件→报表”实现。页面、CSV和后台任务共用服务层权限及计算，不允许表单写一套、导入另写一套。每项规则有稳定编号，并在测试中对应案例；开发者不需由模型阅读整份文档才理解一项任务。

首版使用Django内置能力完成认证、表单校验、ORM和迁移；生产数据更新不能靠在页面里直接改余额。跨单据动作必须事务化，同一应收被同时核销时只允许合法余额内的一次生效；SQLite不支持的锁行为需显式替代并测试，不能把本地通过当作生产并发正确。

数据迁移从空库和上一版本均可执行；迁移前后样例项目的分币金额、余额和来源关系一致。生产PostgreSQL需跑金额、核销并发、幂等、权限和锁账测试；SQLite跑同一确定性计算案例。财务金额禁止依赖SQLite的浮点聚合完成计算。

备份覆盖数据、附件和核算配置快照；交付时演示恢复后能打开原凭证并重建报表。日期、金额、中文搜索和表单错误在浏览器可用；不要求首版原生App。具体安全、部署和性能设计由架构文档承接。

## 16. 首版完成标准与主要反例

首版完成标准：三类项目可从机会走到归档；无ERP/OA也能录入所有核算信息；所有项目金额可追溯；双币金额、金额分单位、费率分配、部分核销和退款有测试；越租户访问、自审、重复入账、超余额和锁期改写被阻断；AI关闭仍可使用；本地及生产数据库验收通过。

以下做法直接判为未完成：只有看板和示例图表；工时保存但无审批与成本；工资付款再加一笔人工费用；采购下单、验收、发票和付款四次计成本；收款即收入；开票即应收且对原结算再建一份；把质保金视作坏账；缺费率显示零；全部月工资平均摊入项目掩盖闲置；导入错误行静默丢弃；AI直接批准财务动作；用解除核销假装现金退款；在SQLite用浮点算钱而只在界面保留两位小数。
