# 冻结基线到1.0的升级与切写契约（PH-132候选）

产品基线`119a04916e3e96a5e4d86516a5f13e841faf2f67`，标签`freeze/product-definition-2026-10-27`。治理主线可以继续前进，不能据其变化重写产品历史。本文是准备规格；尚未实现迁移、应用切换或生产升级。

## 逐来源映射

| 旧事实/入口 | 唯一承接 | 强制比对与拒绝路径 |
| --- | --- | --- |
| Organization、Membership、Employee、Project | 保留原PK；统一资料/身份服务与只读适配 | 不同名自动合并；账号/员工绑定保持，无账号员工仍可核算；不复制成供应商 |
| Project.contract_cents / budget_cents / etc_cents | 旧值只读历史；正式合同、预算、ETC分别由所属域唯一维护 | 新写入口切换前批准逐项映射；旧字段不能长期与新可编辑总额双写 |
| CostRate、Timesheet及历史task_id | 保留费率、日期、分钟、成本快照、原PK和可选任务；旧URL/CSV/PAT/MCP转同服务 | 旧行逐分、旧批准状态和原始来源必须不变；旧范围继续原逐行规则，不强补任务 |
| Document费用 | 映射费用来源/原证据、原成本账与冲销链 | 付款不再记成本；原费用不能以新入口复制后再过账 |
| Document收款/付款 | 映射现金来源/原计划核销及原现金账 | 不因归属/核销再生成银行事实；原收付保留实际日期 |
| Document预算/范围变化 | 保留旧批准记录，只映射到对应预算或已核实范围 | 不能直接将旧预算变化视作合同增价 |
| CashPlan与已核销金额 | 继续计划/历史关系；正式OpenItem须有逐来源业务批准 | 不批量把计划余额当应收应付；部分升级须保留余量和覆盖，不按同金额猜匹配 |
| LedgerEntry / AuditEvent / DomainEvent | 原主键、分币、原始payload、哈希及链顺序保留；新增只追加 | 不关闭触发器、不重算旧哈希链、不拷贝后丢原来源、不编辑余额 |
| 既有页面、导入、API、个人工具 | 兼容适配转发至唯一owner服务 | 权限/幂等/锁期/金额和dry_run等价；停用统一门控，不能只藏按钮 |

SourceRef的version用于读取当时事实，不是“换版本就可以重复记账”的钥匙。独立业务消费键为企业＋消费用途＋原始namespace/kind/id＋明细/期间/覆盖范围；不因UI/CSV/API渠道、请求key或可变版本改变而重复消费。新版本只允许已批准增量/冲销，不再全额过账。旧来源映射另有不可变legacy标记与原表/PK/账本行，不创造第二份有效事实。

## 新旧人工切换

新公司可在无旧成本来源的开账范围选择新月度方法。已有旧账的企业启用月必须晚于所有已过账旧人工的业务月份；若目标月已有旧人工，预检拒绝该月切换，先选择后续完整月份。旧未批工时按原业务日期所属方法和原快照继续办理；不得跨方法重复确认同一来源。

同一员工/月不混用旧逐行与新月度池。切换保存企业、启用月、方法/政策版本、批准人和输入覆盖清单。旧账冲销严格取原已存分币的相反数；锁定历史在开放入账期追加调整，并保留原业务日及其报表口径。不能用当前月度费率重算历史冲销。

## 演练与运行顺序

1. 从冻结Git版本在独立目录构造合成旧库；核对迁移叶、旧账本/审计完整性和逐来源业务快照。PH134构建器及PH135准备测试另留实际结果。
2. 在该副本应用新增迁移；保留旧表/列、PK、触发器。新增适配/来源映射先只读对照，识别重复覆盖、缺项目/对手/期间和不一致金额。任何差异阻止正式切写。
3. 期初按批次声明类别/期间/项目覆盖：明细重建与余额承接互斥；仅备查明细不再次过账。新未清、现金覆盖和历史计划分别批准。
4. 维护窗口停止受影响写入，排空/对账确认中的请求；备份数据库、非空附件与配置引用，记录代码/迁移版本、数量和内容哈希。不得把备份放源码包。
5. 切换唯一写路由，验证旧URL/API/CSV/MCP同服务及dry_run回滚；重跑权限、锁期、幂等、完整性与逐来源报表。验证通过后恢复业务写。
6. 前向修复优先；回退代码必须兼容新结构和已新增事实。无法确认兼容则只读保留现场；隔离恢复须数据库与附件联合演练，不能倒放账本或覆盖新事实。

旧新金额核对比较原财务列、来源与审计链，不以整个SQLite/PG文件二进制哈希不变为目标：迁移和新增行会改变文件。每个原始行和审计payload的既有内容必须不变；新字段/新行单独列出。原生产数据不进入外部代理，演练只用合成构建器。

## 完成门

冻结契约不等于升级已验证。正式升级任务必须有：冻结版本构建器、重复升级幂等、旧行逐分/原哈希链比较、重复来源/覆盖拒绝、旧入口与新入口等价、失败中断恢复、真实PG迁移/多连接、非空附件联合恢复、代码/数据兼容回退与客户维护窗口授权。缺一项保留未验证，当前PH132不代替运行验收。

物理账本兼容：core/models.py原Book枚举为cost/cash_in/cash_out，三者和原金额符号全部保留；“成本/现金两类”不是把存储book改成cash。旧LedgerEntry没有AccountingEvent外键，读取投影以origin=legacy标记、accounting_event_id=null及原document/timesheet引用返回，不伪造历史事件或修改旧行。新记录使用现有book值与明确scope；旧净现金公式和冲销符号逐来源比对。
