# 1.0 四职责业务原型

离线打开 [wireframe.html](wireframe.html)。所有企业、人员与金额均为合成示例。职责开关、表单校验和展开可操作；没有产品后端，不执行审批、记账、导入或锁期。源码中的合成数据并不保密，隐藏区块只展示产品权限设计，服务端权限须在正式开发中验证。

## 每种职责的首次任务

| 职责 | 进入后要做什么 | 只录一次的信息 | 不应出现的内容 |
| --- | --- | --- | --- |
| 老板/负责人 | 选择从零/存量开账，查看未匹配收款和待分配成本的责任人 | 开账范围引用项目、账户、期间，报告只读 | 用净现金流代替利润、覆盖不全仍展示公司完整成果 |
| 项目经理 | 打开授权项目，选收费模板、整理交付验收与客户确认投入 | 交付/工时来自原记录，结算和收入引用它们 | 公司资金、工资池、个人工资/费率、财务审批 |
| 员工 | 查看本人投入、费用和退回缺证据事项 | 分钟/日期/说明和费用证据一次登记 | 合同全量、公司收付、工资池和他人个人信息 |
| 财务/核对人 | 查看来源→结算→收付引用，核对待分配和未匹配事项 | 结算、资金分别唯一维护，核销只建关系 | 把核销再记一次现金，付款再记一次成本 |

四职责代表工作入口，不等同于可自行授予的后台角色。正式权限仍由服务层按公司、项目、本人范围、能力与期间检查。老板也不能自审本人业务。原型中老板与财务显示项目汇总，不展示个人工资；敏感人工明细仍须独立权限。

## 三种收费模板的完整路径

| 模板 | 一份合同/项目的业务输入 | 收入依据 | 结算和现金如何承接 |
| --- | --- | --- | --- |
| 固定总价/里程碑 | 批准明细与价格、节点、验收证据及累计覆盖区间 | 符合条件的已验收履约；金额由确定规则计算 | 结算引用合格来源，保留质保等分区；收款引用账户事实，核销消耗未清项 |
| 客户确认工时 | 原始投入、客户确认的计费分钟与合同单价 | 客户确认的可计费投入 | 同一确认来源形成结算；不能重新手输一份客户工时；实际到账独立记录 |
| 固定服务期 | 起止日期、合同计价、客户确认服务区间与证据 | 已确认期间且满足配置条件的服务 | 结算使用同一期间来源，拒绝重复/重叠；收付款与收入事件互不替代 |

价格、比例、税资格、客户确认条件属于开账配置。缺配置可草稿/模拟，不可正式确认金额。页面模板切换只显示上述差异，固定金额不是实时核算。正式字段、命令、状态和锁约束以PH132 [契约](../contracts/README.md)为唯一标准；本目录不得另建一套业务对象或金额口径。

## 交互及检查

起账日为空时保留输入、聚焦错误字段；有日期时仅显示合成核对预览。项目详情展示概览/关键任务/财务三个涉及本次路径的页签，方向键/Home/End操作；其余正式六页签不在低保真覆盖范围。财务页在PM职责显示拒绝态，工资池、公司收付及开账整个区块隐藏；员工只显示本人投入/费用。职责切换同时移除对应导航。手机导航采用原生模态框，Escape关闭，焦点回到菜单。

状态样张覆盖默认、空、筛选空、错误、加载、无权。样张按钮禁用并标为占位；不是伪造可用业务操作。页面末的模块所有权收进设计附录，客户主路径使用中文业务名称。

实际浏览器脚本 [check-browser.cjs](check-browser.cjs) 使用现有bundled Node/Playwright，无新依赖；输出 [browser-evidence.json](browser-evidence.json) 及1440/390合成截图。技术检查与人工视觉结果见 [review.md](review.md)。这些只证明原型，不证明客户可独立使用、产品权限或生产环境。
