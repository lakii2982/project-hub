# 页面、字段和唯一来源契约

本表是PH132 canonical schema/DTO的页面投影索引，不重新定义schema。输入身份中的公司/actor永远取会话；客户端不能提交审批人、任意状态、已确认收入金额或已记账余额。正式开发按对应字段schema与命令反例验证。

| 页面/记录 | 用户录入或确认 | 只读/继承 | 唯一维护模块与下游关系 | 范围 |
| --- | --- | --- | --- | --- |
| 开账核对 | 起账日、新/旧承接路径、覆盖声明、合成试算确认 | 原快照、期初批次、核对报告 | onboarding编排；masterdata/identity/cash/costing/settlement各维护自己的原对象；不导出第二套余额 | 授权负责人/财务，不开放员工 |
| 项目基础事实 | 名称、编号 | 原项目ID、公司及identity提供的成员/范围引用 | 既有Project/masterdata；所有业务以同一project_id连接 | 授权项目 |
| 成员与授权 | 邀请/账号绑定、权限与项目范围 | 项目/员工主档引用 | identity唯一维护Membership/MembershipScope，项目主档不得另存一套授权 | 授权企业管理者；服务层禁止越权和自授敏感能力 |
| 合同明细/版本 | 客户、含/不含税价、方法、价格比例、节点/服务/工时条件 | project_id、已批准版本、派生金额 | contracts唯一维护，delivery/time/revenue/settlement引用正式版本 | 负责人/项目授权业务；员工隐藏 |
| 验收/确认 | 明细引用、节点覆盖区间/计费分钟/服务期间、外部证据 | 金额来自合同与确定规则、原投入引用 | delivery/time唯一维护事实；不得在收入或结算再填一份事实 | 获授权PM/客户确认流程，制单不得自审 |
| 本人投入/费用 | 日期、分钟、说明；费用凭据、业务范围、分类 | 员工由本人绑定；原金额、状态只读 | time/costing；费用确认成本，后续AP/cash引用来源 | 员工仅本人、PM仅项目投入，财务成本敏感字段独立权限 |
| 工资核对 | 月度池、已发生覆盖、产能、去向与差异说明 | 已批准投入、旧快照及同源暂估 | costing；按正式政策同源调差，来源不能重建；未分配保留去向 | 有敏感权限的财务；PM/员工不可见 |
| 结算/未清 | 合格来源选择、付款条件与证据 | 对象/方向/范围/未清额由来源继承 | settlement；OpenItem创建继承已批准结算，不准手输方向/余额 | 授权财务；PM只准备授权项目事实 |
| 现金记录/核销 | 账户、真实日期、金额和银行证据；选择核销目标 | 已记现金及已消耗金额、账本只读 | cash维护真实现金；settlement维护核销；同公司锁内可用额证明不持久化为新余额 | 授权财务，不自动成为收入/成本 |
| 月末/经营工作台 | 过滤范围、期间；补证据或跳到源记录 | 成本、管理收入、净现金流各只读投影，范围/暂估/遗漏标记 | 统一查询，追溯来源事件与账本；不允许直接编辑汇总 | 老板汇总/财务核对；其他按授权裁剪 |

金额以分持久化、展示人民币元；分钟以整数持久化。先批准事实再记账，反例须覆盖自审、跨公司/跨项目、锁期、未来实际日期、重复来源、超额及冲销。设计支持的字段不代表产品已实现；schema验证也不代表这些服务端规则已执行。

## 与现行界面规范的关系

原型内联一份当前ui-tokens.css快照以便离线打开，只消费已有语义令牌，不修改唯一产品样式源。沿用侧栏/页头/页签/表格手机行卡/表单/状态/原生dialog与焦点模式。三页签是此次路径的裁剪示意，产品实现仍须遵守六页签规范。未来合同/结算/企业初始化导航和状态说明超出现行基础资料三列表，正式实现前应由PH110/PH137映射范围更新共享样张；PH133不直接修改现行规范，不视为批准新产品UI模式。截图不是视觉规范替代品。
