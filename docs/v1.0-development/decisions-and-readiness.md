日期：2026-10-27。本表是设计时的条件清单，未执行的检查保持未执行。不会改写现有任务/发布状态。

### D. 技术取舍：主控负责并记录

SDK schema版本与命名、同公司锁下资源排序、App边界、命令/查询适配、稳定来源键、读模型范围、固定夹具日期、迁移叶节点与兼容窗口按架构契约冻结。无新增客户价值，不增加微服务、前端构建链、消息中间件、常驻调度器或新计费渠道。新依赖如确有必要按原规则单独评估，不让执行者自行安装。

## 3. 开工检查点

### G0 本轮设计交付

目录材料完整；137需求唯一主包、18UAT可追踪；依赖DAG无环；有唯一数据owner、变更与重验路径；原规范/用户改动保留；独立审阅及结构检查完成。G0只证明设计交付。

### G1 第一批产品实现可启动

同时满足：用户明确恢复开发及范围；首批对应准备包完成；冻结版本资料已通过规划合入可信BASE；PH任务ready且依赖done；C01/02/03/11及所涉领域字段级契约冻结；执行隔离/取消能力当轮实测；相关验证环境可用；可执行反例/固定命令成立；独立复核安排与文件范围互斥。旧next中的ready不得因为排在前面就自动启动。

### G2 财务跨域实现可启动

G1加：C04～10所涉契约、公司优先锁序和部分覆盖规则冻结；PG多连接构建器可用；旧新映射/切换及来源唯一有可执行反例；产品政策已定、客户政策可配置拒绝行为已定；同一跨域命令的唯一编排/事务入口已确定。

### G3 候选收口与正式交付

按验收设计分别达到研发候选、目标环境、客户接受及发行门。目标环境、TLS、PG恢复、真实客户或发布授权缺失时仍是未验证/待外部条件，不把研发完成写成1.0正式交付。
