# Agent开发工作单模板

状态：模板，不是实际ready任务。一个实际PH填写一份，冻结到可信BASE；工作包ID仅作产品关联。执行者拿到最小上下文，不能自行扩权。

## 1. 标识与授权

- PH任务ID、工作包ID、需求ID、UAT、风险S/A/B。
- 目标一句话；交付薄片；本次不涉及的领域及理由。
- 可信BASE SHA、spec路径/摘要、批准schema/政策版本。
- 直接依赖PH与实际交付提交/接口；当前状态和开工授权范围。

## 2. 输入和字段级契约

- 必读章节/相邻源文件/固定夹具版本，避免整仓和全聊天。
- 对象owner、App、稳定ID；字段名/类型/单位/可空/默认/边界/唯一约束。
- 状态枚举及合法迁移，提交人/业务本人/复核人及字段权限矩阵。
- 命令/查询/事件schema及名称/版本、返回结果、错误码、分页/日期边界。
- SourceRef和来源唯一键、幂等键及同key改内容、乐观版本、快照/算法版本。
- 公司优先锁序、跨域事务编排owner、失败原子回滚、提交未知查询对账。
- 核算事件/反向关系、金额分配/取整/税额、实际/暂估/预计及部分覆盖。
- 全部新字段必须有业务意义；无关项明确写“不涉及”及原因。

## 3. 文件与集成边界

- executor_allowed_paths：具体文件/受控模式，禁止广泛授权整个仓库。
- integrator_only_paths：共享路由/settings/导航/既有core接线/完整性/迁移/汇总证据。
- forbidden_paths：其他域、已应用迁移、用户配置、凭据/runtime、真实客户文件。
- 数据迁移与旧URL/CSV/API/MCP适配、切换窗口/只读比对、不可逆点和恢复。
- 语义互斥资源：同一schema/方法/来源键/迁移链/指标定义的owner。

## 4. 测试与验收

- 具体失败例：输入、错误/未发生事实、账本/审计/Outbox期望，不写“测权限”等空话。
- 正常路径、边界、重复、越权/跨项目、锁期、反向/部分更正、迁移兼容、PG竞争（适用）。
- 共享golden fixture的阶段输入和逐分预期；新方法改变旧预期须有批准依据。
- 命令采用可信BASE支持的固定argv；环境和夹具版本、预期产物/退出码。
- UI按规范1440/390、键盘/焦点/状态/溢出；代码验证不能代替真实浏览器。
- 明确SQLite、PG回归、PG多连接、目标环境、客户验收各自需要谁、什么证据。

## 5. 完成、交接和失败

- 产出模型/服务/入口/测试/文档、实际命令及结果、差异清单、偏差与未验证项。
- 沿已有project/reports/PH.json和handoffs/PH.md格式；不临时换格式绕过校验。
- 独立复核绑定最终候选；报告/交接/共享接线变更后按现有gate重验重审。
- 同执行者连续两次不合格后主控接管；失败记录保留，禁止弱化断言。
- 不创建/合并PR、发布/部署或联系他人，除非该执行者已获相应明确职责和授权；默认由主控处理交付动作。

## 6. 两个容易漏的具体契约示例

### 核销薄片应写到的程度

例：同企业/合法对手/项目的资金剩余10000分，未清6000分；尝试核销7000拒绝，6000成功且现金事件数不增加，重复同key返回原结果；两PG连接各申请4000，最多允许合计6000并保持来源/核销/审计一致。撤核恢复双方可用而不造退款；跨租户、锁期、旧版本、来源不可用的行为分别明确。settlement拥有关系，cash拥有资金事实，固定cash应用编排同事务调用两者。

此例不替代实际schema/政策/字段名。只有精确scope、实际固定验收及其PH合入后才能派遣。

### 新月度人工成本薄片应写到的程度

例：固定员工/月/方法版本与成本池2400000分、有效分钟9600、批准项目分钟及非项目去向；明确组取整、余数稳定排序、差额池与更正。旧逐行规则的历史结果保持，启用日和method_id有明确映射。工资支付仅记现金，不能再生成成本；未知分母/费率不能假零；锁期补报建立新调整来源。

客户实际薪酬、分母政策和方法切换须有相应确认，合成例子不是替客户批准政策。
