# 1.0 验收、集成夹具与发布收口设计

目标：把“代码存在、单元通过、集成通过、现场可用、客户接受”分开验证并绑定同一候选。来源见[交付方案](../v1.0-delivery-plan.md)和[既有发布规范](../engineering/releases.md)。本文定义要收集什么证据，不生成已通过结论。

## 1. 统一合成企业夹具

由PRE-FIXTURES准备包冻结一份版本化数据说明及可执行构建器/预期结果，正式路径及验收命令在规划PR中确定。不得先让每个域自己编一组互不相关的金额，再在收口时手工拼接。

同一夹具至少包含：两家合成企业；owner/finance/分配与未分配PM/member/auditor；无账号员工与停用身份；固定价、确认工时、固定服务期三项目；一个存量项目；合同明细/变化/质保；工时/费率/工资池/非项目；费用/承诺/暂估/预付服务；结算、预收抵扣/退款、银行退回、共享费用、内部互转、发票/收入配对；开放/锁定期间；非空附件及哈希；CSV原外部ID及重排/内容冲突变体。

夹具清单字段：fixture_id/version、固定业务日期/时区、schema/policy/algorithm版本、原来源ID和覆盖范围、输入事实、允许命令序列、各阶段预期状态/账本分币/未清/资金/预测、预期拒绝路径、附件哈希。采用人民币，不为范围外多币种扩功能。

18UAT各拆为命令级正常/失败断言；每需求也有独立验收要点，UAT映射不能当作该条自动通过。未被现有18场景直接覆盖的需求保留自身专项（激活、借支、权限撤回、导入错误等），禁止为“全覆盖”随意贴UAT编号。

固定日期、固定随机种子与稳定排序；禁止依赖今天日期或执行顺序。并发用屏障/明确提交顺序，两个独立PG连接；不能sleep猜发生竞争。升级验证使用冻结基线构建的同一合成旧库，前后逐来源对账，不导入真实客户备份到外部代理上下文。

## 2. 验证层次与责任

| 层 | 验证对象 | 执行责任 | 证据与不能替代的事项 |
| --- | --- | --- | --- |
| V0 静态契约/文档 | 137需求映射、唯一主包、DAG、schema/版本/owner、链接 | 主控＋独立审阅 | 只证明设计结构，不证明代码/自动门禁 |
| V1 单命令反例 | 权限、来源唯一、计算、版本、状态、幂等 | 实现者，隔离验收重跑 | 涉及逻辑错误必须能红转绿；不写镜像实现的空测试 |
| V2 跨域黄金链 | 合同→履约→成本/收入/结算→现金/票据→预计/月结 | 主控/集成验收 | 固定夹具阶段逐分比对，证明接口联通 |
| V3 回归/兼容 | SQLite/PG域回归、旧URL/导入/API/MCP、append-only | 现有隔离verify＋CI | 同最终候选；跳过/未运行单列 |
| V4 PG多连接 | 双审批、并发核销/退款/分配、期初、锁期 | 专项验收者 | 真实PG、多连接及顺序/结果证据，单连接不算 |
| V5 浏览器 | 三收费模板、四职责、手机/键盘/状态、无溢出 | 前端独立检查/主控 | 真实页面，不是模板渲染/样张截图 |
| V6 目标环境 | Linux安装、TLS、升级、数据库＋非空附件恢复、负载 | 受权集成/运维 | 环境版本、候选SHA、命令/截图、金额/附件核对、实测时间 |
| V7 客户业务接受 | 连续维护、月结、经营决策及签收 | 客户业务负责人＋产品负责人 | 真实操作者、范围、周期和限制，代理不可代签 |
| V8 发行 | 同提交CI、版本/变更、源码/镜像/摘要、发布回执 | 主控在授权范围执行 | 公开发行/部署是独立动作，合入不能替代 |

产品改动执行现有四条Django验收，加projectctl；涉及MCP另加独立测试及stdio。保持固定依赖与check强度，不能以为了缩短长程任务为由减少required checks。全量测试的粒度依可信BASE契约；不要自行改成“相关测试绿即合入”。

## 3. 现有工具与新环境的分工

现有delivery verify接受固定argv形状并实行无凭据禁网隔离。Docker、TLS公网、客户环境或新增自定义验证脚本不能自动获得在该通道执行的权限。正式准备时核对当前解析器/隔离能力：

- 现有支持的Django/unittest/projectctl命令走既有verify。
- 新检查能纳入现有固定命令的，用正规任务补反例/测试；如确需新增命令先独立治理任务冻结允许的argv与隔离/日志边界。
- 目标环境验证走明确授权的独立环境执行路径，与源码验收回执并列记录，不把现场命令拼进任意shell白名单。
- doctor仅证明版本/探测；原有macOS前台四CLI试用不证明本轮可长期无人值守、目标主机可部署或客户Agent可用。

## 4. 证据记录设计

证据字段分公共摘要与私有原始日志；下列为目标格式，落入现有report/回执前须符合其schema，新增工具字段另经规划。

```json
{
  "evidence_id": "stable-id",
  "task_id": "PH-to-be-allocated",
  "requirement_ids": ["V1-SET-05"],
  "uat_ids": ["UAT-14"],
  "level": "V4",
  "candidate": {
    "base_sha": "fixed-trusted-base",
    "contract_digest": "sha256",
    "diff_digest": "sha256",
    "head_sha": "verified-candidate-commit"
  },
  "environment": {"database": "PostgreSQL", "fixture_version": "golden-v1"},
  "executor": "independent-run-or-human",
  "checks": [{"name": "concurrent-clearance", "result": "not_run"}],
  "result": "not_run",
  "limitations": [],
  "supersedes": null
}
```

结果使用pass/fail/not_run/blocked等明确值，pending不是pass，缺结果不是默认成功。证据必须有实际输出或受控摘要/附件；“reviewer说通过”不替代测试。环境与fixture字段应完整到可复跑，不记录秘密和实际工资。客户签收另加操作者/业务负责人、日期、覆盖需求/周期、限制与接受结论，不把代理角色填为客户。

证据更新保留旧失败及supersedes关联。final head、BASE、契约、算法、关键夹具变化时按影响重验；现有gate要求整候选重验的照现有规则执行。客户记录可引用此前实际使用版本；候选变化后做变更影响与差异验收，不能把旧签收改写成新版本使用。

## 5. 18UAT与需求追踪的使用

`requirement-trace.json`仅登记需求原文、主工作包和适用UAT，不保留可手改测试通过状态。正式PH映射/证据从tasks/reports/PR及回执引用，汇总自动派生或人工核对生成只读快照。一个需求必须同时满足其专项、关联跨域UAT和相关权限/金额/迁移验证，不能以主包合入自动判其客户验收完成。

集成失败归属依据来源/接口owner，不让两个代理分别“修”同一接口。每次新域接入运行该域与关键既有路径；每阶段使用完整黄金企业数据重跑累计链。新功能导致旧golden结果变化必须关联已批准政策/迁移，不能直接更新expected数值让测试绿。

## 6. 正式发布门与旧路线对齐

当前 `project/release-readiness.json` 有lifecycle、financial_rules、production_deployment、postgres_concurrency、backup_restore、agent_client、ai_evaluation、business_acceptance、licenses，均为pending。旧PH-020还包含AI/资源/客户端依赖。新产品方案建议这些方向后置，**目前不能删除旧门或将其填写通过**。

PRE-GOVERNANCE必须提出明确规划变更：保留哪些门、哪些需求改为后续扩展、旧PH如何承接/替代、源码检查器/文档/CI如需同步修改的精确范围及反例；独立S级复核和当前CI通过后才生效。未完成前仍按旧规则判断1.0就绪。不能只在新README写“已不需要”绕过机器门。

研发候选完成：137Must有代码和所需V1～V6证据，18UAT、回归、完整性和实际目标环境检查成立，阻断缺陷清零。此时仍可缺V7，状态应为“等待客户验收的候选版”。

客户正式交付：三类客户/收费模板与月度核对有业务证据、产品接受、运维服务和数据退出明确；按已批准发布门执行V8，同提交版本与资产摘要核对。已知缺陷不能突破Must或金额/权限/恢复底线；不以“长程任务已花很多时间”降低终点。

## 7. 缺陷和例外

记录缺陷ID、影响需求/来源/版本、复现、严重度、owner、修复PH、旧失败与新证据。金额/越权/历史损坏/无法恢复阻断发布；影响关键独立使用路径也必须修复。纯非Must外观缺陷可在产品接受后列遗留，但不得掩盖键盘或手机不可用。

测试环境限制、客户缺席、网络故障和证书未配置都记为未验证/阻断，不计通过。外部条件未满足时，先完成无依赖研发部分并交付候选与明确剩余清单，不虚构客户、真实TLS或签收。
