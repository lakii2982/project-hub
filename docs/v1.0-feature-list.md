## 模块之间怎样打通

- 项目、员工、往来方各有唯一档案，所有模块通过同一ID引用；基础资料是统一入口，不是额外一套数据。
- 合同/变更确定收费范围；验收和客户确认工时为结算、管理收入提供同一履约来源。
- 工时、费用和外包确认成本；付款只记现金，不再次计成本；工资和共享费用只能分配一次。
- 结算建立应收应付；现金核销只改变关联与未清额，不再生成银行流水、成本或收入。
- 发票关联原业务，开票和到账不替代履约确认，也不重复新增应收应付。
- 实际、未清与计划按来源升级互相替代，13周预测不重复累计；经营看板和导出只读统一数据。
- 一笔业务可以从多个页面发起或查询，但所有写入都调用拥有该事实的同一业务服务；历史快照不可单独编辑。

## 正式交付的底线

所有模块必需能力和端到端场景通过；客户能在浏览器独立完成日常办理与月度核对；金额逐分可核对，来源能追溯，敏感数据不泄露；目标部署环境的TLS、PG多连接和数据库加非空附件恢复有实证。

预算余额、实际管理毛利、预计完工结余、净现金流和银行余额分别显示。缺成本或收入依据时明确提示，不能填假零或称作完整利润。

多法人/多币种、法定总账和报税、银行自动支付、复杂库存、完整CRM/OA、人事薪税、复杂资源优化和插件市场不在1.0内。AI和个人Agent保留扩展能力，首版业务不依赖它们才能完成。
